Works on Windows 11 and Windows Server 2025, 64-bit. Installing is one command —
or a [setup program you double-click](#install-with-the-setup-program).

## Install

<Steps>

1. Open **PowerShell as Administrator**: right-click the Start button and choose
	**Terminal (Administrator)**. Answer **Yes** to the permission prompt.

	<Aside type="note" title="Why administrator?">
		Waired registers a background service that starts with the computer,
		before anyone logs in. That is a machine-wide change, so Windows asks
		first.
	</Aside>

2. Paste this line and press Enter:

	```powershell
	iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
	```

	<Aside type="tip" title="What that line does">
		`iwr` downloads Waired's install script and `iex` runs it. If you would
		rather read it first, see [below](#read-the-script-before-running-it).
	</Aside>

3. It prints a summary of what it is about to do and asks `Proceed? [Y/n]`.
	Press Enter.

	A fresh interactive install also offers to change where Waired goes — press
	Enter to accept `C:\Program Files\Waired`.

</Steps>

Now [sign in and set up](/getting-started/first-run/).

## Read the script before running it

Reasonable. Download it, read it, then run it:

```powershell
iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 -OutFile $env:TEMP\install.ps1
notepad $env:TEMP\install.ps1
& $env:TEMP\install.ps1
```

This is also how you pass options — the piped one-liner cannot take them.

<Aside type="note" title="Unattended installs">
	`-Yes` skips the confirmation and `-InstallDir <path>` (or the
	`WAIRED_INSTALL_DIR` environment variable) pins the location. The full list
	is in [Advanced install options](/reference/install-options/).
</Aside>

## Install with the setup program

If you would rather click than paste, the
[releases page](https://github.com/waired-ai/waired-agent/releases/latest)
also carries a setup program, `WairedSetup-<version>-x64.exe`. The filename
includes the version, so there is no `latest/download/…` shortcut for it —
download it from the page.

On first run Windows shows **Windows protected your PC**: the setup program
is not signed with a certificate Windows recognises. Choose **More info →
Run anyway**. The PowerShell line above does not raise this prompt, which is
why this page leads with it. Next comes the permission prompt, for the same
reason as above — the background service is a machine-wide change.

The wizard is short. It does not ask where to install — it always uses
`C:\Program Files\Waired` (use the PowerShell installer's `-InstallDir` for
anywhere else). Its one choice is a checkbox under **Claude Code
integration:**, ticked by default: it points Claude Code at Waired by writing
Claude Code's machine-wide managed settings. Untick it and Claude Code keeps
talking to api.anthropic.com; you can turn it on later from an Administrator
terminal with `waired claude enable`.

When it finishes, Waired is installed and its service is running, but you are
not signed in yet — the setup program does not run `waired init`. Leave
**Launch Waired now (recommended -- registers per-user autostart)** ticked on
the last page to start the Waired app and have it start with your session,
then continue with [Sign in and set up](/getting-started/first-run/). The
Start Menu gains two entries: **Waired** (the app) and **Waired (CLI)**.

Setup always writes a log — `%TEMP%\Setup Log*.txt`, or the file named by
`/LOG=<file>` — which is what to attach to a bug report.

Running a newer setup program over an existing install upgrades it in place;
you do not uninstall first. To uninstall, use **Settings → Apps → Installed
apps → Waired → Uninstall**. An interactive uninstall asks whether to remove
`%ProgramData%\waired` — device identity, secrets, cached state — and the
default answer is No, so a reinstall re-uses the same device key. A silent
uninstall always keeps it.

To deploy it unattended:

```powershell
.\WairedSetup-<version>-x64.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG=$env:TEMP\waired-setup.log
```

Add `/MERGETASKS=!claudeproxy` to leave Claude Code alone. Exit code 0 means
installed. Exit code 7 means the setup program declined and installed
nothing — the case described under
[If Windows refuses to run a program](#if-windows-refuses-to-run-a-program).

## Skip the inference engine

Waired installs [Ollama](https://ollama.com) — the program that runs models —
during setup, and only on computers that will run models. To make sure it is
never installed (a headless or low-disk host):

```powershell
$env:WAIRED_NO_OLLAMA = '1'
iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
```

You can add it later from an administrator prompt with
`waired runtimes install ollama`.

## If Windows refuses to run a program

Waired's programs are not yet signed with a certificate Windows recognises, so
Smart App Control — or another application-control policy — can refuse to run
them. Both installers — the PowerShell line above and the downloadable setup
program (`WairedSetup-<version>-x64.exe` on the
[releases page](https://github.com/waired-ai/waired-agent/releases/latest)) —
therefore run the programs first, from a temporary folder, and stop if Windows
refuses one. That happens before anything is installed, stopped or replaced:

```
[waired] Checking the new programs run on this computer before replacing anything
[waired] Windows will not run the new waired-agent.exe on this computer:
[waired]   An Application Control policy has blocked this file
```

The setup program says the same on its **Preparing to Install** page and in its
log, ending with `Nothing has been installed, removed or replaced.` That is the
whole outcome: nothing is half-installed, and Claude Code has not been pointed
at Waired — an install that stops here leaves the computer as it was.

The refusal is per file and changes on its own — a file this computer refused
in the morning can run in the afternoon with nothing changed on the machine —
so trying again later is a real option. Only two programs stop the install:
`waired.exe` (the `waired` command) and `waired-agent.exe` (the background
service). If only the Waired app (`waired-tray.exe`) is refused, setup
continues with a warning; the service and the `waired` command are unaffected.

[Updating](/getting-started/update/#if-an-update-does-not-finish) runs the
same check before it replaces the version you have.

### If it happens after Waired is installed

The same verdict can turn against a file that has been working. When the file
is `waired.exe`, the `waired` command stops starting — and so does everything
that runs it for you, which is why Claude Code's Waired segment in the status
line goes blank and its Waired hooks do nothing. Windows may also show its own
notifications each time.

The Waired app notices and says so, because it is a different file with its own
verdict and keeps running:

> Windows is refusing to run waired.exe on this computer. That is why the
> waired command and Claude Code's Waired status line do nothing. Nothing here
> is broken and there is nothing to repair — Windows does not trust the file
> today, and often does tomorrow. Run `waired doctor` for the details.

There is no setting to change. Once Windows accepts the file again, everything
resumes on its own; nothing needs reinstalling. `waired doctor` reports it
under **Windows Application Control** whenever it can run — which, when
`waired.exe` is the refused file, is after the refusal has lifted.

## What gets installed

| | |
|---|---|
| Program files | `C:\Program Files\Waired` (changeable) |
| Background service | `waired-agent`, starts at boot |
| Settings and state | `%ProgramData%\waired` (secrets are locked down to administrators) |
| inference engine and models | Inside `%ProgramData%\waired`, only on a computer that runs models |
| Start Menu | **Waired** (the icon you use day to day) and **Waired (CLI)** |

Waired keeps its own copy of the inference engine, alongside its settings. It does
not add anything to your system `Path` and does not change any system-wide
settings for it. If you already have Ollama on this PC, Waired leaves it
exactly as it is and does not use it.
