If something is wrong, run [`waired doctor`](/getting-started/doctor/) first.
It fixes most problems. This page is for what comes after: collecting the
evidence that lets somebody else work out what happened.

<Aside type="caution" title="Turn on detailed logs before you reproduce it">
	Waired normally logs the important events only. The detail that explains a
	bug is not written down unless you ask for it first. Turning it on after
	the problem happened gives you a log of everything except the part you
	need.
</Aside>

## Collect the diagnostics

<Steps>

1. **Turn on detailed logs.** This takes effect immediately, on both the
   background service and the Waired app, without a restart.

   ```sh
   waired config log-level debug
   ```

2. **Reproduce the problem.** Do the thing that went wrong, the same way.

3. **Collect the logs into one file.**

   ```sh
   waired logs --mask-pii --since 30m -o report.txt
   ```

   `--since` is how far back to look. Widen it if the problem happened a
   while ago. The default is one hour.

   On Windows, run this from an administrator PowerShell. The service's own
   log and the inference engine's log sit under `C:\ProgramData\waired`,
   which is locked down. Without elevation they are left out of the file.

4. **Turn the detail back off**, so your logs stay small.

   ```sh
   waired config log-level info
   ```

   While the detail is on, Waired keeps more of it: 128 MB per log file
   instead of 32 MB, so a problem you notice days later is still in the
   file.

</Steps>

`report.txt` holds the background service's log and the inference engine's
log together. That one file is what to attach.

## What --mask-pii does

It replaces four things with placeholders: your home folder, your username,
your computer's name, and the email address you signed in with.

It is best-effort, not a guarantee. It does not know about every path or
name that could be personal to you, such as a project folder elsewhere on
disk, a hostname you configured yourself, or a URL you typed. Read the file
before you attach it, whether or not you used the option.

<Aside type="note" title="It works on any command">
	`waired logs --mask-pii` masks that one command. To mask everything,
	including the installer and sign-in, set `WAIRED_PII_MASK=1` in your
	environment instead. See [Advanced install options](/reference/install-options/).
</Aside>

## When the problem happens during install

The steps above need Waired already installed. If it fails while installing,
ask the installer for detailed logs from the start.

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_LOG_LEVEL = 'debug'
		$env:WAIRED_PII_MASK = '1'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```

		The one-line form cannot take options, so set them as environment
		variables. They reach the installer and everything it runs, including
		the administrator step.
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --log-level debug --mask-pii
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --log-level debug --mask-pii
		```
	</TabItem>
</Tabs>

On Windows the installer also writes its own transcript, one file per run, to
`%TEMP%\waired-install-<date>-<time>-<id>.log`. The administrator window
closes when it finishes, so that file is often the only place the failure
survives. Attach it too. The installer prints the exact path before it
starts, and again if anything goes wrong. To find the newest one:

```powershell
Get-ChildItem $env:TEMP\waired-install-*.log | Sort-Object LastWriteTime | Select-Object -Last 1
```

The five most recent are kept, so a second attempt does not overwrite the
log of the attempt that failed.

## Start over from a clean slate

If the setup looks confused rather than broken in one specific way, wiping
and reinstalling in one step is often faster than diagnosing it.

<Aside type="danger" title="This deletes things">
	A clean install permanently removes your settings, keys, local state, and
	the models you downloaded. You sign in again afterwards, and the models
	download again. It asks you to confirm first.
</Aside>

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_CLEAN = '1'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --clean
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --clean
		```
	</TabItem>
</Tabs>

For details, including how to wipe without reinstalling, see
[Uninstall Waired](/getting-started/uninstall/#start-over-on-the-same-computer).

## If you were asked to try a test build

Two options exist for this, and they combine.

- `--edge` or `WAIRED_VERSION=edge`: the latest build of the main branch,
  rebuilt on every change. Not a release. See
  [Release channels](/getting-started/update/#release-channels).
- `--dev` or `-Dev`: connects to Waired's own development service instead of
  the normal one. This is for people working on Waired itself. A device
  registered this way does not appear in your normal account.

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		# Save the script first: the one-line form cannot pass -Dev.
		$env:WAIRED_VERSION = 'edge'
		$env:WAIRED_LOG_LEVEL = 'debug'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 -OutFile $env:TEMP\install.ps1
		& $env:TEMP\install.ps1 -Dev
		```
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --edge --dev --log-level debug
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --edge --dev --log-level debug
		```
	</TabItem>
</Tabs>

The installer remembers which service you chose, so running `waired init`
again later signs you back in to the same one. To get back to a normal
install afterwards, do a clean install as above. The `--stable` option alone
changes the build, not which service you are registered with.

## What to attach

| | |
|---|---|
| `report.txt` | From the four steps at the top |
| `waired version --json` | The exact build |
| `waired doctor` output | What it found, even if it fixed it |
| Windows install failures | The newest `%TEMP%\waired-install-*.log` |
| What you expected | And what happened instead |

On Windows, if the command does not start at all, the same build number is on
the file. Right-click `C:\Program Files\Waired\waired.exe`, select
**Properties**, and read **File version** on the **Details** tab.

File the report at
[github.com/waired-ai/waired-agent/issues](https://github.com/waired-ai/waired-agent/issues).
