Waired tells you when an update is available. Applying it is always something
you start. Nothing updates itself in the background.

## Update now

Select the **Waired icon** and choose the **Update available — install …**
entry when it appears. The app closes, updates, and reopens.

Or, in a terminal:

```sh
waired update
```

The command checks, shows what it found, and asks before applying.

| Command | What it does |
|---|---|
| `waired update` | Check, then apply if a newer version exists |
| `waired update --check` | Report only. Changes nothing |
| `waired update --yes` | Apply without asking, for scripts and servers |
| `waired update --force` | Ask the release source again instead of reusing a cached answer |

## How current the check is on Linux

On Linux the check reads the package index this computer downloaded earlier,
so `waired update --check` prints when that was:

```
Package index:   refreshed 3 hours ago
```

Once the index is more than a day old the line says so, because a newer build
may already be published that this computer has not heard about. Adding
`--force` refreshes the index first. That needs root, so it asks for sudo:

```sh
waired update --check --force
```

macOS and Windows ask the release feed directly, so their answer is already
current. There, `--force` only skips the cached one.

## What an update keeps

You stay signed in, this computer keeps its identity and its place in your
network, and your settings are preserved. You do not have to set up again.

Your downloaded models are not touched. The inference engine is: if this
computer already has one, the update brings it to the version this build of
Waired runs, because that is the only version Waired uses. A computer with no
engine does not get one from an update. Turning local inference on is what
installs it.

Whether the Waired app starts when you log in is not changed. If an update
finds that the app is not set to start for the person logged in, it says so
and leaves it at that. Open Waired once and enable **Start Waired on login**
if you want it back.

If the Waired app was open, it is closed and reopened as part of the update,
so what you see afterwards is the new version. If it was not open, it stays
closed.

## If an update does not finish

An update that fails leaves the version you already had, running. Waired puts
the new files in place only after all of them have been downloaded and
checked, so a failure part-way is an update that did not happen, not a
half-installed one. Run it again.

An update that changes nothing says so. The last line names the version that
is installed when the run finishes, read back from the computer. `updated
0.0.3 -> 0.0.4` means the move happened. An update that could not move reports
that instead.

On Windows there is one more reason an update can stop, and it stops before
touching anything. Waired's programs are not yet signed with a certificate
Windows recognizes, so Smart App Control, or another application control
policy, can refuse to run them. The update runs the new programs first,
before it stops or replaces anything. If Windows refuses one, the update ends
there. The version you had is still installed, and its background service was
never stopped.

```
[waired] Checking the new programs run on this computer before replacing anything
[waired] Windows will not run the new waired.exe on this computer:
[waired]   An Application Control policy has blocked this file
```

The refusal is per file and changes on its own. A file that Windows refused in
the morning can run in the afternoon with nothing changed on the machine, so
trying again later is a real option, and so is staying on the build you have.
A failure after the files have been replaced puts the previous programs back
and restarts the service. If Windows refuses only the Waired app, the update
continues with a warning. For details, see
[If Windows refuses to run a program](/getting-started/install/windows/#if-windows-refuses-to-run-a-program).

<Aside type="note" title="A leftover file on Windows">
	Windows does not let a program be replaced while it is running, so the
	update renames the old copy aside. You may see a file such as
	`waired.exe.displaced-3eb6caa1` in `C:\Program Files\Waired`. It is the
	previous version. The next update deletes it, and you can delete it
	yourself.
</Aside>

## Release channels

| Channel | Who it is for |
|---|---|
| **stable** (default) | Everyone. Follows the numbered releases in order. While Waired is in pre-release, those are release candidates. |
| **edge** | Trying unreleased changes. Rebuilt on every merge. Not for daily use. |

`waired update` keeps this computer on the channel it is already on. A stable
install is never moved onto edge by an update, and the other way round.

To switch:

```sh
waired update --edge     # move to, or stay on, edge
waired update --stable   # move back to stable
```

Switching swaps the apt source on Linux, or the download the update pulls on
macOS and Windows. It works in both directions.

<details>
<summary>Installing straight onto edge</summary>

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_VERSION = 'edge'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | WAIRED_VERSION=edge sh
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | WAIRED_VERSION=edge sh
		```
	</TabItem>
</Tabs>

Once on edge, `waired update` keeps you there.

</details>

<Aside type="note" title="Update notices">
	The background service checks every few hours and shows a notice in the
	Waired app when an update is available. To turn the notice off, open the
	app's **Settings** submenu and clear **Notify me about updates**, or run
	`waired update --notify off`.
</Aside>
