Waired tells you when an update is available; applying it is always something
you trigger. Nothing updates itself behind your back.

## Update now

Click the **Waired icon** — in the menu bar on macOS, next to the clock on
Windows and Linux — and choose the
**“⚠ Update available”** entry when it appears.

Or from a terminal:

```sh
waired update
```

That checks, shows what it found, and asks before applying.

| Command | What it does |
|---|---|
| `waired update` | Check, then apply if a newer version exists |
| `waired update --check` | Report only — changes nothing |
| `waired update --yes` | Apply without asking (for scripts and servers) |
| `waired update --force` | Ask the source again instead of reusing a cached answer |

## How current is "latest"? (Linux)

On Linux the check reads the package index this computer downloaded earlier,
so `waired update --check` prints when that was:

```
Package index:   refreshed 3 hours ago
```

Once the index is more than a day old the line says so, because a newer build
may already be published that this computer has not heard about yet. Adding
`--force` refreshes the index first — that needs root, so it asks for sudo:

```sh
waired update --check --force
```

macOS and Windows ask the release feed directly, so their answer is already
current and `--force` only skips the cached one.

## What an update keeps

Everything that matters: you stay signed in, this computer keeps its identity
and its place in your network, and your settings are preserved. You do **not**
have to set up again.

Your downloaded models are not touched. The inference engine is: if this computer
already has one, an update brings it to the version that build of Waired runs,
because that is the only version Waired will use. A computer with no engine
does not get one from an update — turning local inference on is what installs it.

Whether the Waired app starts when you sign in is not changed either. If an
update finds it is not set to start for the person signed in at this computer,
it says so and leaves it at that. Open Waired once and tick **Start Waired on
login** if you want it back.

The Waired app itself, if it was open, is closed and reopened as part of the
update, so what you see afterwards is the new version. If it was not open, it
stays that way — an update never opens an app you had closed.

## If an update does not finish

An update that fails leaves the version you already had, running. Waired puts
the new files in place one at a time and only after all of them have been
downloaded and checked, so a failure part-way is an update that did not happen
rather than a half-installed one. Run it again.

An update that changes nothing says so. The last line names the version that
is installed when the run finishes — read back from the computer, not from
what the update set out to fetch — so "updated 0.0.3 -> 0.0.4" means the move
happened, and an update that could not move reports that instead of a version
on both sides of the arrow.

<Aside type="note" title="A leftover file on Windows">
	Windows will not let a program be replaced while it is running, so when
	Waired updates itself it renames the old copy aside — you may see a file
	like `waired.exe.displaced-3eb6caa1` in `C:\Program Files\Waired`. It is
	the previous version, it is not in use once you close and reopen anything
	that was running, and the next update deletes it. You can also delete it
	yourself.
</Aside>

## Release channels

| Channel | Who it is for |
|---|---|
| **stable** (default) | Everyone. Released versions only. |
| **edge** | Trying unreleased changes. Rebuilt on every merge, **not for production.** |

`waired update` keeps this computer on whichever channel it is already on — a
stable install never gets silently moved onto edge, or the other way round.

To switch:

```sh
waired update --edge     # move to / stay on edge
waired update --stable   # move back to stable
```

Switching swaps the apt source (Linux) or the download it pulls (macOS,
Windows), and is allowed in both directions.

<details>
<summary>Installing straight onto edge</summary>

<Tabs syncKey="os">
	<TabItem label="macOS / Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | WAIRED_VERSION=edge sh
		```
	</TabItem>
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_VERSION = 'edge'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```
	</TabItem>
</Tabs>

Once on edge, `waired update` keeps you there.

</details>

<Aside type="note" title="Update notifications">
	The background service checks every few hours and tells you when something is
	available. To silence the notification, use the **Settings** submenu of the
	Waired icon.
</Aside>
