If something is wrong and you only try one thing, try this:

```sh
waired doctor
```

It checks every part of the setup in turn and prints one line per check. Then,
if anything it can repair is broken, it offers to repair it.

## Reading the output

Each line is a symbol, the thing checked, and what was found.

<Expected>
```
✓ state directory — /home/you/.config/waired
✓ gateway token — /home/you/.config/waired/secrets/gateway-token
✓ device sign-in — valid
✓ network connection — connected
✓ waired-agent management — /waired/v1/status
✓ waired phase — active — overlay routing in effect
✓ Local Gateway — /v1/models
✓ claude-code managed settings — enabled
```
All ticks. Nothing to do.
</Expected>

| Symbol | Meaning |
|---|---|
| **✓** | Fine. |
| **⚠** | Working, but not the way it should be. Worth reading, not urgent. |
| **✗** | Broken. Something you are trying to do will not work. |
| **·** | Not checked. The line says why — usually that it needs administrator rights. |

When anything is not a ✓, the command finishes with a non-zero exit code and a
count — useful in a script, ignorable when you are reading it yourself.

## Pressing f

If any finding can be repaired automatically, you are asked:

<Expected title="At the end of the output">
```
Press f to fix [f/N]:
```
</Expected>

Press **f**. It re-applies the coding-agent setup (the same work as
`waired link all`) and tells you to run the check again:

```
Running repair (waired link all)...
Done. Re-run `waired doctor` to verify.
```

<Aside type="note" title="What f does and does not touch">
	The repair only re-applies **your own** coding-tool configuration and the
	gateway token in your home directory. It does not reinstall Waired, does not
	sign you out, does not touch models, and never edits a config file inside one
	of your projects.
</Aside>

To repair without being asked — in a script, or over SSH:

```sh
waired doctor --fix
```

## What each check means

| Check | What a failure means | Usual fix |
|---|---|---|
| **state directory** | Waired's own folder for identity, secrets and records is missing or unreadable. | Run the command with `sudo` (elevated on Windows). If it is genuinely missing, [sign in again](/getting-started/first-run/). |
| **gateway token** | The key your coding tools use to reach your AI is missing, or you cannot read it. | `waired link` — or press **f**. |
| **device sign-in** | This computer's sign-in is no longer valid. Your AI keeps working locally, but the computer no longer appears in your account and your other devices cannot reach it. | `waired init` — see [I signed in, but Waired says I am signed out](/troubleshooting/#i-signed-in-but-waired-says-i-am-signed-out). |
| **network connection** | You are signed in, but this computer has not connected yet. Waired keeps retrying on its own. | Wait a minute and run the check again. |
| **waired-agent service** | The background service is not running, and this line says *why* — read out of the operating system's own service records. On Windows it names things like a startup blocked by Windows security, a start that timed out, or an unexpected stop; on Linux and macOS, the exit status the service manager recorded. It quotes the underlying record in brackets so you can check it. | Start it from the Waired menu, or follow the suggestion in the line itself. |
| **waired-agent management** | The background service is not answering. This is the one that stops everything else working. | See [Waired is not running](/troubleshooting/#a-command-says-waired-agent-is-not-running). |
| **waired phase** | Routing is paused, or in an unexpected state. | `waired resume` — see [Pause and resume](/guides/pause/). |
| **Local Gateway** | The service is up, but the part that answers AI requests is not. A `503` usually means no model is loaded yet. | Wait for the download to finish (`waired models ls`), or [check your model](/guides/choose-a-model/). |
| **coding-agent entries** | Claude Code or OpenClaw is not configured to use Waired. | Press **f**. |
| **&lt;tool&gt; installation** | Only a **·** here: the tool's command is not on your `PATH`, so there is nothing to configure. If its folder exists but the command does not, the line says so — a leftover folder is not an installation. | Install the tool, or ignore the line if you do not use it. |
| **AI engine app signature** (macOS) | macOS will not run the installed AI software, so every attempt to start it is stopped. | Press **f** when the cause is a stray Waired file — see [it says the AI software is damaged](/troubleshooting/#macos-it-says-the-ai-software-is-damaged). Otherwise the check names the reinstall command. |

## When the check itself cannot see everything

On a normal desktop install some of Waired's files belong to the system, not to
you. Without administrator rights the doctor reports what it can, and marks the
checks it could not run with a **·** instead of leaving them out:

<Expected title="Without administrator rights">
```
· device sign-in — needs elevation to check; run `sudo waired doctor`
· waired phase — needs elevation to check; run `sudo waired doctor`
```
</Expected>

A **·** never counts towards the exit code — it is not a failure, only a gap.
To close the gap, run the check again with administrator rights.

<Tabs syncKey="os">
	<TabItem label="macOS / Linux">
		```sh
		sudo waired doctor
		```
	</TabItem>
	<TabItem label="Windows">
		Run it from a **Terminal (Administrator)** window — right-click the Start
		button → **Terminal (Administrator)**.

		```powershell
		waired doctor
		```
	</TabItem>
</Tabs>

Running it with `sudo` does not switch the check over to the administrator's own
setup. Your coding tools are configured in **your** home folder, so that is what
gets checked, and the first line says whose:

<Expected title="At the top of the output">
```
Running under sudo — checking the setup for user "you", not root.
```
</Expected>

Pressing **f** after an elevated run repairs that same setup, as you — the files
it writes stay yours.

<Aside type="tip" title="Sharing the output">
	If you are pasting the result into a bug report, add `--mask-pii` to
	`waired status` and `waired init` to hide your home folder, username, machine
	name and account email. `waired doctor` prints file paths, so read it before
	you post it.
</Aside>
