Three checks, quickest first. If any of them fails, run `waired doctor` next.
It checks every part of the setup and repairs what it can.

## 1. Look at the Waired icon

Select the **Waired icon**. It is in the menu bar on macOS, and next to the
clock on Windows and Linux.

<Screenshot
	src="app-ready.png"
	alt="The Waired menu showing the signed-in account, a Connected status, and an Inference item naming the active model."
	caption="Signed in, connected, and a model loaded."
	width="26rem"
/>

A healthy menu shows **Connected** at the top, your account address below it,
and, on a computer that runs models, **Engine: ready** with the model's name.

## 2. Ask it something

```sh
waired infer "say hi"
```

A greeting comes back within a few seconds.

This request goes to the model on this computer, so it works even when
nothing else on your network is reachable. It is the fastest way to prove
that the model itself is alive.

To see where the answer came from and why, add `--explain`:

```sh
waired infer --explain "say hi"
```

## 3. Read the full status

```sh
waired status --observability
```

On a computer that runs models, a healthy output looks like this:

```
Observability:
  Device:   my-desktop  uptime: 1m23s
  Engine:   ready (model=qwen3.8-27b, 0/4 slots used, inflight=0)
  Share:    enabled   Paused: no
  Mesh:     2 enrolled / 1 reachable / 1 ready
  Last:     (no inference yet)
```

| Line | What to check |
|---|---|
| **Engine** | `ready` means a model is loaded and can answer. `not ready` usually means it is still downloading. See [Nothing answers](/troubleshooting/no-answer/). |
| **Share** | `enabled` means your other computers may use this one's model. `disabled` has two possible causes: sharing is off on this computer, or the web console has taken it out of your network. `waired share status` says which. |
| **Paused** | `no` means Waired is handling requests. If it says `yes`, run `waired resume`. |
| **Mesh** | `enrolled / reachable / ready` across your computers. On a laptop, this line confirms that the computer running your model is up. |
| **Last** | Empty on a fresh install. After a request, it summarizes that request. `ttft` is how long you waited before the first word, and `latency` is how long the whole answer took. A follow-up in the same session usually has a much lower `ttft`, because the model reuses what it already read. |

Add `-o json` for a machine-readable version.

<Aside type="tip" title="On a laptop that does not run models">
	`Engine: not ready` is correct there. That computer is not supposed to host
	a model. What matters is the **Mesh** line showing at least `1 ready`,
	which means one of your other computers is available to answer.
</Aside>
