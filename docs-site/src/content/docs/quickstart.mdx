By the end of this page you will have a model running on your own
computer, and Claude Code answering from it instead of from the cloud.

<Aside type="tip" title="Which computer should run the model?">
	The most powerful one you own — a desktop with a GPU, or a Mac with
	Apple Silicon. Your laptop can use that computer's model later, from anywhere,
	without running anything itself. If you only have one computer, use it: it
	will both run the model and use it.

	You do **not** need a GPU. A GPU makes answers faster, but a recent
	CPU runs a small model fine.
</Aside>

## Step 1 — Run one command

Open a terminal, paste the line for your system, and press Enter.

<Tabs syncKey="os">
	<TabItem label="Windows">
		Open **PowerShell as Administrator**: right-click the Start button →
		**Terminal (Administrator)** → **Yes**.

		```powershell
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```

		`iwr` downloads Waired's install script, `iex` runs it.
	</TabItem>
	<TabItem label="macOS">
		Open **Terminal**: press ⌘ + Space, type `Terminal`, press Enter.

		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh | sh
		```

		`curl` downloads Waired's install script, `sh` runs it. You will be asked
		for your Mac password — **nothing appears on screen as you type it**,
		which is normal.
	</TabItem>
	<TabItem label="Linux">
		Open a terminal.

		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh | sh
		```

		`curl` downloads Waired's install script, `sh` runs it. You will be asked
		for your password — **nothing appears on screen as you type it**, which
		is normal.
	</TabItem>
</Tabs>

Before changing anything, the installer prints a summary of what it is about to
do and asks `Proceed? [Y/n]` — press Enter to continue.

That one command does three things: it installs Waired, starts it running in
the background, and then goes **straight into sign-in**. So do not close this
window — the next step is already happening in it.

<Aside type="tip" title="Would rather read the script first?">
	Download it, read it, run it — see the platform pages:
	[Windows](/getting-started/install/windows/#read-the-script-before-running-it) ·
	[macOS](/getting-started/install/macos/) ·
	[Linux](/getting-started/install/linux/).
</Aside>

## Step 2 — Sign in with Google

The installer hands over to sign-in on its own. It prints a link and waits:

<Expected title="In the terminal">
```
Sign in using this link:
  https://app.waired.ai/login/…

Control Plane: https://app.waired.ai

>> Press Enter to open your browser (or open the link above yourself)...
```
</Expected>

Press **Enter**. Your browser opens; choose your Google account. You can also
open the link yourself — in any browser, on this computer or another one. The
terminal keeps working either way and notices when you are signed in.

<Aside type="note" title="On a machine with no desktop">
	There is no browser to open, so the terminal prints the link and says
	*“Nothing to press here — sign-in continues on its own once you open the
	link.”* Open it on your phone or another computer; the terminal notices
	by itself.
</Aside>

Back in the terminal:

<Expected>
```
Signed in as: you@example.com
Waired is signed in and running in the background.

>> Setup is continuing in your browser…
   Keep this terminal window open until setup finishes — it does the parts the
   browser can't.
   (press Enter to continue in the terminal instead)
```
</Expected>

<Aside type="caution" title="Leave this terminal window open">
	Installing the inference engine needs administrator rights, and a web page cannot
	grant those. The terminal window you are in is what actually performs those
	steps while the browser drives them. Close it and setup stops with *“The
	setup command was closed before this finished”* — nothing is lost, but you
	have to come back and run `waired init` again.

	The setup page in the browser says the same thing while it is working. Once
	the terminal has done its part it tells you so — *“nothing more is needed
	from this terminal”* — and from then on you can close it.
</Aside>

## Step 3 — Finish setup in your browser

Switch to the browser tab that just opened. It asks which model to start
with, then does the work.

<Steps>

1. **Pick a model** from the list and press **Continue**. You can change
	it later, so the first entry is a fine choice.

2. **Watch the three steps run.**

	<Screenshot
		src="setup-wizard-progress.png"
		alt="The Waired setup page in a browser, showing three steps — Install the inference engine (done), Download the model (in progress, 7.9 GB of 19.2 GB at 41.9 MB/s), and Benchmark the inference speed (waiting)."
		caption="You can close this tab — the download keeps going."
	/>

	| Step | What is happening | How long |
	|---|---|---|
	| **Install the inference engine** | The program that loads and runs models. This is the part that needs administrator rights. | A minute or two |
	| **Download the model** | The model weights — several gigabytes. | 5–30 minutes |
	| **Benchmark the inference speed** | A short measurement, so Waired knows whether this machine keeps up. If it cannot, you are offered a lighter model. | Up to 5 minutes |

3. **Wait for “Everything's ready.”** Then press **Finish setup** for the list of your
	computers, or **Go to device** for this one’s page.

</Steps>

<Expected>
	Every step shows a tick, and the page says
	**“Everything's ready — this computer can now run models on its own.”**
</Expected>

<Expected tone="bad">
	*“To finish, run `sudo waired init` on this computer.”*

	The terminal window that was doing the work is gone — usually because it was
	closed, or because it never had administrator rights. Open a terminal and run
	that command; your progress is saved and it picks up where it stopped.
</Expected>

<details>
<summary>I would rather do this in the terminal</summary>

At *“Setup is continuing in your browser…”*, press **Enter**. The terminal
asks you to confirm before it takes anything over:

```
   Taking over means this terminal drives setup and the browser page stops.
   Any model download keeps running either way.
   Take over setup in this terminal? [y/N] (default: No)
```

Answer **y**. (Pressing Enter again answers *No* and leaves the browser in
charge — so a stray keystroke never moves setup out from under you.)

The terminal then takes over and asks whether to route Claude Code through
Waired; answer **Y**. Model installation and download run with a progress
bar in the terminal:

```
Starting the inference engine…
Preparing to download qwen3.8-27b…
Downloading qwen3.8-27b: 41%  7.3 GB / 17.7 GB (44 MB/s)
```

When it finishes:

```
╭─ 🎉 Waired is ready — everything completed successfully! ─╮
│ Account   you@example.com                                 │
│ Model     qwen3.8-27b — 58 tok/s                          │
│ Claude    routed through Waired                           │
│ Local inference is live via the waired-agent daemon.      │
│ Point your coding agent at Waired and start building.     │
╰───────────────────────────────────────────────────────────╯
```

On a server with no desktop this is the only option — see
[Sign in and set up](/getting-started/first-run/#no-desktop-no-browser).

</details>

## Step 4 — Check it worked

<Tabs syncKey="mode">
	<TabItem label="In the Waired app">
		Click the **Waired icon** — in the menu bar on macOS, next to the clock
		on Windows and Linux.

		<Screenshot
			src="app-ready.png"
			alt="The Waired app menu showing the signed-in account, a Connected status, and an Inference submenu naming the active model."
			caption="Signed in, connected, and a model loaded."
			width="26rem"
		/>

		<Expected>
			The top of the menu says **Connected**, your email is below it, and
			**Inference** names the model that is running.
		</Expected>
	</TabItem>
	<TabItem label="In the terminal">
		```sh
		waired infer "say hi"
		```

		<Expected>
			A greeting comes back within a few seconds. That answer was produced
			on your own computer — nothing was sent to a cloud AI provider.
		</Expected>
	</TabItem>
</Tabs>

<Aside type="note" title="Nothing came back?">
	Run [`waired doctor`](/getting-started/doctor/). It checks every part of the
	setup, marks each one ✓ / ⚠ / ✗, and — if you press **f** — repairs what it
	can. That single command resolves most first-run problems.
</Aside>

## Step 5 — Use it from Claude Code

Open Claude Code as you normally would, in any project. Type `/model`, pick
**Waired — 200k (any of your devices)**, and ask it something. The footer
tells you which AI answered.

<Screenshot
	src="claude-code-statusline.png"
	alt="The Claude Code footer showing the Waired status line, naming the local model that answered the last request."
/>

<Expected>
```
⚡ waired: on Waired (qwen3.8-27b)
```
Your own hardware answered, using that model.
</Expected>

A session you have not picked in starts on Claude Code's own default, which
is an Anthropic model, and the footer says `→ waired: Anthropic` — Waired
does not change that default for you. `/model` is the switch in both
directions: a **Waired** entry for your own computers, an Anthropic model for
the cloud, from your next message on.
