Waired bundles a catalog of models that spans laptops and multi-GPU servers.
Setup picks one that fits your computer, and you can switch at any time. See
[Change the model](/guides/choose-a-model/). For how the recommendation is
made, see [How Waired chooses a model](/guides/how-a-model-is-chosen/).

## How to read the tables

The catalog is split two ways, so you can go straight to the rows that apply
to your computer.

1. **By inference engine: Ollama or vLLM.** Your operating system and GPU
   decide which engine serves the model. Read only yours.
   - **Ollama**: macOS, Windows, Linux, CPU-only computers, and low-VRAM or
     integrated GPUs. Ships GGUF (quantized) builds. The number to watch is
     system RAM.
   - **vLLM**: NVIDIA (CUDA) and AMD (ROCm) discrete-GPU servers on Linux.
     Ships safetensors (awq, fp8, mxfp4) builds. The number to watch is GPU
     VRAM.

   A model family that ships builds for both engines appears in both
   sections.

2. **By architecture: dense or MoE.** Within each engine, dense models come
   first, then Mixture-of-Experts (MoE) models.
   - **Dense**: every parameter runs on every token. Best where you have
     compute and VRAM headroom, such as a discrete GPU, and smaller on disk
     for a given quality.
   - **MoE**: large total size, but only a few billion parameters are active
     per token, so decoding stays fast. Best on memory-rich unified-memory
     computers such as Apple Silicon and AMD Strix Halo.

**Size** says which class of GPU runs a model at all:

- **small** fits an 8 GB GPU.
- **medium** fits a 32 GB GPU.
- **large** needs more than a 32 GB GPU.

It means the same thing on every computer. The memory column beside it is a
threshold. The fit verdict for your computer comes from
`waired models ls --detail`, which counts your system RAM and VRAM together.

Whichever model wins, clients can address it by the fixed model name
`waired/default`. See [Use Waired from a chat app](/guides/chat-clients/).

The tables are generated at build time from each model's bundled manifest, so
they always match the catalog the client ships.

## vLLM models

For NVIDIA (CUDA) and AMD (ROCm) discrete-GPU servers on Linux. The memory
column is the minimum GPU VRAM for the quantized build. Smaller GPUs are
listed first. On computers with several identical NVIDIA GPUs, vLLM shards
the model across them, so their combined VRAM counts toward the requirement.
On recent NVIDIA GPUs, Ada and Hopper and newer, Waired serves the KV cache
in fp8, which roughly doubles the context window that fits in the same VRAM.
If a model's full context window still does not fit your GPU memory, Waired
serves it with a reduced window and says so in `waired status` and
`waired doctor` instead of failing to start.

### vLLM · Dense

Compute-bound. The natural fit when you have a discrete GPU with VRAM
headroom.

## Retired models

The catalog changes between releases. When a model is dropped, Waired keeps
its name working and points it at a replacement, so a name you saved in a
config file, a script, or a coding-tool setting keeps answering. You see a
line like this when it happens:

```
"qwen2.5-coder-0.5b" was retired; using "qwen3.5-0.8b" instead
```

Requests, downloads, and model switches all follow the replacement. Nothing
on your computer is deleted. A model you already downloaded stays where it
is and keeps running until you switch away from it. Choosing a retired model
as a new setting is the one case that does not follow the replacement.
Waired declines and names the replacement, so you pick deliberately.

| Retired | Use instead | Why |
|---|---|---|
| `qwen2.5-coder-0.5b-instruct` | `qwen3.5-0.8b` | It could not reliably use tools, which coding agents depend on. |
| `qwen2.5-coder-3b-instruct` | `qwen3.5-2b` | An older generation. The replacement is smaller and answers more reliably. |
| `qwen2.5-coder-7b-instruct` | `qwen3.5-4b` | An older generation. It could hold only a 32,000-token conversation, too short for coding work. |
| `qwen2.5-coder-14b-instruct` | `qwen3.5-9b` | The same 32,000-token limit as the 7B. |
| `qwen3-coder-30b-a3b-instruct` | `qwen3.6-27b` | An older generation of the same kind of model. |
| `qwen3-coder-next-80b-a3b-instruct` | `qwen3.6-35b-a3b` | An older generation. The replacement is smaller and scores better. |
| `qwen3-coder-480b-a35b-instruct` | `glm-5.2` | An older generation. |
| `glm-4.5-air-106b-a12b` | `glm-5.2` | An older generation, and it could hold only a 131,000-token conversation. |

Waired carries one generation of models at a time, and these were the
generation before the current one.
