Wairedは、推論専用のオーバーレイネットワークです。コントロールプレーンを通じて自分のパソコンどうしが互いを見つけられるようにしたあとは、パソコンどうしが暗号化された経路で直接通信するのに任せます。

## <a id="the-four-parts"></a>4つの構成要素

| 構成要素 | 役割 |
|---|---|
| `waired`（CLI） | 自分が実行するもの。`init`、`status`、`infer`、`link`など。 |
| `waired-agent` | バックグラウンドサービス（systemd、launchd、またはWindowsのサービス）。コントロールプレーンと通信し、ユーザー空間のWireGuardのデータプレーンを動かします。 |
| `waired-control`（コントロールプレーン） | ホストされたサービス。サインイン、デバイスの登録を扱い、署名されたNetwork Mapを配信します。自分で動かすものではありません。 |
| `waired-relay` | 直接届かないエージェントどうしの間で、暗号化されたWireGuardのパケットを転送するリレー。 |

画面のあるパソコンにはWairedアプリもあり、同じパソコンのバックグラウンドサービスと通信してその状態を表示します。

## <a id="how-a-request-flows"></a>リクエストの流れ

```
+-----------+   OAuth + enroll    +-------------------+
|  waired   | ──────────────────► |  waired-control   |
|  (CLI)    |                     |  (Control Plane)  |
+-----------+                     +---------+---------+
      │                                     │  signed Network Map
      ▼                                     ▼  (peer keys + endpoints + relay URLs)
+-----------+   WireGuard direct UDP   +-----------+
| waired-   | ◄──────────────────────► | waired-   |
|  agent A  |                          |  agent B  |
+-----+-----+                          +-----+-----+
      │            +---------------+         │
      └───wss────► | waired-relay  | ◄──wss──┘
                   +---------------+
                forwards encrypted WG packets only
```

1. **登録。** `waired init`がGoogleでサインインし、デバイスをコントロールプレーンに登録します。
2. **探索。** コントロールプレーンが各エージェントに、署名されたNetwork Mapを配信します。ネットワーク上のほかのデバイスの公開鍵、エンドポイント、リレーのURLです。
3. **直接接続。** エージェントどうしが直接のWireGuard UDP接続を開きます。データプレーンはユーザー空間で動くので、OSのVPNインターフェイスを設定する必要はありません。
4. **リレーへの切り替え。** 厳しいNATやファイアウォールで2台が直接の経路を開けない場合、暗号化されたWireGuardのパケットを転送するリレーに切り替わります。自動です。
5. **推論。** コーディングツールやクライアントは、このパソコンのLocal Gatewayにリクエストを送ります。Local Gatewayはローカルかピアの推論エンジンに振り分け、暗号化された経路で答えを返します。

## <a id="what-the-control-plane-does-and-does-not-do"></a>コントロールプレーンがすること、しないこと

コントロールプレーンは調整のためのサービスです。署名されたNetwork Mapで公開鍵とエンドポイントを配ることが役割のすべてです。プロンプトや答えを見ることはなく、リレーは転送する通信を復号できません。[プライバシー：パソコンの外に出るもの](/ja/concepts/privacy/)を参照してください。

## <a id="where-a-turn-runs"></a>ターンの実行先

リクエストは、自分のパソコンの中からルーティングが選んだパソコンで実行され、Claude Codeのターンは`/model`で選んだモデルが指す場所で実行されます。Wairedがターンを自分のパソコンからクラウドのAPIへ、またはその逆へ勝手に移すことはありません。[Claude Codeのターンはどこで実行されるか](/ja/guides/claude-code/how-turns-are-routed/)と[どのパソコンが答えるかを選ぶ](/ja/guides/routing/)を参照してください。
