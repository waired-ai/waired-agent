通常のインストールに必要なのは、[Wairedをインストールする](/ja/getting-started/install/)の
1行のコマンドだけです。このページでは、インストーラのそれ以外のオプションを説明
します。自前またはステージングのコントロールプレーン、バージョンの固定、
インストール先、クリーンインストール、Wairedの開発です。

<Aside type="caution" title="管理者と開発者向けです">
	管理者や開発の手順でこのページを案内されたのでなければ、ほぼ確実に通常の
	[Wairedをインストールする](/ja/getting-started/install/)の手順が必要なものです。
</Aside>

## <a id="point-at-a-specific-control-plane"></a>特定のコントロールプレーンを指定する

既定では、クライアントは本番のコントロールプレーンに登録します。別のコントロール
プレーンを使うには、インストール時にそのURLを渡します。

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		# フラグにはスクリプトをディスクに置く必要がある。パイプの形ではパラメーターを渡せない。
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 -OutFile $env:TEMP\install.ps1
		& $env:TEMP\install.ps1 -Control 'https://your-control-plane.example.com'
		```
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --control https://your-control-plane.example.com
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --control https://your-control-plane.example.com
		```
	</TabItem>
</Tabs>

インストーラはURLをパソコンに記録するので、あとでそのパソコンで`waired init`を
実行しても、フラグなしで同じコントロールプレーンに登録します。`--control`を再び
渡すのは変更するときだけです。`waired init --control <URL>`で最初にコントロール
プレーンを設定することもできます。環境変数`WAIRED_CONTROL_URL`は、`--control`や
`-Control`のフラグがないときに使われる、優先度の低い代替手段です。

## <a id="pin-a-specific-version"></a>特定のバージョンに固定する

`WAIRED_VERSION`は、最新版ではなく特定のリリースにインストーラを固定します。
`edge`も受け付けます。[リリースチャンネル](/ja/getting-started/update/#release-channels)を
参照してください。

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_VERSION = '1.2.3'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | WAIRED_VERSION=1.2.3 sh
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | WAIRED_VERSION=1.2.3 sh
		```
	</TabItem>
</Tabs>

リリースの名前どおりに書きます。`waired version`が表示する文字列と同じです。
リリース候補版は`1.2.3-rc1`で、リリースタグの先頭の`v`は省略できます。

<Aside type="note" title="Linuxのパッケージではプレリリースの表記が違います">
	`apt`はプレリリースを、ハイフンではなくチルダを使って`1.2.3~rc1`と表示します。
	これはDebianの表記で、リリース候補版として`1.2.3~rc1`が`1.2.3`より前に並ぶ
	ためのものです。Wairedが固定の指定を変換するので、`WAIRED_VERSION=1.2.3-rc1`で
	正しいパッケージが見つかります。
</Aside>

## <a id="choose-the-install-location-windows"></a>インストール先を選ぶ（Windows）

対話的に`install.ps1`を新規実行すると、インストール先を聞かれます。Enterキーで
既定の`C:\Program Files\Waired`のままになります。聞かれずに指定するには、
スクリプトをディスクに置いて`-InstallDir <path>`を渡すか、パイプの1行の形では
`WAIRED_INSTALL_DIR`を設定します。

```powershell
$env:WAIRED_INSTALL_DIR = 'D:\Waired'
iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
```

決まった場所はレジストリの`HKLM\SOFTWARE\Waired`に記録されるので、以後の
アップデート、再実行、`uninstall.ps1`は移動したインストール先を見つけられます。
Linux（aptの配置）とmacOS（`WAIRED_DARWIN_BINDIR`）は、それぞれの慣例のままです。

## <a id="development-preset"></a>開発用プリセット

Wairedの開発専用です。LinuxとmacOSでは`--dev`、Windowsでは`-Dev`を付けると、
組み込みの開発用コントロールプレーン向けにインストールが設定され、インストール後の
`waired init`はフラグなしでそこに登録します。両方を渡した場合は`--control`が優先
されます。この方法で登録したデバイスは、通常のアカウントには表示されません。

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 -OutFile $env:TEMP\install.ps1
		& $env:TEMP\install.ps1 -Dev
		```
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh | sh -s -- --dev
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh | sh -s -- --dev
		```
	</TabItem>
</Tabs>

## <a id="clean-install"></a>クリーンインストール

LinuxとmacOSでは`--clean`、Windowsでは`-Clean`、どのOSでも`WAIRED_CLEAN=1`で、
先にすべてを消してから新規にインストールします。手順は
[Wairedをアンインストールする](/ja/getting-started/uninstall/#start-over-on-the-same-computer)に
あります。`WAIRED_CLEAN=1`は、Windowsのパイプの1行の形で指定する方法です。
無人のパソコンでは`--yes`または`-Yes`で確認を省略します。これがないと、非対話の
実行は初期化を拒否します。

## <a id="every-installer-flag"></a>インストーラのフラグ一覧

LinuxとmacOSは`install.sh`、Windowsは同じオプションをPowerShellの表記にした
`install.ps1`を使います。どちらも環境変数の形を受け付けます。パイプの1行の
コマンドが、スクリプトをディスクに書かずにオプションを渡す方法です。

| `install.sh` | `install.ps1` | 環境変数 | 動作 |
|---|---|---|---|
| `--dry-run` | `-DryRun` | | 権限の必要なコマンドをすべて表示し、何も実行しない。 |
| `--yes`、`-y` | `-Yes` | | インストール前の一覧を含むすべての確認にyesと答える。 |
| `--no-init` | `-SkipInit` | | インストール後に`waired init`を実行しない。これがないと、インストールとサインインとセットアップが一度に進む。 |
| `--skip-ollama` | `-SkipOllama` | `WAIRED_NO_OLLAMA=1` | 推論エンジンをインストールしない。自分ではモデルを動かさないパソコン向け。 |
| `--skip-claude-proxy` | `-SkipClaudeProxy` | `WAIRED_NO_CLAUDE_PROXY=1` | Claude CodeをWairedではなくAnthropic APIに向けたままにする。 |
| `--mask-pii` | `-MaskPII` | `WAIRED_PII_MASK=1` | 出力中のホームフォルダ、ユーザー名、マシン名、アカウントのメールアドレスを伏せる。最善の努力。 |
| `--log-level <level>` | `-LogLevel <level>` | `WAIRED_LOG_LEVEL` | このログの詳細度でサービスを始める。`debug`、`info`（既定）、`warn`、`error`。あとから[`waired config log-level`](/ja/reference/cli/maintenance/#waired-config)で変えられる。 |
| `--check` | `-Check` | | 新しいバージョンがあるかを報告し、何も変えない。 |
| `--update` | `-Update` | | 新規インストールではなく、既存のインストールを更新する。 |
| `--edge`、`--latest` | `-Edge`、`-Latest` | `WAIRED_VERSION=edge` | 最新のmainビルドをインストールする、または切り替える。リリースではない。 |
| `--stable` | `-Stable` | | stableチャンネルをインストールする、または切り替える。 |
| `--clean` | `-Clean` | `WAIRED_CLEAN=1` | 先にすべて消してから新規にインストールする。破壊的。`--yes`がなければ確認する。 |
| `--control <URL>` | `-Control <URL>` | `WAIRED_CONTROL_URL` | 特定のコントロールプレーンに登録する。 |
| `--dev` | `-Dev` | | 組み込みの開発用コントロールプレーン。Wairedの開発専用。 |
| | `-InstallDir <path>` | `WAIRED_INSTALL_DIR` | インストール先（Windows）。 |
| `--non-interactive` | `-NonInteractive` | | 何も聞かない。ターミナルのないパソコンでは既定でサインインを省くが、これを付けるとサインインも行う。 |
| `--inference-enabled true`または`false` | `-InferenceEnabled` | | 「run models on this computer?」に聞かれずに答える。 |
| `WAIRED_VERSION=1.2.3` | `$env:WAIRED_VERSION` | `WAIRED_VERSION` | 特定のリリースに固定する。 |
| | | `WAIRED_STATE_DIR` | Wairedが識別情報と設定を置く場所。macOSとWindowsのみ。 |
| | | `WAIRED_OLLAMA_INSTALL_TIMEOUT` | 推論エンジンの初回ダウンロードをWairedが諦めるまでの時間。既定は`60m`。とても遅い回線でだけ、たとえば`3h`に上げる。 |
| | `-OllamaGpuMode <mode>` | | Windowsのみ。`auto`、`rocm`、`vulkan`、`cuda-only`、`cpu-only`。AMDのROCmのオーバーレイをダウンロードするかを決める。 |

<Aside type="note" title="Windowsのフラグにはスクリプトをディスクに置く必要があります">
	`iwr … | iex`の1行のコマンドはパラメーターを渡せません。環境変数の列を使うか、
	このページの前半の例のように先にスクリプトをダウンロードします。
</Aside>

## <a id="installing-on-a-computer-with-no-screen"></a>画面のないパソコンにインストールする

サーバー、CIのランナー、イメージのビルドでは、サインインする人がおらず、
サインインにはブラウザが必要です。そのため、インストーラはWairedをインストールして
起動したあと、サインインの前で止まり、あとで仕上げるよう伝えます。

```
Note: No terminal detected — sign-in skipped. To finish setup:
  - run:  sudo waired init
```

それでも試させたい場合は、`--non-interactive`または`-NonInteractive`を付けます。
セットアップのすべての質問に既定の答えを採用します。`--yes`は同じではありません。
質問には答えますが、サインインの前で止まります。ブラウザなしでサーバーを
サインインさせるには、
[認証キーでサーバーをセットアップする](/ja/getting-started/servers-and-auth-keys/)を
参照してください。

## <a id="moving-where-waired-keeps-its-files"></a>Wairedのファイルの置き場所を変える

`WAIRED_STATE_DIR`は、識別情報、鍵、設定を既定以外の場所に移します。macOSと
Windowsで動きます。インストーラがバックグラウンドサービスを登録し、好きな場所を
指定できるからです。Linuxでは無視されます。サービスの定義はパッケージの中に
標準の場所`/var/lib/waired`を書き込んだ状態で配布されるからです。`--clean`での
アンインストールは、移動したフォルダも削除します。

正式な一覧は、スクリプトを`--help`または`-Help`で実行するか、リポジトリの
[`packaging/install/README.md`](https://github.com/waired-ai/waired-agent/blob/main/packaging/install/README.md)を
読んでください。
