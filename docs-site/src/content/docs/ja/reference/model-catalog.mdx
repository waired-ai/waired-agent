Wairedは、ノートパソコンからマルチGPUのサーバーまでをカバーするモデルのカタログを同梱しています。セットアップが自分のパソコンに収まるモデルを選び、いつでも切り替えられます。[モデルを変更する](/ja/guides/choose-a-model/)を参照してください。推奨の決め方は[Wairedがモデルを選ぶ仕組み](/ja/guides/how-a-model-is-chosen/)を参照してください。

## <a id="how-to-read-the-tables"></a>表の読み方

カタログは2つの軸で分かれていて、自分のパソコンに当てはまる行にすぐたどり着けます。

1. **推論エンジン別：OllamaかvLLMか。** OSとGPUで、どちらの推論エンジンがモデルを動かすかが決まります。自分の節だけを読んでください。
   - **Ollama**：macOS、Windows、Linux、CPUだけのパソコン、VRAMの少ないGPUや内蔵GPU。GGUF（量子化）のビルドです。見るべき値はシステムRAMです。
   - **vLLM**：Linux上のNVIDIA（CUDA）とAMD（ROCm）の単体GPUを持つサーバー。safetensors（awq、fp8、mxfp4）のビルドです。見るべき値はGPUのVRAMです。

   両方の推論エンジン向けのビルドがあるモデルの系統は、両方の節に載ります。

2. **アーキテクチャ別：denseかMoEか。** 各推論エンジンの中では、denseのモデルが先に、次にMixture of Experts（MoE）のモデルが並びます。
   - **dense**：すべてのパラメーターが毎トークン計算されます。単体GPUのように計算力とVRAMに余裕がある環境に向き、同じ品質ならディスク上の大きさは小さめです。
   - **MoE**：全体は大きいものの、トークンごとに動くのは数十億パラメーターだけなので、生成は速いままです。AppleシリコンやAMD Strix Haloのような、メモリの多いユニファイドメモリのパソコンに向きます。

**サイズ**は、そのモデルを動かせるGPUの階級です。

- **small**は8GBのGPUに収まります。
- **medium**は32GBのGPUに収まります。
- **large**は32GBを超えるGPUが必要です。

どのパソコンで読んでも同じ意味です。となりのメモリの列は閾値です。自分のパソコンに収まるかどうかの判定は`waired models ls --detail`が行い、システムRAMとVRAMを合算して数えます。

どのモデルが選ばれても、クライアントからは固定のモデル名`waired/default`で指定できます。[チャットアプリから使う](/ja/guides/chat-clients/)を参照してください。

表は各モデルに同梱されたマニフェストからビルド時に生成されるので、クライアントが同梱するカタログと常に一致します。

## <a id="ollama-models"></a>Ollama向けモデル

Mac、Windows、CPUだけのパソコン、VRAMの少ないGPUや内蔵GPU向けです。メモリの列は、そのモデルのいちばん小さいGGUFのビルドに必要な最小のシステムRAMです。小さいパソコン向けが先に並びます。

### <a id="ollama--dense"></a>Ollama · Dense

## <a id="vllm-models"></a>vLLM向けモデル

Linux上のNVIDIA（CUDA）とAMD（ROCm）の単体GPUを持つサーバー向けです。メモリの列は量子化ビルドに必要な最小のGPUのVRAMです。小さいGPU向けが先に並びます。同じNVIDIAのGPUを複数枚持つパソコンでは、vLLMがモデルを複数枚に分割するので、合計のVRAMが要件に数えられます。AdaとHopper以降の最近のNVIDIAのGPUでは、WairedはKVキャッシュをfp8で提供し、同じVRAMに収まるコンテキストウィンドウが約2倍になります。それでもモデルのコンテキストウィンドウ全体がGPUのメモリに収まらない場合、Wairedは起動に失敗するのではなく、短いウィンドウで提供して`waired status`と`waired doctor`にその旨を表示します。

### <a id="vllm--dense"></a>vLLM · Dense

計算性能がボトルネックになるモデルです。VRAMに余裕のある単体GPUがあれば自然な選択です。

## <a id="retired-models"></a>退役したモデル

カタログはリリースの間に変わります。モデルが外れるとき、Wairedはその名前を使い続けられるよう後継モデルに向けるので、設定ファイル、スクリプト、コーディングツールの設定に保存した名前はそのまま答えます。そのときは次のような行が表示されます。

```
"qwen2.5-coder-0.5b" was retired; using "qwen3.5-0.8b" instead
```

リクエスト、ダウンロード、モデルの切り替えは、すべて後継モデルに従います。パソコンから削除されるものはありません。ダウンロード済みのモデルはそのまま残り、別のモデルに切り替えるまで動き続けます。退役したモデルを新しい設定として選ぶ場合だけは、後継モデルに従いません。Wairedは断って後継モデルの名前を示すので、意図して選ぶことになります。

| 退役 | 代わりに使うもの | 理由 |
|---|---|---|
| `qwen2.5-coder-0.5b-instruct` | `qwen3.5-0.8b` | コーディングエージェントが頼るツール利用が安定しませんでした。 |
| `qwen2.5-coder-3b-instruct` | `qwen3.5-2b` | 古い世代です。後継モデルは小さく、より安定して答えます。 |
| `qwen2.5-coder-7b-instruct` | `qwen3.5-4b` | 古い世代です。32,000トークンの会話しか保持できず、コーディングには短すぎました。 |
| `qwen2.5-coder-14b-instruct` | `qwen3.5-9b` | 7Bと同じ32,000トークンの上限です。 |
| `qwen3-coder-30b-a3b-instruct` | `qwen3.6-27b` | 同じ種類のモデルの古い世代です。 |
| `qwen3-coder-next-80b-a3b-instruct` | `qwen3.6-35b-a3b` | 古い世代です。後継モデルは小さく、スコアも上です。 |
| `qwen3-coder-480b-a35b-instruct` | `glm-5.2` | 古い世代です。 |
| `glm-4.5-air-106b-a12b` | `glm-5.2` | 古い世代で、131,000トークンの会話しか保持できませんでした。 |

Wairedは一度に1世代のモデルを載せていて、これらは現在の世代の1つ前の世代です。
