このページは、パブリック共有を有効にするときに表示される同意メッセージの、完全な
開示版です。各節で、何が起きるのか、なぜ起きるのかを説明します。

## <a id="what-public-share-is"></a>パブリック共有とは

パブリック共有は既定でオフで、明示的に選んだ場合にだけ有効になります。オンに
すると、ほかのWairedユーザーの空いているパソコン（公開ノード）で推論を実行でき、
ほかのWairedユーザーも自分のパソコンで処理を実行できるようになります。自分の
パソコンを使う人はゲストです。互いに表示されるのは、自動で割り当てられた
ニックネームだけです。公開ノードを使うには、自分もパソコンを1台共有する必要が
あります。[共有しなければ使えない理由](#why-you-must-share-to-use)を参照して
ください。

## <a id="what-the-other-side-can-and-cannot-see"></a>相手に見えるものと見えないもの

### <a id="the-owner-could-see-what-you-send"></a>所有者は送った内容を見られます

公開ノードの所有者は、そこに送った内容を読むことができます。リクエストはその
パソコンのメモリ内で平文のまま処理され、そのパソコンは所有者が完全に管理して
います。WairedのクライアントはApache-2.0のオープンソースで改変も可能なので、
リクエストをログに残さないことは、私たちの方針であり公式アプリの既定の動作
であって、技術的な保証ではありません。公式アプリは、プロンプトや答えをログにも
ディスクにも書き込みません。

結論は単純です。秘密情報、パスワード、個人情報、非公開のコードを公開ノードに
送らないでください。

### <a id="leftover-traces-fade-on-their-own"></a>残った痕跡は自然に消えます

モデルは動作中、応答を速くするために直近のリクエストの短期的なキャッシュ
（KVキャッシュ）を保持します。公開ノードでは、このキャッシュは後続のリクエストで
上書きされ、モデルを降ろすときに解放されます。このバージョンでは、それを能動的に
消去するものはありません。現在のモデルのランタイムには特定のリクエストだけを
選んで消去する手段がなく、キャッシュを消すためにモデルを強制的に降ろすと、
所有者自身の作業を妨げてしまうからです。

### <a id="answers-from-public-nodes-are-not-verified"></a>公開ノードの答えは検証されません

このバージョンは、公開ノードがモデルを忠実に実行したことも、誠実で品質の劣化
していない出力を返したことも検証しません。自分でできることは、`--min-model-size`で
モデルサイズの下限を設定すること、公開ノードを自分が指示したときにだけ使う
explicitモードを使うこと、結果を自分で判断することです。

### <a id="your-nickname-is-stable-so-patterns-can-be-linked"></a>ニックネームは固定なので、パターンは結び付けられます

アカウントの組み合わせごとに、固定のニックネームが割り当てられます。相手が自分の
名前、メールアドレス、アカウントを見ることはありません。ニックネームが変わら
ないため、同じ相手は、自分がいつ活動しがちで、どれだけ使うかという利用パターンを
時間をかけて認識できます。

### <a id="when-your-ip-address-is-visible"></a>IPアドレスが見える場合

同意メッセージには、相手にIPアドレスが見える「ことがある」と書かれています。
正確には次のとおりです。自分のパソコンと公開ノードが直接接続すると、互いに相手の
公開IPアドレスが見え、そこからおおよその地域とインターネットプロバイダーを
推測できます。直接接続できずにリレーを経由する場合、相手に見えるのはリレーの
アドレスで、自分のアドレスではありません。どちらになるかは自動で決まり、両方の
ネットワークの状況によるので、どちらかを前提にはできません。公開ノードを使う
ときも共有するときも、IPアドレスは見える可能性があるものとして扱ってください。
リレー経由の通信もエンドツーエンドで暗号化されていて、リレーは内容を読めません。
[アーキテクチャ](/ja/concepts/architecture/)を参照してください。

### <a id="what-waired-itself-records"></a>Waired自身が記録するもの

Wairedは、リクエスト数、トークン数、所要時間、使われたモデルを、ニックネームに
紐付けて記録します。これにより、双方が利用量の合計を確認できます。何を尋ね、
何が答えられたかは記録しません。Webコンソールにはこう書かれています。
「Waired never records what was asked or answered — only how many requests, how
many tokens, and how long they took.」プロンプトと答えがWairedのサーバーに触れる
ことはありません。[プライバシー：パソコンの外に出るもの](/ja/concepts/privacy/)を
参照してください。

## <a id="why-you-must-share-to-use"></a>共有しなければ使えない理由

パブリック共有は、参加者が提供し合って初めて成り立ちます。公開ノードを使うには、
自分のパソコンを少なくとも1台、公開で共有してオンラインにしておく必要があります。
同意メッセージを受け入れると同意が記録されますが、どこかの共有がオンになるわけ
ではありません。受け入れたときに製品はこう表示します。「To use other people's
computers you must share one of yours. Turn on public sharing for a computer in
the Waired console.」比率や割り当てはありません。1台共有すれば、アカウント全体で
使えるようになります。

## <a id="turning-it-on-and-off"></a>オンとオフの切り替え

公開共有のオンとオフは、Webコンソールで切り替えます。パソコンのページの
［Sharing］のカードに［People outside your account］のスイッチがあり、［Public
share］のタブにはニックネームごとの利用量と、パソコンごとの［Stop sharing］が
あります。コマンドやメニューの項目はありません。CLIとWairedアプリは状態を表示する
だけです。`waired public status`は状態を表示します。

```text
Sharing this computer publicly: on
Guest limit: automatic
Public sharing is turned on and off in the Waired console.
```

パソコン自身は、自分を貸し出すかどうかのスイッチを1つ持っています。
`waired share off`、またはWairedアプリの［Stop sharing this computer］は、公開の
ゲストを含むあらゆる提供をその場で止め、コンソールからは戻せません。
[自分の別のパソコンと共有する](/ja/guides/sharing/)を参照してください。

- **停止は即時です。** 共有をオフにすると、その時点で実行中のゲストのリクエストは
  打ち切られ、そのパソコンへのすべてのゲストのアクセスが取り消されます。いつでも
  オンに戻せます。
- **Max guests**は、同時に何人のゲストがそのパソコンを使えるかで、コンソールで
  設定します。既定の自動は、自分用に1スロットを確保します。パソコンの処理能力の
  上限まで上げられます。どの値にしても、パソコンが混んでいるときは自分の作業が
  優先されます。ゲストが長く邪魔することはなく、自分が使っている間はゲストの
  新しい処理は待たされます。
- コンソールの2つのスイッチは連動しています。公開共有をオンにすると自分のほかの
  パソコンとの共有もオンになり、［Your other computers］をオフにすると公開共有も
  オフになります。

## <a id="choosing-when-public-nodes-are-used"></a>公開ノードを使うタイミングを選ぶ

`waired public use`、またはWairedアプリの［Public computers］で、自分のリクエストが
公開ノードに送られてよい条件を決めます。

- **off**（既定）。公開ノードは使いません。
- **auto**。自分のパソコンが提供できる最良のモデルより、公開ノードのモデルの
  ほうが良い場合にだけ使います。
- **explicit**。下のフィルターが許すかぎり、公開ノードを使います。

CLIの追加のコントロール: `--min-model-size small|medium|large`は、指定したサイズ
以上のモデルを動かしているパソコンだけを使います。`--main on|off`と`--sub on|off`は、
メインの会話とサブエージェントについて別々に公開ノードの利用を許可または禁止
します。たとえば、メインのアシスタントは公開ノードを使わず、サブエージェントには
使わせる、という設定ができます。

自分のパソコンは、常に公開ノードより優先されます。

## <a id="known-limitations"></a>既知の制限

- 公開ノードへの最初のリクエストは、接続に数秒余分にかかります。
- 所有者が優先されます。公開ノードは、予告なくいつでもゲストの新しい処理の受け
  入れを止めることがあります。その場合、リクエストはほかのノードに送られるか、
  再試行されます。
- リクエストの実行中に所有者が共有を止めると、リクエストは失敗し、途中までの
  出力は破棄されます。

## <a id="your-consent"></a>同意について

同意は、受け入れたメッセージのバージョンとともに一度だけ記録されます。文言が
意味のある形で変わった場合は、公開ノードを使う前にもう一度確認されます。
ニックネームごとの利用量は、Webコンソールの［Public share］のタブでいつでも
確認できます。
