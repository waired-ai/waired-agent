## つなぐ

```sh
waired link opencode
```

これだけです。あとはいつもどおり OpenCode を起動し、Waired のモデルを選びます。

<Expected>
	```
	opencode:    configured

	OpenCode integration:
	  - Plugin written to ~/.config/opencode/plugin/waired.js
	    (registers the 'waired' provider). Restart opencode to pick it up.
	```
	OpenCode のモデル選択に **Waired** プロバイダが追加され、次の 1 つが並びます。

	| モデル | 用途 |
	|---|---|
	| `waired/default`(表示名は **Waired Default**) | このパソコンで Waired が動かしているモデル |
</Expected>

API キーも環境変数も使いません。Waired が、自分のマシンで動いているモデルへ
OpenCode を直接つなぎます。

<Aside type="note" title="自分の既定モデルは変更されません">
	リンクが行うのは、選べるモデルの一覧に Waired のモデルを**追加**することだけです。
	OpenCode が起動時に使うモデルはこれまでの設定のままで、使いたいときに
	`/models` かモデル選択から切り替えます。
</Aside>

<Aside type="tip" title="コーディングツールを複数入れている場合">
	名前を付けずに `waired link` を実行すると、見つかったすべて
	(Claude Code・OpenCode・OpenClaw)を設定します。
</Aside>

## 何が変わったか

変更されるのは、自分のホームフォルダの中の 3 ファイルだけです。

| パス | 内容 |
|---|---|
| `~/.config/opencode/plugin/waired.js` | `waired` プロバイダを登録する小さなプラグイン |
| `~/.config/opencode/commands/waired-status.md` | OpenCode の中で使う `/waired-status` コマンド |
| `~/.config/opencode/commands/waired-doctor.md` | OpenCode の中で使う `/waired-doctor` コマンド |

`opencode.json` には書き込まず、ホームフォルダの外も変更しません。

## 確認と解除

[`waired doctor`](/ja/getting-started/doctor/) が経路全体を検証します
(接続、ルーティングが停止していないか、モデルが読み込まれているか)。
**f** を押せば直せるものは直します。OpenCode の中では `/waired-status` と
`/waired-doctor` が同じ確認をして結果をまとめてくれます。

連携を削除するには:

```sh
waired unlink opencode
```

`waired link` が追加したものだけを正確に取り消します。
`~/.config/opencode/commands/` に自分で置いたファイルや、OpenCode 自身が
作ったファイルはそのまま残ります。

Waired アプリからも確認・再適用できます(**Waired アイコン** → **Settings** → **OpenCode**)。
