Wairedは、ホームフォルダに置く小さなプラグインを通じて、OpenCodeを自分のパソコンのモデルに接続します。コーディングツールの質問にyesと答えていれば、セットアップがインストールしています。このページでは、自分でインストールする方法、変更される内容、削除の方法を説明します。

## <a id="connect-opencode"></a>OpenCodeを接続する

```sh
waired link opencode
```

セットアップはこれだけです。そのあといつもどおりOpenCodeを起動し、Wairedのモデルを選択します。

<Expected>
	```
	opencode:    configured

	OpenCode integration:
	  - Plugin written to ~/.config/opencode/plugin/waired.js
	    (registers the 'waired' provider). Restart opencode to pick it up.
	```
	OpenCodeのモデル選択に、**Waired**プロバイダーが追加されます。

	| モデル | ターンが動く場所 |
	|---|---|
	| `waired/default`（表示は**Waired**） | 自分のコンピュータのどれか。200kのコンテキストウィンドウを持つコンピュータをWairedが選びます |
	| `waired/local`（**Waired local**） | このコンピュータ。200kのコンテキストウィンドウを持つ場合に限ります |
	| `waired/peer`（**Waired peer**） | 200kのコンテキストウィンドウを持つ自分の別のコンピュータ。このコンピュータでは動きません |
	| `waired/peer-<名前>`（**Waired peer: &lt;名前&gt;**） | 名前で指定したコンピュータ。200kのコンテキストウィンドウを持つ場合に限ります |
	| `waired/public`（**Waired public share**） | 200kのコンテキストウィンドウを持つ他の人のコンピュータ |
	| `waired/default[1m]`などの`[1m]`付きの項目（**… (1M context)**） | 上と同じで、1Mのコンテキストウィンドウを持つコンピュータ。その項目に答えられるコンピュータが1Mを宣言している間だけ出ます |
</Expected>

APIキーも環境変数も使いません。WairedはOpenCodeを自分のパソコンのモデルに直接接続します。

項目が指しているのはモデルではなく**パソコン**です。答えたパソコンが、そのパソコンの持っているモデルで動かします。`waired/local`は、このパソコンにエンジンがあってローカル推論がオンのときだけ出ます。`waired/public`は、Public Shareをオンにしたときだけ出ます。`waired/peer-<名前>`は、いま推論を提供していて、200,704トークン以上のコンテキストウィンドウを持つ自分のコンピュータ1台につき1つ出ます。

項目が指しているパソコンが答えられないときは、黙って別の場所で動かさずに、理由を言って失敗します。

この一覧は、Claude Codeの`/model`に出るものと同じで、`(1M context)`付きの項目も含みます。各行の意味は[Claude Codeのターンはどこで実行されるか](/ja/guides/claude-code/how-turns-are-routed/)を参照してください。

## <a id="subagents"></a>サブエージェント

サブエージェントは、自分の項目を指定しない限り、それを起動した会話と同じ項目を使います。OpenCodeに組み込みの`general`サブエージェントを別の場所で動かすには、`opencode.json`でモデルを指定します。

```json
{
  "agent": {
    "general": { "model": "waired/peer" }
  }
}
```

Wairedはサブエージェントのリクエストを会話のリクエストと区別します。そのため、[Webコンソール](/ja/guides/web-console/)の各パソコンのページにある［Serve main conversation］と［Serve subagents］のスイッチは、Claude Codeと同じようにOpenCodeにも効きます。

項目が使えるパソコンがすべて使用中のときは、Wairedはどれかが空くまでリクエストを待たせます。待つのは、会話なら最大1分、サブエージェントなら最大20秒です。それを過ぎるとエラーを返し、OpenCodeが自分でリクエストを再試行します。

<Aside type="note" title="一覧はOpenCodeの起動ごとに読み直されます">
	OpenCodeは起動時に、どのパソコンが使えるかをWairedに尋ねます。いま電源を入れたパソコンの項目は、次にOpenCodeを起動したときに出ます。Wairedが動いていないときは、`waired/default`だけの一覧に戻ります。
</Aside>

<Aside type="note" title="自分の既定のモデルは変わりません">
	連携は、選べるモデルの一覧にWairedのモデルを加えるだけです。OpenCodeが最初に使うモデルは、自分で設定したままです。使いたいときに`/models`か選択画面でWairedのモデルに切り替えます。
</Aside>

<Aside type="tip" title="コーディングツールが複数ある場合">
	名前を付けずに`waired link`を実行すると、見つかったツールをすべて設定します。Claude Code、OpenCode、OpenClawが対象です。
</Aside>

## <a id="context-windows"></a>コンテキストウィンドウ

どの項目も、200,704トークンのコンテキストウィンドウを持つコンピュータだけを使います。`[1m]`付きの項目は、1,048,576トークンを持つコンピュータだけを使います。`waired/local`と`waired/peer-<名前>`も同じです。それより小さいコンピュータ、たとえば動かしているモデルで200,704トークンをVRAMに保持できないコンピュータは、どの項目にも答えません。そのコンピュータ自身の`waired/local`も同じです。

プラグインは、各項目のコンテキストウィンドウを項目の名前だけから決めて`limit.context`に書きます。`[1m]`付きの項目は1048576、それ以外の項目は200704です。Wairedが動いていないときに一覧が戻る`waired/default`の項目も同じです。OpenCodeは、このウィンドウに達する前に会話を要約します。このウィンドウは、どのコンピュータが答えるかに依りません。`[1m]`の付かない項目で200,704トークンを超えるターンは、1Mを保持するコンピュータでも`prompt is too long`として返ります。`http://127.0.0.1:9473/v1/models`の一覧も、同じ値を`max_input_tokens`として示します。

プラグインは、どのコンピュータでもよい項目を`waired/default`として表示します。この名前で書いた設定はそのまま使えます。送信するときは、Claude Codeが送るのと同じidである`waired`として送ります。`waired/default[1m]`は`waired[1m]`として送ります。上の200kと1Mの条件を運ぶのはこれらのidです。チャットアプリが`waired/default`をそのまま送った場合、この条件は付きません。[チャットアプリから使う](/ja/guides/chat-clients/#what-to-put-in-the-settings)を参照してください。

項目が必要とするコンテキストウィンドウをどのコンピュータも満たさない場合、ターンは失敗し、OpenCodeがエラーを表示します。要約も再試行もしません。会話の長さが原因ではないからです。

```
None of your computers that could take this turn has a context window of 200704 tokens, which the model you picked needs.
```

## <a id="what-it-changed"></a>変更される内容

自分のホームフォルダの中の3つのファイルです。

| パス | 内容 |
|---|---|
| `~/.config/opencode/plugin/waired.js` | `waired`プロバイダーを登録する小さなプラグイン |
| `~/.config/opencode/commands/waired-status.md` | OpenCodeの中で使う`/waired-status`コマンド |
| `~/.config/opencode/commands/waired-doctor.md` | OpenCodeの中で使う`/waired-doctor`コマンド |

`opencode.json`は書き込まれず、ホームフォルダの外には触れません。

## <a id="check-it-or-remove-it"></a>確認と削除

[`waired doctor`](/ja/getting-started/doctor/)は、接続、ルーティングの一時停止、モデルの読み込みまで、経路全体を検査します。`f`キーを押すと、直せるものを修復します。OpenCodeの中では、`/waired-status`と`/waired-doctor`が同じ検査を行い、結果をまとめて表示します。

連携を削除するには次のように実行します。

```sh
waired unlink opencode
```

`waired link`が追加したものだけを元に戻します。`~/.config/opencode/commands/`に自分で置いたファイルと、OpenCodeがそこに書いたものは残ります。

連携の状態の確認と再適用は、Wairedアプリからもできます。**Wairedアイコン**を選択し、［Settings］の［OpenCode］の項目を選択します。
