通常はセットアップが Claude Code を接続します。このページは、接続されていなかった
場合の手順と、あとから制御する方法です。

環境変数の設定も、設定ファイルの編集も、エイリアスも必要ありません。Waired が
Claude Code のマシン全体設定を書き込むことで、Claude Code が自分のモデルと話すように
なります。Windows / macOS / Linux で同じ仕組みです。

<Aside type="caution" title="claude.ai のサブスクリプションはそのままです">
	認証情報は一切書き込まれないため、既存の Claude Code のサインインとサブスクリプションの
	扱いはこれまでどおり動きます。Waired が変えるのは「リクエストの行き先」であって、
	「誰としてサインインしているか」ではありません。
</Aside>

## 接続する

<Steps>

1. 連携を設定します。

	```sh
	waired link claude-code
	```

2. ルーティングを有効にします。ルーティングの質問に「いいえ」と答えた、ブラウザで
	Claude Code をつながなかった、`--skip-claude-proxy` を付けてインストールした、
	のいずれでもなければ **セットアップ時に済んでいます**。この手順は、あとから
	有効化したいときのためのものです。

	<Tabs syncKey="os">
		<TabItem label="macOS / Linux">
			```sh
			sudo waired claude enable
			```
		</TabItem>
		<TabItem label="Windows">
			管理者プロンプトから:

			```powershell
			waired claude enable
			```
		</TabItem>
	</Tabs>

3. いつもどおり Claude Code を起動します。

	```sh
	claude
	```

</Steps>

## どの AI が答えた？

フッターに毎回表示されます。

<Screenshot
	src="claude-code-statusline.png"
	alt="Claude Code のフッターに表示された Waired のステータス行。現在のルートと、直前の応答を返したローカルモデル名。"
/>

| 表示 | 意味 |
|---|---|
| `⚡ waired: on Waired (qwen3-8b-instruct)` | 自分のハードウェアが、そのモデルで応答 |
| `→ waired: Anthropic` | 本来の Anthropic API が応答 |
| `✕ waired: agent down` | このパソコンで Waired が動いていない |

クラウドにフォールバックしたターンの後には、その旨が 1 行表示されます。
黙って転送されることはありません。

<Aside type="note" title="ステータス行が出ない場合">
	プロジェクト直下の `.claude/settings.json` が、Waired の設定より優先されています。
	プロジェクト内で `waired claude status` を実行すると、優先されているファイル名と、
	自分のステータス行スクリプトに貼れる 1 行が表示されます。Waired がプロジェクトの
	ファイルを書き換えることはありません。
</Aside>

## 送り先を切り替える

セッション中に、再起動なしで切り替えられます。

```
/waired-route waired      # 自分の AI だけ。クラウドには送らない
/waired-route anthropic   # 本来の Anthropic API
/waired-route auto        # 既定。自分を優先し、必要ならフォールバック
```

次のメッセージから反映されます。ターミナルからも同じことができます。

```sh
waired claude route                          # 今の状態を表示
waired claude route anthropic --sub waired   # メイン会話はクラウド、サブエージェントは自分
```

`--sub` は知っておく価値があります。Claude Code のサブエージェントは大量の
ファイル読み取りを担当するので、メイン会話はクラウドを使いつつサブエージェントだけ
自分のハードウェアに残す、という中間案が実際に有効です
（→ [プライバシー](/ja/concepts/privacy/)）。

引数だけの実行は、分けたものをまとめて戻します。`waired claude route auto` は
メイン会話を動かし、**同時に**サブエージェントをそれに追従する状態へ戻します。
それが設定済みの分割を取り消す場合は、その旨を表示します。メイン会話だけを動かして
サブエージェントをそのままにしたいときは `--main` を使ってください。

**Waired アイコン → Claude Code** からも変更でき、本体とサブエージェントを別々に
選べます。

<Aside type="note" title="「waired」は自分のネットワークであって、このパソコンとは限りません">
	実際にどのマシンが応答するかは `waired worker` が決めます —
	[ほかの端末を追加する](/ja/getting-started/add-a-device/)を参照してください。
</Aside>

## よく驚かれること

**Claude Code には Anthropic のモデル名が出たままです。** Opus や Sonnet などが
これまでどおり選べます。Waired が処理する場合は、セッションで何が選ばれていても
**そのデバイスで動いているローカルモデル**が応答します。Anthropic のモデル名が
意味を持つのは、実際にクラウドへ送られたときだけです。

**`/model` には Waired の項目も 4 つ出ます。** Anthropic のモデル名と並んで
**Waired auto — 200k** / **Waired auto — 1M** / **Waired local** /
**Waired cloud** が、いま開いているメニューからそのまま選べます。
Claude Code を接続したあとに表示され、一度 Claude Code を再起動すると出てきます。
出てこない場合は
[/model に Waired の項目が出ない](/ja/troubleshooting/#the-waired-entries-are-missing-from-model)
を参照してください。

**auto** の 2 つは、セッションが一度に保持できる会話量だけが違います。どちらも
使えるときは自分のコンピュータを、使えないときは Anthropic を使いますが、
コンピュータが使われるのは、その量の会話を実際に収められるモデルを動かしている
ときだけです。たいていのコンピュータは 200k を満たせます。1M はデスクトップ機の
搭載メモリをはるかに超えるので、選んでもたいていは Anthropic が応答します。
作業に合わせて選んでください — 普通のセッションは 200k、大きなコードベースを
まるごと Claude Code に渡すときは 1M です。

**Waired local** はそれを一切気にせず、このコンピュータが収められる量のまま、
必ずこのコンピュータを使う項目です。何があっても手元のマシンに応答させたいときに
選んでください。

**長いセッションは要約されます。** モデルが一度に保持できる会話量はクラウドより
少ないため、Claude Code が古いターンを要約して収めます。**auto** の 2 つはその
上限をあらかじめ明示しており、実際にその量を収められるコンピュータだけが応答する
ので、要約は想定どおりのタイミングで起こります。**Waired local** だけは例外で、
このコンピュータが収められる量をそのまま使います。あとで別のモデルに切り替えた
ときは、新しい上限を伝えるために `sudo waired claude enable` を実行し直して
ください（Windows は管理者プロンプトから）。
`waired claude status` が両方の数値を表示し、食い違っていればそう伝えます。これは
失敗ではなく、セッションが途切れずに継続しているということです
（→ [長い Claude Code のセッションが要約される](/ja/troubleshooting/#long-claude-code-sessions-get-summarized)）。

**モデルによっては保持できる量がかなり少なくなります。** カタログの一部 —
`gpt-oss` の 2 本 — は 200,000 ではなく 131,000 トークン程度が
上限です。Waired がこれらを自動で選ぶことはなく、モデル一覧でもその旨を示しますが、
選ぶこと自体は可能です。選んだ場合、Claude Code は想定より早く上限に達します。
要約して継続するので止まりはしませんが、限界まで詰めてからの要約は、早めの要約より
多くを失います。早めに始めさせてください。

```sh
export CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=55
```

131k のモデルでは 55〜60 が実用的な範囲です。これは Waired ではなく Claude Code
側の設定なので、Claude Code のリリースで変わる可能性があり、フルセッションを
保持できるモデルでは何も起きません。

**失敗しても止まらず、クラウドに回ります。** 一時停止中・ダウンロード中・非対応の
リクエスト形式などで応答できないとき、Claude Code は本来の Anthropic API を使って
ターンを完了させます。転送されるくらいならエラーを見たい場合は、`waired` ルートを
選んでください。

**固定したパソコンが別のパソコンで代替されることはありません。** `waired worker`
でどれかのパソコンに固定していて、それが使えないとき、Waired はこのパソコンで
代わりに答えたりしません。`auto` ルートなら本来の Anthropic API に回り、その理由が
会話に 1 行表示されます。`waired` ルートならエラーになります
（→ [パソコンを固定したらリクエストが通らなくなった](/ja/troubleshooting/#requests-stopped-working-after-i-pinned-a-computer)）。

## 1 台をほかの端末と共有する

[Web 画面](https://app.waired.ai/)のマシンのページで、ほかの端末からの使われ方を
調整できます。

- **Serve main / subagents** — 2 つのスイッチ。main を切れば、遅いマシンを
  サブエージェントの並列作業専用にできます。これは*ほかのマシンから*来るリクエストに
  対する設定で、そのマシン自身の Claude Code は常に動きます。
- **Max concurrent requests** — 同時に処理する数。並列を増やすとメモリを余分に使い、
  1 件あたりも遅くなるため、推奨上限が表示され、超える前に警告が出ます。

## 確認と解除

```sh
waired claude status
```

ルーティングの有効・無効と、設定ファイルの場所を表示します。

| | |
|---|---|
| Linux | `/etc/claude-code/managed-settings.json` |
| macOS | `/Library/Application Support/ClaudeCode/managed-settings.json` |
| Windows | `C:\Program Files\ClaudeCode\managed-settings.json` |

Claude Code を Waired 経由にするのをやめる（Claude Code は通常動作に戻ります）:

```sh
sudo waired claude disable    # Windows は管理者プロンプトから
```

連携ファイルごと削除する:

```sh
waired unlink claude-code
```
