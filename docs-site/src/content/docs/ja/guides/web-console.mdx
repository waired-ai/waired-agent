Wairedアプリは目の前のパソコンを操作します。Webコンソールは、スマートフォンを含むどのブラウザからでも、自分のすべてのパソコンを操作します。[app.waired.ai](https://app.waired.ai)を開き、同じアカウントでサインインします。Wairedアプリの［Open Waired console…］からは、サインイン済みの状態で開きます。

コンソールのナビゲーションは英語です。各ページは英語と日本語で表示でき、ブラウザの言語に従います。

## <a id="devices"></a>Devices

最初に表示される一覧です。パソコンごとに1行あり、動かしているものと、いま届くかどうかが表示されます。

| 列 | 内容 |
|---|---|
| **Status** | そのパソコンがオンラインで届く状態かどうか。 |
| **Inference** | モデルを自分で動かしているかどうかと、その状態。［Ready］、［Inference off］、または問題の内容。 |
| **Peers** | 自分のほかのパソコンのうち、いま通信できる台数。 |
| **Last seen** | 最後に報告があった時刻。 |
| **Sign-in expires** | サインインの失効を有効にしている場合、そのパソコンのサインインが失効する時期。 |

セットアップが終わっていないパソコンには、セットアップページへのリンクを含むバナーが表示されます。[ブラウザでセットアップする](/ja/getting-started/set-up-in-the-browser/)を参照してください。

## <a id="one-computers-page"></a>パソコンごとのページ

行を選択します。

### <a id="overview"></a>Overview

パソコンの名前、ハードウェア、OS、Wairedのバージョン、アドレス、最後に報告があった時刻です。［Rename］で名前を変えられます。名前は自分のためのもので、変えても何も壊れません。

### <a id="model"></a>Model

このパソコンが動かしているモデルと、切り替えるための［Change model］です。新しいモデルはバックグラウンドでダウンロードされ、進捗がここに表示され、新しいモデルの準備ができるまで現在のモデルが答えます。vLLMのパソコンでは、そのあと推論エンジンが新しいモデルを読み込むために再起動し、準備ができるまで答えません。自分のモデルを動かしていないパソコンにはこの節はありません。

### <a id="sharing"></a>Sharing

このパソコンを誰に提供するかを、3つのスイッチで決めます。［Your other computers］、チームに入っている間の［Team share］、［Public share］です。各スイッチの隣のバッジは、いま起きていることを表します。［Shared］、［Not shared］、またはパソコン自身のスイッチがオフの間は［Off on the computer］です。スイッチは連動しています。［Your other computers］をオフにするとTeam shareとPublic shareもオフになり、そのどちらかをオンにすると［Your other computers］もオンになります。[チーム共有](/ja/team-share/)と[パブリック共有](/ja/public-share/)を参照してください。

カードには、パソコン自身が持つスイッチの状態も表示されますが、ここからは変えられません。そのスイッチがオフの間は、カードの上部に［Sharing is off on this computer］と表示されます。オンに戻すのはパソコン側で行います。Wairedアプリの［Share this computer］か、`waired share on`です。[自分の別のパソコンと共有する](/ja/guides/sharing/)を参照してください。

［Which requests］を開くと、［Main conversation］と［Sub-agents］の2つのスイッチがあります。共有しているすべての相手から、Claude CodeとOpenCodeのどの種類のリクエストをこのパソコンが受けるかを決めます。このパソコン自身のClaude CodeとOpenCodeは常に動きます。

### <a id="capacity"></a>Capacity

［Requests at once］は、このパソコンが同時に応答するリクエストの件数です。［Public share limit］は、そのうちパブリックユーザーに渡す件数です。いま適用されている値が、それぞれの欄の隣に表示されます。［Routing priority］は自分のパソコンのどれを先に試すか、［Keep model in memory］は最後のリクエストのあとにモデルをメモリに残しておく時間です。それぞれの動作は[自分の別のパソコンと共有する](/ja/guides/sharing/#how-much-work-it-takes-at-once)を参照してください。

<Aside type="note" title="並行処理はメモリを使います">
	［Requests at once］を上げると同時に多くの処理を実行できますが、同時のリクエストごとにVRAMを確保するため、すべてのリクエストが遅くなります。コンソールにはこのパソコンの推奨最大値が表示され、それを超える前に確認されます。
</Aside>

### <a id="authentication"></a>Authentication

このパソコンのサインインがいつ失効するか、失効の対象かどうかです。パソコンを一時的に無効化して、削除せずに使えない状態にすることや、削除することもできます。

<Aside type="caution" title="削除は、もう手元にないパソコンのためのものです">
	削除は、パソコンを外側からネットワークから外します。パソコンが手元にある場合は、代わりにそのパソコンで[Wairedをアンインストール](/ja/getting-started/uninstall/)してください。両側からきれいに外れます。削除されたパソコンでWairedが動いたままだと、サインインし直すまで動かなくなります。
</Aside>

## <a id="public-share"></a>Public share

アカウント全体の要約です。自分のどのパソコンをパブリックユーザーと共有しているか、自分が何を使ってきたかが表示されます。各パソコンから共有の設定に移動できます。ここで［Stop sharing］を押すと、そのパソコンでパブリックユーザーが実行中の処理は打ち切られます。[パブリック共有](/ja/public-share/)を参照してください。

## <a id="settings"></a>Settings

ネットワークの名前、サインインが失効するかどうかとその期間、アカウントが受け付けるサインインの方法、認証キーです。[認証キーでサーバーをセットアップする](/ja/getting-started/servers-and-auth-keys/)を参照してください。

## <a id="logs"></a>Logs

何がいつ変わったかの記録です。パソコンの参加、名前の変更、無効化や削除、ルーティングや処理能力の変更、キーの更新、セットアップ中の選択などです。何かが変わったのに何が変えたのか分からないときに見る場所です。

## <a id="account"></a>Account

表示名、アカウントID、現在のセッションです。［Delete account］もここにあります。アカウントとその中のすべてを削除し、元に戻せません。

<Expected tone="bad" title="一覧にパソコンがない">
	サインインが完了していないか、削除されています。そのパソコンで`waired status`を実行します。識別情報がないと表示されたら、サインインし直します。[サインインする](/ja/getting-started/sign-in/)を参照してください。
</Expected>
