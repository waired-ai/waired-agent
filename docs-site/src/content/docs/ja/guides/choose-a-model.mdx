Wairedは、セットアップ中にこのパソコンのモデルを選びます。コーディングセッション
全体を処理できる中でいちばん良いモデルです。ほかのモデルも収まるかぎり選択
できます。このページでは、何が動いているかの確認と切り替えの方法を説明します。

## <a id="whether-to-change-it"></a>変えるべきかどうか

| したいこと | 操作 |
|---|---|
| 答えの品質を上げたい。メモリに余裕がある | 大きいモデルに切り替える |
| 答えを速くしたい。パソコンが重い | 小さいモデルに切り替える |
| いま何が動いているかを知りたい | [動いているモデルを確認する](#which-model-is-running)を参照 |
| モデルを動かしていないパソコンで動かしたい | [モデルが選ばれなかった場合](#if-no-model-was-picked)を参照 |
| 特に不満はない | そのままにします。自動の選択は良い既定値です |

<Aside type="caution" title="大きければ良いとはかぎりません">
	メモリに収まらないモデルは、遅く動くのではなく、読み込みに失敗します。この
	パソコンは答えなくなります。大きいモデルに切り替える前に、
	[モデルカタログ](/ja/reference/model-catalog/)でそのモデルのメモリの列を確認して
	ください。
</Aside>

## <a id="if-no-model-was-picked"></a>モデルが選ばれなかった場合

Wairedがモデルを選ばず、ローカル推論をオフの状態で始めるパソコンがあります。理由は
速度です。フルサイズのモデルをダウンロードする前に、Wairedは小さいモデルで現実的な
リクエストを計測します。1回の答えに45秒より長くかかると、何分も待つことになる
モデルをダウンロードせずにそこで止まります。
[Wairedがモデルを選ぶ仕組み](/ja/guides/how-a-model-is-chosen/)を参照してください。

パソコンはネットワークに加わり、自分のほかのパソコンのモデルを使えます。それでも
ローカル推論をオンにするには、`waired inference on`を実行するか、Wairedアプリで
［Run models on this computer］を選択します。一度選ぶと、Wairedはその選択を保ち
ます。

```sh
waired inference status   # オンかオフか。Wairedが決めた場合はその理由
```

## <a id="which-model-is-running"></a>動いているモデルを確認する

**Wairedアイコン**を選択し、［Inference］を開きます。動作中のモデルがそこに
表示されます。ターミナルからは次のように確認します。

```sh
waired models ls              # ダウンロード済みのモデルと、動作中のモデル
waired models ls --detail     # すべてのモデル、必要なメモリ、このパソコンに収まるか
```

## <a id="reading-the-list"></a>一覧の読み方

一覧の各モデルには、必要なメモリと、`small`、`medium`、`large`のサイズが表示され
ます。サイズは、そのモデルを動かせるGPUの階級です。大きいモデルほど答えの品質は
上がり、必要なパソコンの性能も上がります。

- **メモリの値**は、コーディングセッション全体を処理するためにモデルが使う量です。
  重み、推論エンジン自身のオーバーヘッド、KVキャッシュを含みます。システムRAMと
  VRAMは合算します。
- **VRAMは搭載量ではなく空き容量で数えます。** ディスプレイの描画にも使っている
  GPUや、ほかのプログラムが使っているGPUは、貸せる量が減ります。使用中のGPUでは、
  GPUの仕様上の容量から想像されるより小さいモデルが推奨されます。GPUを使っている
  ほかのものを閉じてWairedを再起動すると、そのメモリが再び見えるようになります。
- Wairedが選ぶモデルには**recommended**の印が付きます。動くが推奨ではないモデルには
  理由が付き、選択できます。
- このパソコンで遅すぎると計測されたモデルは、推奨ではなくなります。各行に計測した
  内容が表示されます。
- vLLMを動かすNVIDIAのパソコンでは、重みが収まるモデルでも長い会話のための余裕が
  足りないことがあります。該当する行にはそのことが表示されます。
- このパソコンで動かせないモデルには、必要な量が表示されます。選ぶと不足分とともに
  先に確認され、既定の答えは［Cancel］です。

## <a id="switch-models"></a>モデルを切り替える

<Tabs syncKey="mode">
	<TabItem label="Wairedアプリで">
		<Steps>

		1. **Wairedアイコン**を選択します。
		2. ［Models］を開きます。
		3. 一覧からモデルを選択します。

		</Steps>

		変更はその場で反映されます。推論エンジンは数秒で再読み込みし、応答を
		続けます。まだダウンロードしていないモデルなら、ダウンロードが始まって
		アイコンに進捗が表示され、新しいモデルの準備ができるまで元のモデルが答えます。
	</TabItem>
	<TabItem label="ターミナルで">
		```sh
		waired models use <model-id>
		```

		モデルIDは[モデルカタログ](/ja/reference/model-catalog/)のIDの列の値で、
		たとえば`qwen3.8-27b`です。必要ならダウンロードがバックグラウンドで
		走ります。進捗は`waired status`で確認できます。

		代わりにWairedにこのパソコンを計測させて切り替えを提案させるには、次のように
		実行します。

		```sh
		waired runtimes benchmark
		```

		ベンチマークは、いまのモデルでこのパソコンがどれだけ速いかを計測します。別の
		モデルのほうが適していれば、Wairedは両方のモデルの名前を挙げて切り替えを提案
		します。承諾すると、ダウンロードが進捗バーつきで走ります。Enterキーを押すと
		いつでもバックグラウンドで続けられます。新しいモデルが応答を始めると、Wairedは
		もう一度計測してその値を報告します。

		Wairedが提供するいちばん小さいモデルでもまだ遅すぎる場合は、Wairedはそのことを
		伝え、ローカル推論をオンのままにするかを聞きます。`n`と答えるとオフになり、
		パソコンは自分のほかのパソコンへの入口として動き続けます。

		そのあと、Wairedは元のモデルを削除するかを聞きます。ファイルは数GBあるからです。
		あとで大きいモデルに戻す予定なら、残しておいて構いません。
	</TabItem>
	<TabItem label="デスクトップのないサーバーで">
		`waired models use <model-id>`は、SSH経由でもほかと同じように使えます。設定
		ファイルでモデルを指定してバックグラウンドサービスを再起動することもできます。

		<Tabs syncKey="os">
			<TabItem label="Linux">
				`/etc/waired/agent.json`の`inference.bundled_model_id`にモデルIDを
				設定し、次のように実行します。

				```sh
				sudo systemctl restart waired-agent
				```
			</TabItem>
			<TabItem label="Windows">
				`%PROGRAMDATA%\waired\agent.json`を同じように編集し、次のように実行
				します。

				```powershell
				Restart-Service waired-agent
				```
			</TabItem>
		</Tabs>

		環境変数`WAIRED_INFERENCE_BUNDLED_MODEL_ID`とフラグ
		`--inference-bundled-model-id`も同じ設定で、この順に設定ファイルより優先
		されます。[高度なインストールオプション](/ja/reference/install-options/)を
		参照してください。
	</TabItem>
</Tabs>

## <a id="confirm-the-switch"></a>切り替わったことを確認する

```sh
waired status --observability
```

**Engine**の行に、いま読み込まれているモデルの名前が表示されます。

```
Engine:   ready (model=qwen3.8-27b, 0/4 slots used, inflight=0)
```

`not ready`と表示される場合は、まだダウンロード中の可能性が高く、
`waired models ls`で進み具合を確認できます。ダウンロードが終わっても`not ready`の
ままなら、そのモデルはこのパソコンに収まりません。小さいモデルに戻してください。

<Aside type="note" title="推奨ではないモデルも選べます">
	動くが推奨ではないモデルを選ぶと、拒否されるのではなく、警告と確認が表示され
	ます。このパソコンのメモリに収まらないモデルも選択肢として残ります。Wairedは
	`needs 32 GB RAM (have 31 GB)`のように不足分を示し、読み込みは失敗する見込みだと
	伝え、ダウンロードの前にもう一度確認します。推論エンジンにそのモデルのvariantが
	ない場合、警告は`has no Ollama variant`となり、メモリの値は示されません。メモリを
	増やしても解決しないからです。推論エンジンがそのモデルに対して古すぎる場合は、
	そのことを示して`waired update`を案内します。
</Aside>

## <a id="free-up-disk-space"></a>ディスク領域を空ける

モデルは1つ数GBあります。使っていないモデルを削除するには、次のように実行します。

```sh
waired models rm <model-id>
```

先に確認されます。`--yes`を付けると確認を省略します。モデルのファイルが削除され、
領域が戻ります。このパソコンのほかのモデルが同じファイルを共有している場合、
ファイルは残り、項目だけが消えます。削除に失敗した場合、Wairedはそのことを伝え、
空いていない領域を報告する代わりにモデルを一覧に残します。
