Wairedは、カタログのすべてのモデルについて2つの問いに別々に答えます。この
パソコンにそもそも収まるか、そして推奨するモデルかどうか、です。このページでは
その両方と、ローカル推論をオフのままにすることがある速度の計測、Wairedが
カタログに載せていても自動では選ばないモデルについて説明します。

## <a id="offered-does-it-fit-at-all"></a>提示：そもそも収まるか

モデルは、このパソコンのメモリに収まるかぎり提示されます。収まるとは、重み、
推論エンジン自身のオーバーヘッド、コーディングセッション全体のKVキャッシュを
保持できることです。システムRAMとVRAMは合算します。推論エンジンは、GPUに
収まらない分をシステムRAMに置いてそこから動かすからです。

その合計が、`waired models ls --detail`とWairedアプリの［Models］の一覧に
表示される**NEEDS**の列です。収まらないモデルは、必要な量とともに表示され、
選択もできます。選ぶと先に確認されます。

Appleシリコンだけは、この2つの値を合算しません。VRAMは同じメモリの一部なので、
RAMの合計が全体です。

## <a id="recommended-can-it-hold-a-whole-coding-session"></a>推奨：コーディングセッション全体を保持できるか

収まるモデルの中から、Wairedは、約200,000トークンのコーディングセッション全体を
モデルの重みをGPUに載せたまま処理できる、いちばん強いモデルを推奨します
（waired#1056に記録されたオーナー裁定）。

収まるがこの条件を満たさないモデルも、提示され、選択できます。Wairedが自動で
選ばないだけです。この条件から外れる主な理由は2つあります。

- **重みがGPUに収まらない。** 答えの1語ごとにシステムRAMから重みを読むことになり、
  長いコーディングのプロンプトほどその代償が大きくなります。大きいGPUが解決策です。
- **KVキャッシュが重みと同時に収まらない。** モデルは動き、答えも十分ですが、長い
  セッションを保持できません。

選ぶ画面で、Wairedはどちらに該当するかを示します。推奨モデルには*recommended*の
印が付き、動くが推奨ではないモデルには理由が付きます。

推奨モデルでも、セッションのKVキャッシュの一部をシステムRAMに置くことがあります。
その場合、`waired models ls --detail`とダウンロードの確認画面が、ダウンロードの
前にその量を示します。

```
qwen3.5-9b  ...  ✓ fits · recommended · 2.5 GB of KV cache in system RAM
```

モデルは動きます。その部分はGPUよりも遅いシステムRAMから読まれます。どれだけ
遅くなるかはマシンによるので、Wairedは速度を推測せずメモリの量を示します。
インストール後のベンチマークが実際の速度を計測し、遅すぎればより軽いモデルを
提案します。

<Aside type="note" title="計測結果が優先されます">
	このパソコンで実際にモデルを動かして遅すぎると計測された場合、そのモデルは
	推奨ではなくなり、1つ下のモデルに印が移ります。各行に計測した内容が表示され
	ます。このパソコンで動くすべてのモデルが遅すぎると計測された場合は、印は
	そのままの位置に残ります。選べる遅いモデルは、提案がないより役に立つからです。
</Aside>

メモリに収まることと速く動くことは別です。共有メモリのMacでは、大きい密な
モデルが収まっていても1秒に数語しか答えられず、同程度の大きさのMixture of
Expertsのモデルはその何倍も速く答えることがあります。Wairedは各モデルの横に
その見込みを表示し、最初のモデルをインストールしたあとに実際の速度を計測して、
より軽いモデルのほうがよければそのことを伝えます。遅いという理由でモデルが
隠されることはありません。速度が決めるのはWairedが提案するモデルであって、
選べるモデルではありません。

## <a id="the-timing-that-can-leave-local-inference-off"></a>ローカル推論をオフのままにする速度の計測

どのモデルを選んでもコーディング用のモデルを実用的に動かせないパソコンがあり、
そういうパソコンでは小さいモデルを選んでも助けになりません。GPUのないパソコンは
1つのリクエストに数分かかることがあり、いちばん小さいモデルでも、収まるいちばん
大きいモデルとほとんど同じ時間がかかります。

そこでWairedは、試して確かめます。推論エンジンのインストール直後、フルサイズの
モデルをダウンロードする前に、約1GBの小さいモデルをダウンロードし、長い質問と
十分な長さの答えという現実的なリクエストを最初から最後まで計測します。3回計測して
中央の値を採ります。1回の答えに45秒より長くかかると、Wairedは期待を裏切るものを
ダウンロードせず、ローカル推論をオフの状態で始めます。

これはターミナルとブラウザのどちらのセットアップでも行われます。計測はインストール
ごとに1回で、Wairedか推論エンジンのアップデート時にもう一度行われます。
`waired inference status`はその計測結果を表示し、それがローカル推論をオフにした
理由であればそのことを示します。

これは出発点であって、最終的な判定ではありません。

- パソコンはネットワークに加わり、自分のほかのパソコンのモデルを使えます。
- ローカル推論はいつでもオンにできます。`waired inference on`か、Wairedアプリの
  ［Run models on this computer］です。Wairedは収まるモデルをダウンロードします。
- 一度選んだあとは、Wairedはその選択を保ちます。計測は出発点を決めるために
  行われ、その選択を覆すために再び行われることはありません。

## <a id="models-that-are-never-the-automatic-choice"></a>自動では選ばれないモデル

求める人がいるためカタログに載せていても、頼まれていない人のためにWairedが
選ぶことはないモデルがいくつかあります。どのパソコンでも同じで、モデルへの
評価ではありません。

- OpenAIの**gpt-oss 20B**と**gpt-oss 120B**。Wairedがモデルを推奨するのは、同程度の
  大きさのほかのモデルではなくそれを選ぶ理由を説明できる場合だけで、これらには
  それができません。
- **Qwen3.6 27B**。Qwen3.8 27Bが同じ系統の次の世代です。古いほうは、すでに
  ダウンロード済みのパソコンがそのまま動き続けられるようカタログに残しています。

3つとも一覧に表示され、選択でき、ほかのモデルと同じようにダウンロードされて
動きます。Wairedがセットアップ中にこれらを選ぶこと、*recommended*の印を付ける
こと、切り替えの提案で名前を挙げることはありません。

## <a id="adding-hardware-never-costs-you-a-model"></a>ハードウェアの追加でモデルを失うことはありません

GPUを増設する、または大きいGPUに替えると、このパソコンに提示されるモデルと
推奨されるモデルは良くなる方向にしか変わりません。小さいGPUでも同じです。推論
エンジンにはシステムRAMのすべてが後ろに控えているので、GPUのあるパソコンが、
同じパソコンのGPUなしの場合より短いセッションや劣るモデルを割り当てられることは
ありません。

NVIDIAのGPUが2枚以上ある場合、Wairedは合算します。1枚では大きすぎるモデルでも、
2枚にまたがって収まれば適した選択になることがあります。メーカーの異なるGPUは
合算しません。

WindowsとmacOSではOllamaを使います。vLLMにはLinuxが必要なので、それらの環境では
WairedはOllamaの一覧から選びます。Linuxでも、vLLMの一覧にGPUに収まるモデルが
ない場合はOllamaの一覧から選びます。

何も変えずにルーティングの判断を確認するには、次のように実行します。

```sh
waired infer --explain "say hi"
```
