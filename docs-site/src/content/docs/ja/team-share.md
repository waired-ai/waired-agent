このページは、チームを作るときと参加するときに表示される同意メッセージの、完全な開示版です。各節で、何が起きるのか、なぜ起きるのかを説明します。

## <a id="what-team-share-is"></a>チーム共有とは

チームは、最大10人のWairedアカウントの小さなグループで、メンバーどうしでパソコンを貸し合います。チームに入っていると、パソコンの所有者がそのパソコンをチームと共有している場合に、自分のリクエストがチームメイトのパソコンで実行されることがあり、チームメイトのリクエストが自分のパソコンで実行されることもあります。

チーム共有と[パブリック共有](/ja/public-share/)は、次の3点が違います。

- **互いに知っている相手です。** チームメイトどうしは、ニックネームではなく名前で表示されます。
- **共有は必須ではありません。** 自分のパソコンを共有しなくても、チームメイトのパソコンを使えます。
- **期限がありません。** チームに入っていて、パソコンがチームと共有されている間はずっと使えます。

## <a id="what-your-teammates-can-and-cannot-see"></a>チームメイトに見えるものと見えないもの

### <a id="the-owner-could-see-what-you-send"></a>所有者は送った内容を見られます

チームメイトのパソコンの所有者は、そこに送った内容を読むことができます。リクエストはそのパソコンのメモリ内で平文のまま処理され、そのパソコンは所有者が完全に管理しています。公式アプリはプロンプトや答えをログにもディスクにも書き込みませんが、Wairedのクライアントはオープンソースで改変も可能なので、これは私たちの方針でありアプリの既定の動作であって、技術的な保証ではありません。相手を知っていてもこの事実は変わらないため、パブリック共有と同じようにここで開示しています。

### <a id="your-name-your-computers-and-sometimes-your-ip-address"></a>名前、パソコン、場合によってはIPアドレス

チームメイトには、Wairedのアカウントに表示される自分の名前、チームと共有しているパソコンの名前、そこで動いているモデルが見えます。自分のパソコンとチームメイトのパソコンが直接接続すると、互いに相手の公開IPアドレスも見えます。リレーを経由する場合、相手に見えるのはリレーのアドレスです。どちらになるかは自動で決まるので、IPアドレスは見える可能性があるものとして扱ってください。リレー経由の通信もエンドツーエンドで暗号化されていて、リレーは内容を読めません。

チームの外の人には、これらのどれも見えません。チームの名前とメンバーは、チームに入っていない人からは見えません。

### <a id="what-waired-itself-records"></a>Waired自身が記録するもの

Wairedは、共有されたパソコンごとの利用量を記録します。リクエスト数、トークン数、処理時間、使われたモデルです。何を尋ね、何を答えたかは記録しません。プロンプトと答えがWairedのサーバーに届くこともありません。チームのページに表示される利用量はパソコンごとで、メンバーごとではありません。[プライバシー：パソコンの外に出るもの](/ja/concepts/privacy/)を参照してください。

## <a id="create-or-join-a-team"></a>チームを作る、チームに参加する

チームはWebコンソールの［Team］タブで管理します。同時に入れるチームは1つです。

- **チームを作る。** 名前を付けます。作った人がオーナーになります。
- **チームに参加する。** チームメイトから届いた招待リンクを開き、求められたらサインインして、承諾します。招待リンクは7日間有効で、複数の人が使え、チームの管理者がいつでも取り消せます。

作るときも参加するときも、先に同意メッセージが表示されます。チームメイトには名前で表示されるので、どちらの前にもアカウントに名前が設定されている必要があります。［Account］のページで設定してください。

## <a id="share-a-computer-with-the-team"></a>パソコンをチームと共有する

共有はパソコンごとに、Webコンソールのパソコンのページにある［Sharing］のカードで設定します。チームに入っている間は、カードの［Your other computers］と［People outside your account］の隣に、3つ目のスイッチ［Share with team］が表示されます。どの組み合わせでもオンにできます。

- **パソコンを共有できるのは所有者だけです。** チームのほかの人が代わりにオンにすることはできません。
- **止めるとすぐに止まります。** ［Share with team］をオフにすると、そのパソコンでその時点に実行中のチームメイトのリクエストは打ち切られます。
- **［Your other computers］と連動しています。** ［Share with team］をオンにすると［Your other computers］もオンになり、［Your other computers］をオフにするとチームとの共有もオフになります。自分のほかのパソコンに貸していないパソコンは、ほかの誰にも貸さないからです。
- **パソコン自身のスイッチが優先されます。** `waired share off`、またはWairedアプリの［Stop sharing this computer］は、ほかのすべての提供と一緒にチームへの提供も止めます。

チームの管理者は、共有されたパソコンをチームのプールから外せます。外すと新しいチームのリクエストは届かなくなり、実行中のものは最後まで処理されます。所有者自身がそのパソコンを使うことには影響せず、所有者のスイッチも所有者のものです。管理者がプールから外している間はカードにそのことが表示され、プールに戻るのは管理者と所有者の両方がオンにしているときだけです。

このパソコンがチームと共有されているかどうかは、`waired share status`で確認できます。

```text
Sharing this computer: on
Your other computers: on
Your team: on
People outside your account: off
Who this computer is shared with is set in the Waired console.
```

## <a id="how-teammates-computers-are-used"></a>チームメイトのパソコンの使われ方

チームメイトが共有したパソコンは、自分のパソコンと同じように扱われます。Wairedがリクエストの処理先を選ぶとき、自分のパソコンとチームメイトのパソコンは同じ設定で一緒に検討され、どちらも公開ノードより先に選ばれます。そのパソコンに所有者が設定した内容、たとえばメインの会話とサブエージェントのどちらを受けるかは、そのまま適用されます。

自分のリクエストをチームメイトのパソコンで実行したくない場合は、［Team］タブで自分の分だけオフにできます。自分が共有しているパソコンは、そのままチームに提供されます。

## <a id="roles-and-leaving"></a>役割と退出

チームには、オーナーが1人と、任意の数の管理者とメンバーがいます。

| 操作 | オーナー | 管理者 | メンバー |
|---|---|---|---|
| 招待リンクの作成と取り消し | できる | できる | できない |
| メンバーを外す | できる | できる | できない |
| 管理者を外す、メンバーに戻す | できる | できない | できない |
| メンバーを管理者にする | できる | できる | できない |
| パソコンをチームのプールから外す | できる | できる | できない |
| チームの名前変更と削除 | できる | できない | できない |
| チームから抜ける | 先にオーナーを譲るかチームを削除する | できる | できる |

チームから抜けたり外されたりすると、自分のパソコンはチームに提供されなくなり、自分のリクエストもチームメイトのパソコンに届かなくなり、自分のパソコンのチームとの共有はオフになります。あとで再びチームに参加したときは、改めて共有を設定してください。

オーナーは、チームを持っている間はWairedのアカウントを削除できません。先にオーナーをほかのメンバーに譲るか、チームを削除してください。

## <a id="limits"></a>制限

- 1アカウントにつき1チーム。
- 1チームにつき最大10人。
- 招待リンクの有効期間は7日間。
