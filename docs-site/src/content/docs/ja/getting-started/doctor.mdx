何かおかしくて、1 つだけ試すならこれです。

```sh
waired doctor
```

セットアップの各部分を順に検査し、1 項目 1 行で表示します。そのうえで、
自動で直せるものがあれば修復を提案します。

## 出力の読み方

各行は「記号」「検査した対象」「結果」の順です。

{/* Captured verbatim from `sudo waired doctor` on a Linux apt install running
    0.0.3-edge.20260822153528+059a3ad, with all three coding tools linked and
    installed; only the user name in paths is replaced. Two ⚠ rows present on
    that host (the engine's context-window note and a mesh-peers reachability
    note naming other machines) are left out: this block shows the all-ticks
    case, and the table below explains ⚠. Re-capture, don't edit, when the
    product wording moves. */}
<Expected>
```
✓ device sign-in — valid
✓ network connection — connected
✓ waired phase — active — overlay routing in effect
✓ claude-code skill waired-status — /home/you/.claude/skills/waired-status/SKILL.md
✓ claude-code skill waired-doctor — /home/you/.claude/skills/waired-doctor/SKILL.md
✓ claude-code installation — binary=/home/you/.local/bin/claude configDir=/home/you/.claude
✓ openclaw plugin — /home/you/.openclaw/plugins/waired/index.mjs
✓ openclaw config — /home/you/.openclaw/openclaw.json
✓ openclaw installation — binary=/home/you/.local/bin/openclaw configDir=/home/you/.openclaw
✓ opencode plugin — /home/you/.config/opencode/plugin/waired.js
✓ opencode command waired-status — /home/you/.config/opencode/commands/waired-status.md
✓ opencode command waired-doctor — /home/you/.config/opencode/commands/waired-doctor.md
✓ opencode installation — binary=/home/you/.opencode/bin/opencode configDir=/home/you/.config/opencode
✓ Local Gateway — HTTP 200 at http://127.0.0.1:9473/v1/models
✓ waired-agent management — HTTP 200 at http://127.0.0.1:9476/waired/v1/status
✓ recent fallbacks — none in last 10 min
✓ claude-code statusline — installed, and this computer's shell can run it
```
すべて ✓。することはありません。
</Expected>

| 記号 | ASCII | 意味 |
|---|---|---|
| **✓** | `*` | 問題なし。 |
| **⚠** | `!` | 動いてはいるが、本来の状態ではない。急ぎではないが読む価値あり。 |
| **✗** | `x` | 壊れている。やろうとしていることが動きません。 |
| **·** | `-` | 未確認。その行に理由が出ます（多くは管理者権限が必要）。 |

**ASCII** の列は、記号をそのまま書けない場所で出る形です。UTF-8 になっていない
Windows コンソール、Windows でファイルにリダイレクトした出力、ロケールが UTF-8
でない端末が該当します。そこでは `窶ｻ` のように化けるバイトを出す代わりに ASCII を
書きます。行のそれ以外は同じです。

✓ 以外があると、終了コードが 0 以外になり件数が表示されます。スクリプトでは役に立ち、
自分で読むぶんには気にしなくて構いません。

## f を押す

自動修復できる項目があると、最後にこう聞かれます。

<Expected title="出力の末尾">
```
Press f to fix [f/N]:
```
</Expected>

**f** を押してください。何を修復するかは、検査で見つかったものによります。

- Waired を使う設定になっていないコーディングツール: コーディングツールの設定を
  再適用します（`waired link all` と同じ処理）。
- Linux デスクトップで AppIndicator 拡張が無い、または無効になっている:
  インストールして有効にします。
- 推論エンジンが起動しておらず、常駐サービスがその理由を示している:
  サービスにエンジンの起動を頼みます（`waired inference engine start` と同じ要求）。

終わると再実行を促します。コーディングツールの修復ではこう表示されます。

```
Running repair (waired link all)...
Done. Re-run `waired doctor` to verify.
```

エンジンの修復では、サービスが示した理由を表示してから起動を頼みます。

```
Starting the inference engine...
  It is not running because: no vLLM-capable model selected — set a preferred model that ships a vllm/safetensors variant (e.g. gpt-oss-20b)
  Asked. `waired inference engine status` reports when it is running.
Done. Re-run `waired doctor` to verify.
```

「Asked（頼んだ）」であって「started（起動した）」ではありません。大きなモデルの
読み込みには数分かかるため、サービスは要求を受け付け、エンジンは背後で立ち上がります。
サービスが断った場合（たとえばこのパソコンのローカル推論がオフのとき）は、
`warn: the inference engine was not started:` で始まりサービス自身の理由で終わる
警告が出て、エンジンはそのままです。

<Aside type="note" title="f が触るもの・触らないもの">
	修復が触るのは、**あなた自身の**ホームディレクトリにあるコーディングツールの設定、
	デスクトップの AppIndicator 拡張、常駐サービスが動かすエンジンだけです。
	Waired の再インストールもサインアウトもせず、モデルにも触らず、
	プロジェクト内の設定ファイルを書き換えることもありません。
</Aside>

確認なしで修復する（スクリプトや SSH 越し）:

```sh
waired doctor --fix
```

## 各検査項目の意味

| 検査項目 | 失敗した場合の意味 | 通常の対処 |
|---|---|---|
| **state directory** | 識別情報・秘密情報・記録を保持する Waired 自身のフォルダに識別情報が無い。背景のサービスはサインイン済みなので、Waired の動作中にフォルダが空にされたということ。単に**読めない**だけの場合は別の行が出て、失敗ではなく省略扱いになります。 | [サインインし直し](/ja/getting-started/first-run/)て識別情報を戻す。 |
| **device sign-in** | このパソコンのサインインが無効になっている。ローカルの AI は動き続けるが、アカウント上にこのパソコンが現れず、他の端末からも届かない。 | `waired init` → [サインインしたのに「サインインしていない」と出る](/ja/troubleshooting/#i-signed-in-but-waired-says-i-am-signed-out)を参照。 |
| **network connection** | サインインは有効だが、このパソコンがまだ接続できていない。Waired が自動で再試行し続けます。 | 1 分ほど待ってもう一度実行。 |
| **device key** | ネットワーク側がこのパソコンに対して、パソコン自身が持っているものとは別の鍵を使っている。自分のモデルは動き続けるが、他のパソコンからこのパソコンには一切届かない。それ以外はすべて正常に見えるため、この検査があります。両者が一致していれば何も出ません。 | `waired init` でこのパソコンを登録し直す。 |
| **waired-agent service** | 常駐サービスが起動しておらず、その**理由**を OS 自身のサービス記録から読み取って表示します。Windows なら「Windows のセキュリティ機能に起動をブロックされた」「起動がタイムアウトした」「予期せず停止した」など、Linux / macOS ならサービスマネージャーが記録した終了ステータスです。根拠となった記録は角かっこ内に引用されるので、自分で確認できます。 | Waired のメニューから起動するか、その行に書かれた対処に従ってください。 |
| **waired-agent management** | 常駐サービスが応答していない。これが失敗すると他もすべて動きません。 | [Waired が動いていない](/ja/troubleshooting/#a-command-says-waired-agent-is-not-running)を参照。 |
| **waired phase** | ルーティングが一時停止しているか、想定外の状態。 | `waired resume` → [しばらく使わないようにする](/ja/guides/pause/)。 |
| **Local Gateway** | サービスは動いているが、AI 応答を担う部分が動いていない。`503` はたいていモデル未読み込み。 | ダウンロード完了を待つ（`waired models ls`）か、[モデルを見直す](/ja/guides/choose-a-model/)。 |
| **コーディングツールの各行** | Claude Code / OpenCode / OpenClaw が Waired を使う設定になっていない。 | **f** を押す。 |
| **claude-code statusline** | インストール済みだが、別の OS のシェル向けに書かれている — このバージョンより前の Waired でセットアップした Windows がこれにあたる。Git Bash が入っていない限り Claude Code はこれを起動できないため、ステータス行が空のまま。AI の応答自体は続き、影響はフッターだけなので **⚠**。問題なければ表示されず、Claude Code を使っていなければ行そのものが出ない。 | `sudo waired claude enable`（Windows は管理者プロンプトから）。 |
| **&lt;ツール名&gt; installation** | ここは **·** のみです。そのツールのコマンドが `PATH` に無く、設定する対象がありません。フォルダだけあってコマンドが無い場合はその旨が出ます（残ったフォルダはインストール済みとは見なしません）。 | そのツールを入れる。使っていないなら無視して構いません。 |
| **inference engine** | 毎回表示されます。**⚠** ``paused — `waired resume` to restore overlay routing``: ルーティングが一時停止中で、エンジン自体は正常。**⚠** `not ready`、続いて常駐サービス自身の 1 行の理由、続いて `local inference is offline; mesh peers and api.anthropic.com fallback will be used`: エンジンが起動していない。起動するまでリクエストは他のパソコンかクラウドへ向かいます。**✓** で ``off on this computer — requests go to your other computers or the cloud. `waired inference on` to run models here`` と出るのは設定であって故障ではありません。このパソコンはモデルを動かさない設定になっています。 | 一時停止なら `waired resume`。ここでモデルを動かしたいなら `waired inference on`。エンジンが起動しておらず、サービスが理由を示しているときは **f** を押す（または `waired doctor --fix`）と、Waired がサービスに起動を頼みます（`waired inference engine start` と同じ要求）。自分で `waired inference engine stop` で止めた場合と、サービスがまだ起動中の場合には提案されません。外からはどちらも「起動していないが何も壊れていないエンジン」に見え、起動すれば誰かが頼んだことを取り消してしまうからです。 |

### 検査ではなくお知らせの行

Waired がこのパソコンについていま伝えることがあれば、それも上の行の間に **⚠** として
出ます。これはセットアップの検査ではなく、事実である間だけ立っているメッセージです。
伝えている内容が事実でなくなれば、次に実行したときにはその行はありません。
`waired doctor` を失敗にすることもありません。

<Expected>
```
⚠ model suggestion — Lighter model recommended — switch to qwen3-8b-instruct. This computer answers at 42 tok/s with qwen3-30b-a3b, below the 60 tok/s floor.
⚠ engine version — ollama is not running the version Waired pins. engine version 0.24.0 does not match the bundled pin 0.33.3 — run `sudo waired runtimes install ollama`
```
</Expected>

推論エンジンについては、動かしている版とモデルの調整の 2 つが同時に出ることが
あり、その場合は両方とも表示されます。上の **inference engine** の行はエンジンが
動いているかどうかを報告する行で、こちらは動いているエンジンが自分について
言うことです。

同じメッセージは Waired アプリのメニューにも出ます。`waired status` には、より良い
モデルを動かす価値が出てきたとき、新しい Waired が出たとき、エンジンが意図して
行った調整の取引のような、問題ではないものも含めてすべて出ます。
画面のないパソコンでは、この 2 つのコマンドだけが唯一の表示場所です。

### ネットワークとこのパソコンで鍵が食い違っている場合

ネットワーク内の各パソコンはそれぞれ自分の鍵を持ち、他のパソコンはその鍵を
使って相手に届きます。パソコンを登録し直したあとなどに、パソコンが実際に
持っている鍵とは別の鍵がネットワーク側に渡ると、双方向とも通信できなくなり
ます。

<Expected>
```
✗ device key — the network is using a different key for this device than the device holds — no other computer can reach it over Waired. Run `waired init` to register this device again.
```
</Expected>

このとき、他に異常は見えません。サインインは有効、アカウント上はオンライン、
自分のモデルも普通に応答し、他のパソコンからはピアデバイスとして一覧にも出ます。
互いのリクエストだけが通りません。

鍵の切り替えが進行中の場合は、代わりに **·** で表示されることがあります。
こちらは放っておけば収まります。

## 診断自体が全体を見られない場合

通常のデスクトップ用インストールでは、Waired のファイルの一部はあなたではなく
システムの所有物です。管理者権限がないと、doctor は見える範囲だけを報告し、
実行できなかった検査は行ごと省略せず **·** を付けて示します。

<Expected title="管理者権限なしで実行した場合">
```
· device sign-in — needs elevation to check; run `sudo waired doctor`
· waired phase — needs elevation to check; run `sudo waired doctor`
```
</Expected>

全員向けにインストールされたパソコンでは、識別情報そのものがシステムの所有物です。
その場合 doctor は「失われた」ではなく、どこに在るかを示します。

<Expected title="システム全体インストールを管理者権限なしで実行した場合">
```
· state directory — this device is enrolled system-wide; its state (/var/lib/waired) needs elevation to check; run `sudo waired doctor`
```
</Expected>

**·** は終了コードに影響しません。失敗ではなく、確認できていないという意味です。
確認するには、管理者権限を付けて実行し直してください。

<Tabs syncKey="os">
	<TabItem label="macOS / Linux">
		```sh
		sudo waired doctor
		```
	</TabItem>
	<TabItem label="Windows">
		**ターミナル（管理者）**から実行します（スタートボタンを右クリック →
		**ターミナル（管理者）**）。

		```powershell
		waired doctor
		```
	</TabItem>
</Tabs>

`sudo` を付けても、確認対象が管理者自身の設定に切り替わるわけではありません。
コーディングツールの設定は**あなたの**ホームフォルダにあるので、そちらが確認され、
誰の設定を見ているかが 1 行目に出ます。

<Expected title="出力の先頭">
```
Running under sudo — checking the setup for user "you", not root.
```
</Expected>

管理者権限で実行したあとに **f** を押した場合も、修復されるのは同じ設定です。
書き込まれるファイルはあなたの所有のままになります。

<Aside type="tip" title="出力を共有するとき">
	バグ報告に貼るなら、`waired status` や `waired init` には `--mask-pii` を付けると
	ホームフォルダ・ユーザー名・マシン名・アカウントのメールアドレスが伏せられます。
	`waired doctor` はファイルパスを表示するので、貼る前に目を通してください。
</Aside>
