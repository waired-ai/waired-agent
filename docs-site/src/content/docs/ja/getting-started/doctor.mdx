何かがおかしくて、1つだけ試すなら、これを実行してください。

```sh
waired doctor
```

セットアップの各項目を順に検査し、検査ごとに1行を表示します。そのあと、修復できるものが壊れていれば、修復を提案します。

## <a id="reading-the-output"></a>出力の読み方

各行は、記号、検査した項目、見つかった内容の順です。

{/* 0.0.3-edge.20260822153528+059a3ad を動かす Linux の apt インストールで、3 つの
    コーディングツールを連携・インストール済みの状態の `sudo waired doctor` から逐語で採取。パスのユーザー名だけ置換。そのホストにあった ⚠ 2 行は省いた。製品文言が変わったら編集せず採り直す。 */}
<Expected>
```
✓ device sign-in — valid
✓ network connection — connected
✓ waired phase — active — overlay routing in effect
✓ claude-code skill waired-status — /home/you/.claude/skills/waired-status/SKILL.md
✓ claude-code skill waired-doctor — /home/you/.claude/skills/waired-doctor/SKILL.md
✓ claude-code installation — binary=/home/you/.local/bin/claude configDir=/home/you/.claude
✓ openclaw plugin — /home/you/.openclaw/plugins/waired/index.mjs
✓ openclaw config — /home/you/.openclaw/openclaw.json
✓ openclaw installation — binary=/home/you/.local/bin/openclaw configDir=/home/you/.openclaw
✓ opencode plugin — /home/you/.config/opencode/plugin/waired.js
✓ opencode command waired-status — /home/you/.config/opencode/commands/waired-status.md
✓ opencode command waired-doctor — /home/you/.config/opencode/commands/waired-doctor.md
✓ opencode installation — binary=/home/you/.opencode/bin/opencode configDir=/home/you/.config/opencode
✓ Local Gateway — HTTP 200 at http://127.0.0.1:9473/v1/models
✓ waired-agent management — HTTP 200 at http://127.0.0.1:9476/waired/v1/status
✓ recent fallbacks — none in last 10 min
✓ claude-code statusline — installed, and this computer's shell can run it
```
すべて✓です。することはありません。
</Expected>

| 記号 | 代替表記 | 意味 |
|---|---|---|
| **✓** | `*` | 正常です。 |
| **⚠** | `!` | 動いていますが、本来の動きではありません。読む価値はありますが急ぎではありません。 |
| **✗** | `x` | 壊れています。やろうとしていることのどれかが動きません。 |
| **·** | `-` | 検査していません。理由が行に書かれ、多くは管理者権限が必要なためです。 |

**代替表記**の列は、記号を書けない環境での表示です。UTF-8でないWindowsのコンソール、Windowsでファイルにリダイレクトした出力、ロケールがUTF-8でないターミナルです。行のほかの部分は同じです。

✓でないものが1つでもあると、コマンドは0以外の終了コードと件数で終わります。スクリプトでは便利で、自分で読むときは気にしなくて構いません。

## <a id="pressing-f"></a>fキーを押す

自動で修復できるものがあると、次のように聞かれます。

<Expected title="出力の末尾">
```
Press f to fix [f/N]:
```
</Expected>

`f`キーを押します。何を修復するかは、検査で見つかったものによります。

- Wairedを使う設定になっていないコーディングツール：コーディングツールの設定を適用し直します。`waired link all`と同じ処理です。
- Linuxのデスクトップで、AppIndicator拡張機能がないか無効になっている場合：インストールして有効にします。
- バックグラウンドサービスが理由を報告している、動いていない推論エンジン：サービスに推論エンジンの起動を依頼します。`waired inference engine start`と同じ依頼です。

そのあと、検査をもう一度実行するよう表示されます。コーディングツールの修復では次のように表示されます。

```
Running repair (waired link all)...
Done. Re-run `waired doctor` to verify.
```

推論エンジンの修復では、サービスの理由を表示してから起動を引き渡します。

```
Starting the inference engine...
  It is not running because: no vLLM-capable model selected — set a preferred model that ships a vllm/safetensors variant (e.g. gpt-oss-20b)
  Asked. `waired inference engine status` reports when it is running.
Done. Re-run `waired doctor` to verify.
```

「started」ではなく「Asked」です。大きいモデルの読み込みには数分かかるので、サービスは依頼を受け付け、推論エンジンはバックグラウンドで立ち上がります。このパソコンでローカル推論がオフになっているなどの理由でサービスが断ると、修復は`warn: the inference engine was not started:`で始まりサービス自身の理由で終わる警告を表示します。

<Aside type="note" title="fが触るものと触らないもの">
	修復が触るのは、ホームディレクトリにある自分のコーディングツールの設定、デスクトップのAppIndicator拡張機能、バックグラウンドサービスが動かす推論エンジンです。それ以外には触れません。Wairedの再インストール、サインアウト、モデルの変更は行わず、プロジェクトの中の設定ファイルを編集することもありません。
</Aside>

スクリプトやSSH経由で、確認なしに修復するには次のように実行します。

```sh
waired doctor --fix
```

## <a id="what-each-check-means"></a>各検査項目の意味

| 検査項目 | 失敗の意味 | 通常の対処 |
|---|---|---|
| **state directory** | バックグラウンドサービスはサインインしているのに、識別情報、秘密情報、記録を置くWairedのフォルダに識別情報がありません。Wairedの動作中にフォルダが空にされています。このアカウントで読めないフォルダは別の行で、失敗ではなく検査の省略です。 | [サインインし直して](/ja/getting-started/sign-in/#sign-in-again)識別情報を戻します。 |
| **device sign-in** | このパソコンのサインインが無効になっています。モデルはローカルで動き続けますが、パソコンはアカウントから消え、ほかのパソコンから届かなくなります。 | `waired init`。[サインインしたのに、Wairedはサインアウトしていると言う](/ja/troubleshooting/install-and-sign-in/#i-signed-in-but-waired-says-i-am-signed-out)を参照してください。 |
| **network connection** | サインインはできていますが、このパソコンがまだ接続していません。Wairedは自動で再試行を続けます。 | 1分待ってからもう一度実行します。 |
| **device key** | ネットワークが持つこのパソコンの鍵と、パソコン自身が持つ鍵が違います。自分のモデルは動き続けますが、ほかのパソコンからこのパソコンに届きません。一致していれば表示されません。 | `waired init`でパソコンを登録し直します。 |
| **waired-agent service** | バックグラウンドサービスが動いておらず、OSのサービス記録から読んだ理由がこの行に表示されます。 | Wairedのメニューから始めるか、行の提案に従います。 |
| **waired-agent management** | バックグラウンドサービスが応答していません。ほかのすべてが動かなくなる原因です。 | [コマンドが「waired-agent is not running」と言う](/ja/troubleshooting/no-answer/#a-command-says-waired-agent-is-not-running)を参照してください。 |
| **waired phase** | ルーティングが一時停止しているか、想定外の状態です。 | `waired resume`。[Wairedを一時停止する](/ja/guides/pause/)を参照してください。 |
| **Local Gateway** | サービスは動いていますが、リクエストに答える部分が動いていません。`503`は多くの場合、モデルがまだ読み込まれていないことを意味します。 | ダウンロードの完了を待つ（`waired models ls`）か、[モデルを確認](/ja/guides/choose-a-model/)します。 |
| **coding-agent entries** | Claude Code、OpenCode、OpenClawがWairedを使う設定になっていません。 | `f`キーを押します。 |
| **claude-code statusline** | インストールされていますが、別のOSのシェル向けの形になっています。古いWairedで設定したWindowsのパソコンで起きます。ステータス行は空白のままです。モデルは答え続けます。正常なら表示されず、Claude Codeを使っていなければ行自体がありません。 | `sudo waired claude enable`（Windowsでは管理者のターミナルで）。 |
| **&lt;tool&gt; installation** | ここは**·**だけです。ツールのコマンドが`PATH`にないので、設定するものがありません。フォルダが残っているだけではインストールとみなしません。 | ツールをインストールするか、使っていなければ無視します。 |
| **inference engine** | 毎回表示されます。**⚠**の``paused — `waired resume` to restore overlay routing``は、ルーティングが一時停止していて推論エンジン自体は正常であることを意味します。**⚠**の`not ready`にサービス自身の理由が続く場合は、推論エンジンが動いていません。**✓**の``off on this computer — requests go to your other computers or the cloud. `waired inference on` to run models here``は設定であって、不具合ではありません。 | 一時停止なら`waired resume`。ここでモデルを動かすなら`waired inference on`。推論エンジンが動いておらずサービスが理由を報告している場合は、`f`キーを押します。自分で推論エンジンを止めた場合と、サービスの起動中は、この提案は表示されません。 |

### <a id="rows-that-are-notices-not-checks"></a>検査ではなくお知らせの行

Wairedは、このパソコンについて伝えたいことも、上の行の中に**⚠**として表示します。これらはセットアップの検査ではありません。事実である間だけ表示されるメッセージで、`waired doctor`が失敗を報告する原因にはなりません。

<Expected>
```
⚠ model suggestion — Lighter model recommended — switch to qwen3-8b-instruct. This computer answers at 42 tok/s with qwen3-30b-a3b, below the 60 tok/s floor.
⚠ engine version — ollama is not running the version Waired pins. engine version 0.24.0 does not match the bundled pin 0.33.3 — run `sudo waired runtimes install ollama`
```
</Expected>

同じメッセージはWairedアプリと`waired status`にも表示されます。すべてのお知らせは[お知らせ](/ja/guides/notices/)を参照してください。

### <a id="when-your-network-and-this-computer-disagree-on-its-key"></a>ネットワークとこのパソコンで鍵が食い違っている場合

ネットワークの各パソコンは自分の鍵を持ち、ほかのパソコンはその鍵でそのパソコンに届きます。パソコンを登録し直したあとなどに、ネットワークが持つ鍵とパソコンが持つ鍵が違うと、双方向とも通信できなくなります。

<Expected>
```
✗ device key — the network is using a different key for this device than the device holds — no other computer can reach it over Waired. Run `waired init` to register this device again.
```
</Expected>

この状態でも、ほかはすべて正常に見えます。パソコンはサインイン済みで、アカウントではオンラインと表示され、自分のモデルは答えます。パソコンどうしのリクエストだけが失敗します。鍵の変更がまだ終わっていない間は、代わりに**·**と表示されることがあります。それは自然に解消します。

## <a id="when-the-check-itself-cannot-see-everything"></a>診断自体が全体を見られない場合

通常のデスクトップのインストールでは、Wairedのファイルの一部はシステムのものです。管理者権限がないと、診断は見られる範囲を報告し、実行できなかった検査に**·**を付けます。

<Expected title="管理者権限なし">
```
· device sign-in — needs elevation to check; run `sudo waired doctor`
· waired phase — needs elevation to check; run `sudo waired doctor`
```
</Expected>

全員向けにWairedをインストールしたパソコンでは、識別情報自体がシステムのもので、診断はその場所を示します。

<Expected title="システム全体へのインストール、管理者権限なし">
```
· state directory — this device is enrolled system-wide; its state (/var/lib/waired) needs elevation to check; run `sudo waired doctor`
```
</Expected>

**·**は終了コードに数えられません。すべてを検査するには、管理者権限で実行します。

<Tabs syncKey="shell">
	<TabItem label="macOS / Linux">
		```sh
		sudo waired doctor
		```
	</TabItem>
	<TabItem label="Windows">
		［ターミナル（管理者）］で実行します。

		```powershell
		waired doctor
		```
	</TabItem>
</Tabs>

`sudo`で実行しても、検査の対象が管理者自身の設定に切り替わることはありません。コーディングツールは自分のホームフォルダに設定されているので、それが検査され、最初の行に誰の設定かが表示されます。

<Expected title="出力の先頭">
```
Running under sudo — checking the setup for user "you", not root.
```
</Expected>

管理者権限で実行したあとに`f`キーを押すと、同じ設定を自分として修復します。

<Aside type="tip" title="出力を共有するとき">
	`waired doctor`はファイルのパスを表示するので、不具合報告に貼り付ける前に読み返してください。`waired logs --mask-pii`は、集めたログファイルの中のホームフォルダ、ユーザー名、マシン名、アカウントのメールアドレスを伏せます。
</Aside>
