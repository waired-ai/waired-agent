調子がおかしいときは、まず [`waired doctor`](/ja/getting-started/doctor/) を
実行してください。多くはこれで直ります。このページはその次 — ほかの人が原因を
突き止められるだけの材料を集める話です。

<Aside type="tip" title="再現する「前」に詳細ログを有効にします">
	Waired は普段、重要な出来事だけを記録します。不具合の原因を説明する細かい記録は、
	**先に**頼まないと残りません。問題が起きた「後」で有効にしても、肝心の部分だけが
	抜けたログが手に入ります。
</Aside>

## 診断情報を集める

<Steps>

1. **詳細ログを有効にします。** バックグラウンドサービスと Waired アプリの両方に
   即座に効きます。再起動は不要です。

   ```sh
   waired config log-level debug
   ```

2. **問題を再現します。** うまくいかなかった操作を、同じようにもう一度行います。

3. **ログを 1 つのファイルにまとめます。**

   ```sh
   waired logs --mask-pii --since 30m -o report.txt
   ```

   `--since` はどこまで遡るかです。しばらく前に起きた問題なら広げてください。
   既定は 1 時間です。

   Windows では**管理者権限の** PowerShell から実行してください。サービス自身の
   ログも推論エンジンのログも `C:\ProgramData\waired` 配下にあり、そこは権限が
   絞られています。権限がないとどちらもファイルに入らず、問題を説明する部分が
   欠けた報告になります。

4. **詳細ログを戻します。** ログが際限なく大きくならないようにするためです。

   ```sh
   waired config log-level info
   ```

   詳細ログが ON の間は保存量も増え、ファイル 1 つあたり 128 MB（通常は 32 MB）に
   なります。数日後に気づいた問題でも記録が残っています。OFF に戻すと元のサイズに
   戻ります。

</Steps>

`report.txt` にはバックグラウンドサービスのログと推論エンジンのログが
まとめて入ります。添付するのはこのファイルです。

## `--mask-pii` が伏せるもの、伏せないもの

伏せるのは 4 つです。**ホームフォルダ**、**ユーザー名**、**パソコンの名前**、
そしてサインインに使った**メールアドレス**。

ベストエフォートであり、保証ではありません。あなたにとって個人的でありうる
すべてのパスや名前を知っているわけではありません — ディスクの別の場所にある
プロジェクトフォルダ、自分で設定したホスト名、入力した URL などです。
このオプションを使ったかどうかにかかわらず、**添付する前にファイルを読んで
ください**。

<Aside type="note" title="どのコマンドでも使えます">
	`waired logs --mask-pii` はそのコマンドだけをマスクします。インストーラや
	サインインを含めてすべてをマスクするには、環境変数 `WAIRED_PII_MASK=1` を
	設定します。[高度なインストールオプション](/ja/reference/install-options/)を
	参照してください。
</Aside>

## インストール中に問題が起きた場合

上の手順は Waired がすでに入っていることが前提です。インストール中に失敗する
場合は、最初から詳細ログを出すようインストーラに指示します。

<Tabs syncKey="os">
	<TabItem label="Linux / macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --log-level debug --mask-pii
		```
	</TabItem>
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_LOG_LEVEL = 'debug'
		$env:WAIRED_PII_MASK = '1'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```

		ワンライナー形式はオプションを渡せないので、環境変数で指定します。
		管理者権限のステップを含め、インストーラが実行するすべてに届きます。
	</TabItem>
</Tabs>

Windows ではインストーラ自身の記録が実行ごとに 1 ファイルずつ
`%TEMP%\waired-install-<日付>-<時刻>-<ID>.log` に残ります。管理者ウィンドウは
終了と同時に閉じるため、失敗の内容がこのファイルにしか残らないことがよく
あります。こちらも添付してください。インストーラは開始前と、問題が起きた
ときに、このパスを表示します。最新のものを自分で探すには次のようにします。

```powershell
Get-ChildItem $env:TEMP\waired-install-*.log | Sort-Object LastWriteTime | Select-Object -Last 1
```

直近 5 件が保持されるため、やり直しても実際に失敗した回のログが上書きされる
ことはなくなりました。

## まっさらな状態からやり直す

特定の症状というより全体がおかしい場合は、原因を追うより、消して入れ直す方が
早いことがあります。

<Aside type="danger" title="消えるものがあります">
	クリーンインストールは、設定・鍵・ローカルの状態・ダウンロード済みの AI
	モデルを完全に削除します。あとでサインインし直し、モデルも再ダウンロードに
	なります。実行前に確認を求められます。
</Aside>

<Tabs syncKey="os">
	<TabItem label="Linux / macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --clean
		```
	</TabItem>
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_CLEAN = '1'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```
	</TabItem>
</Tabs>

入れ直さずに消すだけの方法を含む詳細は
[アンインストール](/ja/getting-started/uninstall/#start-over-on-the-same-computer)に
あります（英語の id は、言語間でアンカーを揃えるために置かれているものです）。

## テストビルドを試すよう頼まれた場合

方法は 2 つあり、組み合わせられます。

- **`--edge` / `WAIRED_VERSION=edge`** — main ブランチの最新ビルドで、変更のたびに
  作り直されます。リリース版ではありません →
  [Waired を更新する](/ja/getting-started/update/#リリースチャンネル)
- **`--dev` / `-Dev`** — 通常のサービスではなく、Waired 自身の開発用サービスに
  接続します。Waired の開発者向けです。この方法で登録した端末は、通常の
  アカウントには表示されません。

<Tabs syncKey="os">
	<TabItem label="Linux / macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --edge --dev --log-level debug
		```
	</TabItem>
	<TabItem label="Windows">
		```powershell
		# -Dev はワンライナーでは渡せないので、先にスクリプトを保存します。
		$env:WAIRED_VERSION = 'edge'
		$env:WAIRED_LOG_LEVEL = 'debug'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 -OutFile $env:TEMP\install.ps1
		& $env:TEMP\install.ps1 -Dev
		```
	</TabItem>
</Tabs>

選んだサービスはインストーラが記憶します（どの OS でも同じです）。あとから
このパソコンで `waired init` をやり直しても同じサービスにサインインするので、
`--dev` や `--control` を付け直す必要はありません。

通常のインストールに戻すには、上のクリーンインストールを行ってください
（`--stable` だけではビルドが変わるだけで、登録先のサービスは変わりません）。

## 添付するもの

| | |
|---|---|
| `report.txt` | 冒頭の 4 ステップで作ったもの |
| `waired version --json` | 正確なビルド |
| `waired doctor` の出力 | 修復された場合でも、何が見つかったか |
| Windows のインストール失敗時 | 最新の `%TEMP%\waired-install-*.log` |
| 期待した動作 | と、実際に起きたこと |

報告先は
[github.com/waired-ai/waired-agent/issues](https://github.com/waired-ai/waired-agent/issues)
です。
