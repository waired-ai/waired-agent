何かがおかしいときは、まず[`waired doctor`](/ja/getting-started/doctor/)を実行して
ください。大半の問題はそれで直ります。このページは、そのあとの手順です。何が
起きたかをほかの人が突き止められる証拠を集めます。

<Aside type="caution" title="再現する前に詳細なログをオンにしてください">
	Wairedは通常、重要な出来事だけをログに記録します。不具合の説明になる詳細は、
	先に求めておかないと記録されません。問題が起きたあとにオンにしても、必要な
	部分だけが抜けたログになります。
</Aside>

## <a id="collect-the-diagnostics"></a>診断情報を集める

<Steps>

1. **詳細なログをオンにします。** バックグラウンドサービスとWairedアプリの両方に、
   再起動なしですぐに反映されます。

   ```sh
   waired config log-level debug
   ```

2. **問題を再現します。** うまくいかなかった操作を、同じように行います。

3. **ログを1つのファイルに集めます。**

   ```sh
   waired logs --mask-pii --since 30m -o report.txt
   ```

   `--since`はどこまでさかのぼるかです。問題がしばらく前に起きた場合は広げます。
   既定は1時間です。

   Windowsでは、管理者のPowerShellから実行します。サービス自身のログと推論
   エンジンのログは、アクセスが制限された`C:\ProgramData\waired`にあります。
   管理者権限がないと、これらはファイルに含まれません。

4. **詳細なログをオフに戻します。** ログを小さく保つためです。

   ```sh
   waired config log-level info
   ```

   詳細なログがオンの間、Wairedはログを多く保持します。ログファイル1つあたり
   32MBではなく128MBなので、数日後に気づいた問題もファイルに残っています。

</Steps>

`report.txt`には、バックグラウンドサービスのログと推論エンジンのログがまとめて
入ります。添付するのはこの1ファイルです。

## <a id="what---mask-pii-does"></a>--mask-piiが行うこと

4つのものをプレースホルダーに置き換えます。ホームフォルダ、ユーザー名、パソコンの
名前、サインインに使ったメールアドレスです。

これは最善の努力であって、保証ではありません。ディスク上の別の場所にある
プロジェクトのフォルダ、自分で設定したホスト名、入力したURLなど、個人に関わる
すべてのパスや名前を知っているわけではありません。このオプションを使ったか
どうかにかかわらず、添付する前にファイルを読んでください。

<Aside type="note" title="どのコマンドでも使えます">
	`waired logs --mask-pii`は、そのコマンド1つを対象にします。インストーラと
	サインインを含むすべてを対象にするには、代わりに環境変数`WAIRED_PII_MASK=1`を
	設定します。[高度なインストールオプション](/ja/reference/install-options/)を
	参照してください。
</Aside>

## <a id="when-the-problem-happens-during-install"></a>インストール中に問題が起きた場合

上の手順は、Wairedがインストール済みであることが前提です。インストール中に失敗
する場合は、インストーラに最初から詳細なログを出させます。

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_LOG_LEVEL = 'debug'
		$env:WAIRED_PII_MASK = '1'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```

		1行の形ではオプションを渡せないので、環境変数で設定します。環境変数は
		インストーラと、管理者の手順を含むインストーラが実行するすべてに届きます。
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --log-level debug --mask-pii
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --log-level debug --mask-pii
		```
	</TabItem>
</Tabs>

Windowsでは、インストーラは実行ごとに1ファイルの記録を
`%TEMP%\waired-install-<date>-<time>-<id>.log`にも書きます。管理者のウィンドウは
終了時に閉じるので、失敗の記録が残るのはこのファイルだけであることがよくあります。
これも添付してください。インストーラは開始前と、何かが失敗したときに、正確な
パスを表示します。最新のものを探すには次のように実行します。

```powershell
Get-ChildItem $env:TEMP\waired-install-*.log | Sort-Object LastWriteTime | Select-Object -Last 1
```

直近の5つが残るので、2回目の試行が失敗した試行のログを上書きすることは
ありません。

## <a id="start-over-from-a-clean-slate"></a>まっさらな状態からやり直す

特定の1か所が壊れているのではなく、セットアップ全体が混乱しているように見える
場合は、原因を調べるより、初期化と再インストールを一度に行うほうが早いことが
よくあります。

<Aside type="danger" title="削除されるものがあります">
	クリーンインストールは、設定、鍵、ローカルの状態、ダウンロードしたモデルを
	完全に削除します。そのあとサインインし直し、モデルもダウンロードし直します。
	実行前に確認されます。
</Aside>

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_CLEAN = '1'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --clean
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --clean
		```
	</TabItem>
</Tabs>

再インストールせずに初期化する方法を含む詳細は、
[Wairedをアンインストールする](/ja/getting-started/uninstall/#start-over-on-the-same-computer)を
参照してください。

## <a id="if-you-were-asked-to-try-a-test-build"></a>テストビルドを試すよう頼まれた場合

2つのオプションがあり、組み合わせて使えます。

- `--edge`または`WAIRED_VERSION=edge`：mainブランチの最新ビルドで、変更のたびに
  ビルドされます。リリースではありません。
  [リリースチャンネル](/ja/getting-started/update/#release-channels)を参照して
  ください。
- `--dev`または`-Dev`：通常のサービスではなく、Waired自身の開発用サービスに接続
  します。Wairedそのものを開発する人のためのものです。この方法で登録した
  デバイスは、通常のアカウントには表示されません。

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		# 先にスクリプトを保存する。1行の形では -Dev を渡せない。
		$env:WAIRED_VERSION = 'edge'
		$env:WAIRED_LOG_LEVEL = 'debug'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 -OutFile $env:TEMP\install.ps1
		& $env:TEMP\install.ps1 -Dev
		```
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --edge --dev --log-level debug
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | sh -s -- --edge --dev --log-level debug
		```
	</TabItem>
</Tabs>

インストーラは選んだサービスを記憶するので、あとで`waired init`を実行しても同じ
サービスにサインインし直します。通常のインストールに戻すには、上のクリーン
インストールを行います。`--stable`だけではビルドが変わるだけで、登録先のサービスは
変わりません。

## <a id="what-to-attach"></a>添付するもの

| | |
|---|---|
| `report.txt` | 冒頭の4つの手順で作ったもの |
| `waired version --json` | 正確なビルド |
| `waired doctor`の出力 | 修復された場合も含め、見つかった内容 |
| Windowsでのインストールの失敗 | 最新の`%TEMP%\waired-install-*.log` |
| 期待した動作 | そして実際に起きたこと |

Windowsでコマンドがまったく起動しない場合、同じビルド番号はファイルにあります。
`C:\Program Files\Waired\waired.exe`を右クリックして［プロパティ］を選択し、
［詳細］タブの［ファイル バージョン］を読みます。

報告は[github.com/waired-ai/waired-agent/issues](https://github.com/waired-ai/waired-agent/issues)に
提出してください。
