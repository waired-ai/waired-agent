Windows 11 と Windows Server 2025（64 ビット）に対応します。インストールはコマンド 1 つです。
ダブルクリックで進める[セットアッププログラム](#セットアッププログラムでインストールする)もあります。

## インストール

<Steps>

1. **管理者として PowerShell を開きます。** スタートボタンを右クリックし、
	**「ターミナル（管理者）」**を選び、確認画面で**「はい」**を押します。

	<Aside type="note" title="なぜ管理者権限が必要？">
		Waired は、誰もログインしていなくても電源投入時から動く常駐サービスを登録します。
		パソコン全体に対する変更なので、Windows が確認を求めます。
	</Aside>

2. 次の行を貼り付けて Enter を押します。

	```powershell
	iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
	```

	<Aside type="tip" title="このコマンドが何をするか">
		`iwr` が Waired のインストールスクリプトをダウンロードし、`iex` がそれを実行します。
		先に中身を読みたい場合は[下記](#実行する前にスクリプトを読む)を参照してください。
	</Aside>

3. 実行内容が表示され、`Proceed? [Y/n]` と確認されます。Enter を押します。

	初回の対話インストールでは、インストール先を変更するか聞かれます。
	Enter を押せば `C:\Program Files\Waired` になります。

</Steps>

次は[サインインとセットアップ](/ja/getting-started/first-run/)です。

<a id="read-the-script-before-running-it"></a>

## 実行する前にスクリプトを読む

もっともな話です。ダウンロードして読んでから実行できます。

```powershell
iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 -OutFile $env:TEMP\install.ps1
notepad $env:TEMP\install.ps1
& $env:TEMP\install.ps1
```

オプションを渡したい場合もこの形式にします（1 行版ではオプションを渡せません）。

<Aside type="note" title="無人インストール">
	`-Yes` で確認を省略、`-InstallDir <パス>`（または環境変数 `WAIRED_INSTALL_DIR`）で
	インストール先を固定できます。一覧は
	[高度なインストールオプション](/ja/reference/install-options/)にあります。
</Aside>

## セットアッププログラムでインストールする

貼り付けるよりクリックしたい場合は、
[リリースページ](https://github.com/waired-ai/waired-agent/releases/latest)に
セットアッププログラム `WairedSetup-<version>-x64.exe` もあります。ファイル名に
バージョンが入るため、`latest/download/…` の固定 URL はありません。リリースページから
ダウンロードします。

初回の実行では、まず**「Windows によって PC が保護されました」**と表示されます。
セットアッププログラムはまだ Windows が認識する証明書で署名されていないためです。
**「詳細情報」→「実行」**で先へ進めます。上の PowerShell の 1 行ではこの画面は
出ません。このページが 1 行のほうを先に載せているのはそのためです。続いて管理者権限の
確認画面が出ます。理由は上と同じで、常駐サービスの登録はパソコン全体に対する変更だからです。

ウィザードは短いものです。インストール先は聞かれず、常に `C:\Program Files\Waired`
です（別の場所にしたい場合は PowerShell インストーラの `-InstallDir` を使います）。
選択肢は 1 つだけ、**Claude Code integration:** の下のチェックボックスで、既定でオンです。
オンのままにすると、Claude Code のマシン全体の設定ファイル（managed settings）を書いて、
Claude Code を Waired に向けます。オフにすると Claude Code は api.anthropic.com と
話し続けます。あとから管理者ターミナルで `waired claude enable` を実行すれば有効に
できます。

完了した時点で Waired はインストールされ、常駐サービスも動いていますが、まだサインイン
していません。セットアッププログラムは `waired init` を実行しないためです。最後のページの
**Launch Waired now (recommended -- registers per-user autostart)** をオンのままにすると
Waired アプリが起動し、以後サインイン時にも自動で起動します。そのまま
[サインインとセットアップ](/ja/getting-started/first-run/)に進んでください。
スタートメニューには **Waired**（アプリ）と **Waired (CLI)** の 2 つが追加されます。

セットアップは毎回ログを書きます。場所は `%TEMP%\Setup Log*.txt`、または `/LOG=<file>`
で指定したファイルです。不具合を報告するときに添付するのはこのファイルです。

新しいバージョンのセットアッププログラムを既存のインストールの上で実行すると、その場で
アップグレードされます。先にアンインストールする必要はありません。アンインストールは
**設定 → アプリ → インストールされているアプリ → Waired → アンインストール**です。
対話的なアンインストールでは `%ProgramData%\waired`（この端末の識別情報、秘密情報、
キャッシュされた状態）を削除するか聞かれます。既定の答えは「いいえ」で、残しておけば
入れ直したときに同じデバイス鍵が使われます。サイレントアンインストールでは常に残ります。

無人で配布する場合:

```powershell
.\WairedSetup-<version>-x64.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /LOG=$env:TEMP\waired-setup.log
```

Claude Code に触れたくない場合は `/MERGETASKS=!claudeproxy` を足します。終了コード 0 は
インストール完了です。終了コード 7 は、セットアッププログラムが実行を見送り、何も
インストールしなかったことを意味します。下の
[Windows がプログラムの実行を拒否したとき](#windows-がプログラムの実行を拒否したとき)で
説明している状況です。

## 推論エンジンを入れない

モデルを動かすプログラム（[Ollama](https://ollama.com)）は、セットアップ時に、
モデルを動かすパソコンにだけ導入されます。まったく入れたくない場合
（ヘッドレス、ディスク容量が少ないなど）:

```powershell
$env:WAIRED_NO_OLLAMA = '1'
iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
```

あとから管理者プロンプトで `waired runtimes install ollama` を実行すれば追加できます。

## Windows がプログラムの実行を拒否したとき

Waired のプログラムはまだ Windows が認識する証明書で署名されていないため、
Smart App Control（または別のアプリケーション制御ポリシー）が実行を拒否することが
あります。そのため、上の PowerShell の 1 行も、ダウンロードして実行するセットアップ
プログラム（[リリースページ](https://github.com/waired-ai/waired-agent/releases/latest)の
`WairedSetup-<version>-x64.exe`）も、まず一時フォルダからプログラムを実行してみて、
Windows が拒否した場合はそこで止まります。止まるのは、何かをインストール・停止・
置き換えする前です。

```
[waired] Checking the new programs run on this computer before replacing anything
[waired] Windows will not run the new waired-agent.exe on this computer:
[waired]   An Application Control policy has blocked this file
```

セットアッププログラムは同じ内容を **Preparing to Install** ページとログに出し、
最後に `Nothing has been installed, removed or replaced.` と言います。結果はそれだけ
です。中途半端に入ったものはなく、Claude Code が Waired に向けられることもありません。
ここで止まったインストールは、このパソコンを元のままにして終わります。

拒否はファイル単位で、しかも勝手に変わります。朝に拒否されたファイルが、
このパソコン側は何も変わっていないのに午後には動くことがあります。あとで
もう一度試すのは現実的な選択肢です。インストールを止めるのは 2 つのプログラム
だけです: `waired.exe`（`waired` コマンド）と `waired-agent.exe`（常駐サービス）。
拒否されたのが Waired アプリ（`waired-tray.exe`）だけの場合、セットアップは警告を
出して続行します。常駐サービスと `waired` コマンドには影響しません。

[アップデート](/ja/getting-started/update/#アップデートが最後まで進まなかったとき)も、
いまのバージョンを置き換える前に同じチェックをします。

### インストール後に起きた場合

同じ判定が、それまで動いていたファイルに対して覆ることもあります。それが
`waired.exe` だった場合、`waired` コマンドが起動しなくなり、あなたの代わりに
それを実行しているものも同時に止まります。Claude Code のステータスラインの
Waired の欄が空になり、Waired のフックが何もしなくなるのはそのためです。
Windows 自身の通知が毎回出ることもあります。

Waired アプリは別のファイルで判定も別なので、拒否されている間も動き続け、
このことを知らせます。

> Windows is refusing to run waired.exe on this computer. That is why the
> waired command and Claude Code's Waired status line do nothing. Nothing here
> is broken and there is nothing to repair — Windows does not trust the file
> today, and often does tomorrow. Run `waired doctor` for the details.

変更すべき設定はありません。Windows が再びこのファイルを受け入れれば、すべて
自動的に元に戻ります。入れ直す必要はありません。`waired doctor` は実行できる
ときには **Windows Application Control** としてこれを報告します — ただし
`waired.exe` が拒否されている当のファイルである場合、実行できるのは拒否が
解けたあとです。

## インストールされるもの

| | |
|---|---|
| プログラム | `C:\Program Files\Waired`（変更可） |
| 常駐サービス | `waired-agent`（起動時から動作） |
| 設定と状態 | `%ProgramData%\waired`（秘密情報は管理者のみアクセス可） |
| 推論エンジンとモデル | `%ProgramData%\waired` の中（モデルを動かすパソコンのみ） |
| スタートメニュー | **Waired**（日常操作に使うアイコン）と **Waired (CLI)** |

Waired は推論エンジンを自分の設定と同じ場所に持ちます。システムの `Path` には何も
追加せず、推論エンジン向けのシステム全体の設定も変更しません。この PC にすでに Ollama が
入っている場合、Waired はそれに触れず、使いもしません。
