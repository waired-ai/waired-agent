手軽な順に3つの確認方法があります。どれかが失敗したら、次に`waired doctor`を
実行してください。セットアップの各項目を検査し、直せるものを修復します。

## <a id="1-look-at-the-waired-icon"></a>1. Wairedアイコンを見る

**Wairedアイコン**を選択します。macOSではメニューバー、WindowsとLinuxでは時計の
となりにあります。

<Screenshot
	src="app-ready.png"

/>

正常なメニューでは、最上部に「Connected」、その下に自分のアカウントのアドレス、
モデルを動かすパソコンでは「Engine: ready」とモデル名が表示されます。

## <a id="2-ask-it-something"></a>2. 質問してみる

```sh
waired infer "say hi"
```

数秒であいさつが返ってきます。

このリクエストはこのパソコンのモデルに送られるので、ネットワーク上のほかの
パソコンに届かなくても動きます。モデル自体が動いていることを確かめる最短の
方法です。

答えがどこから来たか、なぜそう選ばれたかを見るには、`--explain`を付けます。

```sh
waired infer --explain "say hi"
```

## <a id="3-read-the-full-status"></a>3. 詳細なステータスを読む

```sh
waired status --observability
```

モデルを動かすパソコンでの正常な出力は次のようになります。

```
Observability:
  Device:   my-desktop  uptime: 1m23s
  Engine:   ready (model=qwen3.8-27b, 0/4 slots used, inflight=0)
  Share:    enabled   Paused: no
  Mesh:     2 enrolled / 1 reachable / 1 ready
  Last:     (no inference yet)
```

| 行 | 確認すること |
|---|---|
| **Engine** | `ready`なら、モデルが読み込まれていて応答できます。`not ready`は多くの場合ダウンロード中です。[応答が返らない](/ja/troubleshooting/no-answer/)を参照してください。 |
| **Share** | `enabled`なら、自分のほかのパソコンがこのパソコンのモデルを使えます。`disabled`の原因は2つあります。このパソコンで共有をオフにしているか、Webコンソールがこのパソコンをネットワークから外しているかです。どちらかは`waired share status`で分かります。 |
| **Paused** | `no`ならWairedはリクエストを処理しています。`yes`なら`waired resume`を実行します。 |
| **Mesh** | 自分のパソコン全体の`enrolled / reachable / ready`です。ノートパソコンでは、モデルを動かしているパソコンが起動していることをこの行で確認します。 |
| **Last** | インストール直後は空です。リクエストを送ると、そのリクエストの要約が表示されます。`ttft`は最初の単語が出るまでの待ち時間、`latency`は答え全体にかかった時間です。同じセッションで続けて質問すると、モデルが読み込み済みの内容を再利用するため、`ttft`は大きく下がるのが普通です。 |

`-o json`を付けると、機械で読める形式で出力されます。

<Aside type="tip" title="モデルを動かさないノートパソコンの場合">
	そのパソコンで`Engine: not ready`と出るのは正常です。モデルを持たない役割だから
	です。大事なのは**Mesh**の行に`1 ready`以上と出ることで、自分のほかのパソコンの
	どれかが答えられる状態にあることを意味します。
</Aside>
