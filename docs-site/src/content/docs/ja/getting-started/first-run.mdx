**通常のインストールでは、これは自動的に行われます。**インストールコマンドが Waired を起動し、
そのままサインインへ進むので、初回セットアップは[クイックスタート](/ja/quickstart/)で完結し、
`waired init` を自分で打つ機会はありません。

このページは、自分で打つ必要がある場合のためのものです。

- セットアップが中断され、再開したい
- `--no-init` を付けてインストールした
- 画面のないサーバーを設定している
- それぞれの選択が実際に何を決めているのか知りたい

<Aside type="tip" title="同じアカウント = 同じネットワーク">
	**すべての**パソコンで**同じ Google アカウント**を使ってください。この共通の
	サインインが、あるマシンから別のマシンの AI を使えるようにしています。
	アカウントが違うと、互いにつながらない別々のネットワークになります。
</Aside>

## 開始する

<Tabs syncKey="os">
	<TabItem label="Windows">
		**ターミナル（管理者）**を開き（スタートボタンを右クリック）、次を実行します。

		```powershell
		waired init
		```

		<Aside type="note" title="「waired は認識されません」と出る場合">
			インストーラは Waired をシステムのパスに追加しますが、インストール**前**に
			開いていたターミナルは古いパスのままです。**新しい**管理者ターミナルを
			開いてください。開きたくない場合はフルパスで実行します:
			`& "C:\Program Files\Waired\waired.exe" init`
			（インストール先を変更した場合はそのフォルダに読み替えてください）
		</Aside>
	</TabItem>
	<TabItem label="macOS">
		```sh
		sudo waired init
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		sudo waired init
		```
	</TabItem>
</Tabs>

サインイン用のリンクを表示して待ちます。

<Expected>
```
Sign in using this link:
  https://app.waired.ai/login/…

>> Press Enter to open your browser (or open the link above yourself)...
```
</Expected>

**Enter** を押して Google アカウントを選びます。リンクを任意のブラウザに
コピーしても構いません（このパソコンでも、別のパソコンでも）。ターミナルは
このキー入力を待って止まることはなく、サインインが済み次第そのまま進みます。

<Aside type="caution" title="セットアップが終わるまでウィンドウを閉じないでください">
	AI ソフトウェアのインストールには管理者権限が必要で、Web ページからは取得できません。
	**このコマンドが、その作業を実際に行っています**（ブラウザ側の画面は指示を出す役です）。

	閉じてしまうと、ブラウザに *「The setup command on … was closed before this finished.
	Your progress was saved.」*と表示されます。同じコマンドを実行し直せば続きから進みます。
	失われるものはなく、モデルのダウンロードはそのまま続いています。

	実行し直してもサインインからやり直しにはなりません。*「Already signed in as
	you@example.com — resuming setup」*と表示され、中断した続きから進みます。
	あらためてサインインし直したい場合は `waired init --force-reauth` です。Waired が
	自分からサインインし直すのは、既存のサインインが修復不能なほど期限切れのときだけです。
</Aside>

## ブラウザで終える

サインインすると、ブラウザはこのパソコンのセットアップ画面に着きます。
モデルを選んで **Yes, set it up** を押すと、そのパソコンの状況がリアルタイムで表示されます。

<Screenshot
	src="setup-wizard-progress.png"
	alt="ブラウザに表示された Waired のセットアップ画面。3 つのステップ — AI ソフトウェアのインストール（完了）、AI モデルのダウンロード（進行中、19.2 GB 中 7.9 GB のバー）、速度の確認（待機中）。"
	caption="各ステップは、パソコン自身が報告しています。このタブを閉じても止まりません。"
/>

| ステップ | 何をしているか | 所要時間 |
|---|---|---|
| **AI ソフトウェアのダウンロード** | モデルを読み込んで動かすプログラムの取得。標準のものは 1.5 GB ほど、高性能版は 4 GB ほどあります。どこまで進んだか・どれくらいの速度かが、ターミナルと同じ数字でページにも出ます。 | 数分 |
| **AI ソフトウェアのインストール** | 取得したものの展開と設定。管理者権限が必要なのはここで、だからターミナルを開いたままにする必要があります。 | 1〜2 分（高性能版は最大 15 分） |
| **コーディングツールの接続** | チェックしたコーディングツールの送信先を Waired に向けます。これも管理者権限の要る作業なのでターミナルが担当します。長いダウンロードの後ではなく前に済ませるので、あとから待たされることはありません。 | 数秒 |
| **AI モデルのダウンロード** | AI 本体。数 GB あります。 | 5〜30 分 |
| **速度の確認** | このマシンが実用的な速度を出せるかの短い計測。 | 最大 5 分 |

ダウンロードのステップは、ダウンロードするものがあるときだけ出ます。すでに
AI ソフトウェアが入っているパソコンでは、次のステップから始まります。
コーディングツールのステップは、画面でそれを尋ねられたときだけ出ます。

<Expected>
	すべてのステップにチェックが付き、
	**「Everything's ready — this computer can now run AI on its own.」**と表示されます。
	**Go to device** を押します。
</Expected>

ブラウザが主導している間、ターミナルは何も聞いてきません。開いたままにするよう
促し、そしてセットアップ画面でどのコーディングツールをつなぐか選ばれていれば、
それを書き込むのはこのウィンドウです（Web ページには無い管理者権限が要るため）。

```
Keep this terminal window open until setup finishes — it does the parts the
browser can't.
🔌 Setting up your coding tools (claude-code, openclaw)…
```

ここで **Claude Code** にチェックを入れると、画面の説明どおりのことが起きます。
このコンピュータを使う全員に対して、Claude Code の送信先が Waired に変わります。
もう 1 つのツールは自分のホームフォルダにファイルを置くだけです。これはブラウザを
使わないインストールでターミナルが尋ねるルーティングと同じもので、決める場所が
ブラウザに変わっただけです。インストール時の `--skip-claude-proxy` は引き続き
こちらより優先されます。

まだ選択を聞かない古いセットアップ画面では、代わりに自分で設定する方法が
表示されます — *「You can set up your coding tools later from this terminal with
`waired link all`.」*

これが起きるのはモデルのダウンロードの**前**です。これは意図的で、このパソコンで
管理者権限が要るのはここが最後だからです。1 時間かかることもあるダウンロードの
後ろに置くと、戻ってきたときにセットアップが自分を待っていた、という状態になって
いました。そのため、ダウンロードが始まる時点でターミナルの担当分は終わっており、
*「Setup is continuing in your browser — nothing more is needed from this
terminal」* と表示されます。そこから先は閉じてかまいません。モデルのダウンロードと
速度チェックにターミナルは不要で、コーディングツールの接続はウィンドウを開いて
いてもいなくても保たれます。

開いたままにすると、ダウンロードの進捗が表示され続けます。開けておく理由は
それだけです。

<Aside type="note" title="セットアップ画面は英語のみです">
	Web コンソールは現在英語のみです。翻訳は予定されています。
</Aside>

## ターミナルで進める

*「Setup is continuing in your browser…」*の表示で **Enter** を押します。
すぐには切り替わりません。まず、切り替えると何が起きるかを示して確認されます。

<Expected title="聞かれること">
```
   Taking over means this terminal drives setup and the browser page stops.
   Any model download keeps running either way.
   Take over setup in this terminal? [y/N] (default: No)
```

**y** と答えると切り替わります。もう一度 Enter を押した場合は *No* と答えたことに
なるため、意図しないキー入力でセットアップがブラウザから移ってしまうことはありません。
気が変わればあとからでも切り替えられます。
</Expected>

この申し出は、ブラウザで **Yes, set it up** を押した時点で閉じます。そこから先は
このウィンドウがインストールを実行しており、ターミナルもそう表示します。

<Expected>
```
Setup has started in your browser — this window now runs the installation.
```

Enter は応答しますが、もう切り替えは行いません。

```
Setup is running in your browser and this window is doing the installation.
To abandon it, press Ctrl-C and run the setup command again.
```

中止すれば進行中の作業は失われます。だからこそキー 1 つではなく、明示的な
Ctrl-C が必要です。おかしくなったのがブラウザのタブのほうなら、これは不要です —
そのパソコンのページを開き直して **Resume setup** を選んでください。
</Expected>

そのあと何を聞かれるかは、どういう状態で動いているかによります。

### 通常のインストール後

コーディングツールについてだけ聞かれます。モデルはブラウザ側、
またはインストーラ側ですでに決まっているためです。質問はどちらも
モデルのダウンロードが**終わってから**なので、転送が中断されることはありません。

<Expected title="聞かれること">
	コーディングエージェント連携を設定するかどうか、続けて Claude Code を
	Waired 経由にするかどうか。どちらも **Y** と答えます。

	経由設定にいいえと答えても連携自体はインストールされ、無効なだけです。
	あとから `sudo waired claude enable` で有効にできます。
</Expected>

### <a id="no-desktop-no-browser"></a>サーバー、またはブラウザがない場合

`--no-browser`、`--non-interactive`、あるいは引き継ぎ先のサービスに到達できない環境では、
`waired init` がすべてを自分で行い、質問も一通り聞いてきます。

<Steps>

1. **Google サインイン。**リンクとペアリングコードだけが表示されるので、
	別の端末で開きます。ターミナルには *「Nothing to press here」*（ここで押す
	キーはありません）と表示されます。サインインは自動で検知されます。

2. **Run AI models on this computer? `[Y/n]`** — デスクトップや GPU マシンなら **Y**。
	ほかのパソコンの AI を*使うだけ*のマシンなら **N**（それでもネットワークには参加します）。
	既定値はこのマシンのメモリ量と、Waired が計測した速さに従います。

3. **Let your other devices use this computer's AI? `[Y/n]`** — ノートパソコンに
	提供するためのマシンなら **Y**。前の回答とは独立した設定です。

4. **Route Claude Code through Waired? `[Y/n]`**

5. **Run a quick performance benchmark now? `[Y/n]`** — モデルの準備ができてから
	聞かれます。実施を推奨します。このパソコンの速度が足りない場合、
	軽いモデルを提案し、両方の品質スコアを並べて示すので判断できます。

</Steps>

### <a id="servers-and-containers-auth-keys"></a>サーバーとコンテナ: 認証キー

通常のサインインには人とブラウザが必要です。サーバーが何十台もある場合や、
自力で起動しなければならないコンテナイメージでは、そのどちらもありません。
**認証キー**がその代わりになります。サインイン済みの状態で管理コンソールから
一度作成しておけば、各マシンはサインインの代わりにそれを提示します。

**設定 → 認証キー** で作成し、マシン側では次を実行します。

```sh
sudo waired init --auth-key waired_ak_...
```

一度だけ使うキーなら **1 台のみ**、複数のサーバーやコンテナイメージで共有する
なら **複数台可** を選びます。有効期限は最長 90 日で、いつでも失効させられます。
失効させると**新しいマシンが参加できなくなるだけ**で、すでに参加済みの
マシンはサインインしたままです。

<Aside type="caution" title="コマンドラインのキーは他のユーザーからも見えます">
	コマンドラインに書いたものは、そのマシンの全ユーザーの `ps` に表示され、
	シェルの履歴にも残ります。共有マシンではキーをファイルに置き、
	そのパスを指定してください。

	```sh
	sudo waired init --auth-key file:/etc/waired/authkey
	```

	コンテナでは環境変数 `WAIRED_AUTH_KEY` に設定すればフラグ自体が不要です
	（`waired init` がそこから読みます）。
</Aside>

Waired がインストール済みで、バックグラウンドサービスが動いている必要があります。
認証キーは資格情報であって、サービスを省略する手段ではありません。サービスが
応答しない場合、`waired init` はその旨を伝えて停止します（中途半端に参加させません）。

この方法で参加させたマシンは、すぐにネットワークに加わりコンソールにも現れますが、
ブラウザのセットアップ画面は開きません（ブラウザが無いためです）。AI モデルの選択を
含め、それ以外はすべてコンソールから操作できます。

<Aside type="note" title="無人インストールは確認なしで Claude Code をルーティングします">
	ルーティングの質問に答える人がターミナルにいないため、無人インストールでは
	対話インストールの既定と同じ「はい」が採用されます。そのマシンの Claude Code は
	**それを使う全員に対して** Waired を向くようになります（ユーザーごとではなく
	マシン全体の設定です）。

	Claude Code を Anthropic API のままにしたい場合は、`--skip-claude-proxy`
	（Windows は `-SkipClaudeProxy`、環境変数なら `WAIRED_NO_CLAUDE_PROXY=1`）を
	付けてインストールしてください。ネットワークへの参加、モデル、スキルや
	プラグインなど、それ以外はこれまでどおり実行されます。あとから
	`sudo waired claude enable` で有効化、`sudo waired claude disable` で
	無効化できます。
</Aside>

そのあとモデルが進捗表示付きでダウンロードされます。

```
Starting the AI engine…
Preparing to download qwen3-coder-30b-a3b-instruct…
Downloading qwen3-coder-30b-a3b-instruct: 41%  7.9 GB / 19.2 GB (44 MB/s)
```

ここに表示されるモデル名は**あなたが選んだモデル**です。ブラウザで
セットアップを進めている場合は、そこで選んだモデルが表示されます。
コンピューターが自動で選んだであろうモデルではありません。

<Aside type="note" title="ダウンロードが終わらないうちは">
	ファイルは数十 GB あるため、回線が遅い環境では時間がかかります。
	そのあとどうなるかは、どちらが主導しているかで変わります。

	- **この経路**（`--no-browser` / `--non-interactive`、またはブラウザに
		到達できない場合）では、10 分ほどでシェルに戻り、ダウンロードは
		バックグラウンドで続く旨が表示されます。
	- **このターミナルが主導している場合**（自分で切り替えた場合、または
		ブラウザで結局セットアップが始まらなかった場合）は、<kbd>Enter</kbd> を
		押せばいつでも見張りをやめられます。*「Continuing in the background —
		the agent finishes the download on its own」*と表示され、残りの
		セットアップに進みます。
	- **ブラウザが主導している場合**は、**選んだモデルの**ダウンロードが
		終わるまでターミナルが進捗表示のまま残ります。ターミナル側とブラウザ側で
		「終わったかどうか」の認識がずれないようにするためです。この場合
		<kbd>Enter</kbd> では抜けられません。インストールを実行しているのが
		このウィンドウだからです。

	いずれの場合も、ダウンロードを行っているのはバックグラウンドサービスであって
	このコマンドではありません。<kbd>Ctrl</kbd>+<kbd>C</kbd> を押しても
	**中止されません**。状況は `waired status` でいつでも確認できます。
</Aside>

<Aside type="caution" title="「Waired hasn't started downloading …」と表示されたら">
	ブラウザで選んだモデルは要求されているものの、ダウンロードがまだ
	始まっていない状態です。多くの場合、このバージョンではそのモデルを
	このコンピューターで動かせないことが原因です。ターミナルは待ち続けずに
	シェルを返し、バックグラウンドサービスが試行を続けます。

	各モデルの状態は `waired models ls` で確認できます。状況が変わらない
	場合は `waired doctor` を実行してください。
</Aside>

```
╭─ 🎉 Waired is ready — everything completed successfully! ─────────╮
│  Account   you@example.com                                       │
│  Device    my-desktop  d-4f2a…                                   │

```
</Expected>

<Expected tone="bad">
```
!  The AI engine could not be installed on this device.
   no space left on device

   Sign-in worked — this device is signed in and running. Only local AI is missing.
   Retry the install with: sudo waired init
```

AI ソフトウェアをインストールできませんでした。多くはディスク容量不足、
ネットワーク不通、または管理者権限なしで実行した場合です。サインイン自体は
成功しているので、このパソコンはネットワークに参加していて、ほかのマシンの AI を
すでに使えます。表示された原因を解消してから、同じコマンドを実行し直してください。
来ないエンジンを待ち続けることはせず、ここでセットアップは止まります。
</Expected>

<Aside type="caution" title="「非常に小さいモデルしか動かせません」と出たら">
	メモリの少ないパソコンでは、ごく小さいモデルしか収まらないため
	**動かさないこと**を勧められる場合があります。その助言に従ってください。
	そのサイズのコーディングモデルは、役に立つ出力より壊れた出力のほうが多くなります。
	そのパソコンをセットアップする価値はあります — ほかのマシンの AI を使えるからです。
</Aside>

<details>
<summary>サーバー・スクリプト向けのオプション</summary>

| フラグ | 効果 |
|---|---|
| `--no-browser` | ブラウザを開かず、URL とペアリングコードを表示する |
| `--non-interactive` | ハードウェアから導かれた既定値を採用し、何も聞かない |
| `--inference-bundled-model-id <id>` | 自動選択ではなくモデルを指定する |
| `--inference-enabled=true\|false` | 1 つめの質問に、聞かれずに答える |
| `--share-with-mesh=true\|false` | 2 つめの質問に、聞かれずに答える |
| `--control <url>` | 既定以外のサービスを指定する |
| `--mask-pii` | 出力中のホームディレクトリ・ユーザー名・ホスト名・メールアドレスを伏せる（バグ報告用） |

</details>

## Waired アプリからサインインする場合

[Waired アプリ](/ja/guides/waired-app/)には **Sign in…** があり、
このパソコンをサインインさせることはできます。

<Aside type="caution" title="ただし初回セットアップは完結しません">
	AI ソフトウェアのインストールに必要な管理者権限を、アプリ側から取得できないためです。
	未セットアップのパソコンでアプリからサインインすると、セットアップ画面までは進み、
	結局ターミナルで `waired init` を実行するよう促されます。

	**Sign in…** はサインアウト後の再サインインや、すでにセットアップ済みのパソコンで使ってください。
	初回は上記のコマンドを使います。
</Aside>

## もう一度実行する場合

すでにサインイン済みのパソコンでセットアップをやり直しても安全です。
