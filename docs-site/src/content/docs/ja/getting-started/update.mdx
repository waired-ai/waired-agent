更新があることは Waired が知らせますが、**適用するかどうかは常にあなたが決めます**。
勝手に更新されることはありません。

## いま更新する

**Waired アイコン**（macOS はメニューバー、Windows・Linux は時計のとなり）をクリックし、
**「⬆ Update available — install …」**の項目を選びます。

ターミナルからでも同じです:

```sh
waired update
```

確認し、見つかった内容を表示し、適用前に聞いてきます。

| コマンド | 動作 |
|---|---|
| `waired update` | 確認して、新しければ適用 |
| `waired update --check` | 確認のみ（何も変更しない） |
| `waired update --yes` | 確認なしで適用（スクリプトやサーバー向け） |
| `waired update --force` | キャッシュされた答えを使わず、取得元に聞き直す |

## 「最新」はいつ時点のものか（Linux）

Linux では、このパソコンが以前ダウンロードしたパッケージインデックスを読んで確認します。
そのため `waired update --check` は、それがいつのものかを表示します。

```
Package index:   refreshed 3 hours ago
```

インデックスが 1 日より古くなると、その旨も併せて表示します。このパソコンがまだ知らない
新しいビルドが、すでに公開されている可能性があるからです。`--force` を付けると先に
インデックスを更新します。更新には root が必要なので sudo を求めます。

```sh
waired update --check --force
```

macOS と Windows はリリースフィードに直接問い合わせるため、答えは常に最新です。
`--force` はキャッシュされた答えを飛ばすだけです。

## 更新で保持されるもの

大事なものはすべて保持されます。サインインしたまま、このパソコンの識別情報も
ネットワーク上の位置もそのままで、設定も残ります。**セットアップをやり直す必要はありません。**

ダウンロード済みのモデルには触りません。推論エンジンには触ります。このパソコンに
すでにエンジンが入っている場合、アップデートはそれを、その版の Waired が使う
バージョンに揃えます。Waired はそのバージョンしか使わないためです。エンジンが
入っていないパソコンに、アップデートがエンジンを入れることはありません。
エンジンが入るのは、ローカル推論を有効にしたときです。

サインイン時に Waired アプリが起動するかどうかも変更しません。このパソコンに
サインインしている人の分が未設定だった場合は、それを伝えるだけにします。
戻したいときは Waired を一度開いて **Start Waired on login** にチェックを
入れてください。

Waired アプリ自体は、開いていた場合、アップデートの中でいったん閉じられ、
開き直されます。更新後に見えているのは新しいバージョンです。開いていなかった
場合はそのままです — アップデートが、閉じてあったアプリを開くことはありません。

## アップデートが最後まで進まなかったとき

失敗した場合、今まで使っていたバージョンがそのまま動き続けます。Waired は
すべてのファイルをダウンロードして検証してから、1 つずつ置き換えます。
そのため途中で失敗しても「中途半端に入った状態」にはならず、「アップデートが
行われなかった」だけです。もう一度実行してください。

何も変わらなかったアップデートは、そう報告します。最後の行に出るのは、実行後に
このパソコンから読み直した実際のバージョンです（取りに行こうとしたバージョンでは
ありません）。したがって `updated 0.0.3 -> 0.0.4` と出れば移動は起きており、移動
できなかった場合は矢印の両側に同じバージョンを並べる代わりに、その事実が出ます。

Windows では、アップデートが止まる理由がもう 1 つあります。止まるのは、
何かに触る前です。Waired のプログラムはまだ Windows が認識する証明書で
署名されていないため、Smart App Control（または別のアプリケーション制御
ポリシー）が実行を拒否することがあります。そのためアップデートは、何かを
止めたり置き換えたりする前に、まず新しいプログラムを実行してみます。
Windows が拒否した場合はそこで終わりです。今まで使っていたバージョンが
入ったままで、常駐サービスも止まっていません。

```
[waired] Checking the new programs run on this computer before replacing anything
[waired] Windows will not run the new waired.exe on this computer:
[waired]   An Application Control policy has blocked this file
```

拒否はファイル単位で、しかも勝手に変わります。朝に拒否されたファイルが、
このパソコン側は何も変わっていないのに午後には動くことがあります。あとで
もう一度試しても、いまのビルドのまま使い続けても構いません。判定はこの
チェックからサービスが起動するまでの間にも変わりうるので、ファイルを
置き換えたあとで失敗した場合は、以前のプログラムを元に戻してサービスを
再起動します。新規インストールも同じで、動かせないプログラムを残すのでは
なく、そこで止まります。拒否されたのが Waired アプリだけの場合、セットアップは
警告を出して続行します。常駐サービスと `waired` コマンドには影響しません。

<Aside type="note" title="Windows に残るファイル">
	Windows は実行中のプログラムを置き換えられないため、Waired が自分自身を
	アップデートするときは古い方を別名に変えます。`C:\Program Files\Waired` に
	`waired.exe.displaced-3eb6caa1` のようなファイルが見えることがあります。
	これは以前のバージョンで、起動中のものを閉じて開き直せば使われていない状態に
	なり、次のアップデートで削除されます。自分で削除しても構いません。
</Aside>

## リリースチャンネル

| チャンネル | 対象 |
|---|---|
| **stable**（既定） | 全員。リリース済みバージョンのみ。 |
| **edge** | 未リリースの変更を試す人向け。マージのたびに再ビルドされ、**本番利用は非推奨**。 |

`waired update` は、そのパソコンが今いるチャンネルを維持します。stable のマシンが
黙って edge に移ることも、その逆もありません。

切り替えるには:

```sh
waired update --edge     # edge へ / edge のまま
waired update --stable   # stable に戻す
```

apt のソース（Linux）または取得するファイル（macOS / Windows）が入れ替わり、
どちらの方向にも切り替えられます。

<details>
<summary>最初から edge を入れる</summary>

<Tabs syncKey="os">
	<TabItem label="macOS / Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | WAIRED_VERSION=edge sh
		```
	</TabItem>
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_VERSION = 'edge'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```
	</TabItem>
</Tabs>

一度 edge にすると、`waired update` はそのまま edge を追い続けます。

</details>

	常駐サービスが数時間おきに確認し、更新があると知らせます。通知を止めたい場合は
	Waired アイコンの **Settings** サブメニューから設定できます。
</Aside>
