Wairedは、更新があるとそのことを伝えます。適用するのは常に自分の操作です。バックグラウンドで勝手に更新されることはありません。

## <a id="update-now"></a>いま更新する

**Wairedアイコン**を選択し、表示されている［Update available — install …］の項目を選択します。アプリは閉じて更新され、再び開きます。

ターミナルからは次のように実行します。

```sh
waired update
```

このコマンドは、更新を確認して見つかった内容を表示し、適用する前に確認します。

| コマンド | 動作 |
|---|---|
| `waired update` | 確認して、新しいバージョンがあれば適用する |
| `waired update --check` | 報告だけで何も変えない |
| `waired update --yes` | 確認せずに適用する。スクリプトやサーバー向け |
| `waired update --force` | キャッシュした結果を使わず、リリース元に問い合わせ直す |

## <a id="how-current-the-check-is-on-linux"></a>Linuxでの確認結果の新しさ

Linuxでは、このパソコンが以前にダウンロードしたパッケージ索引を読んで確認します。そのため、`waired update --check`はそれがいつのものかを表示します。

```
Package index:   refreshed 3 hours ago
```

索引が1日より古いと、その旨が表示されます。このパソコンがまだ知らない新しいビルドが公開されている可能性があるためです。`--force`を付けると、先に索引を更新します。root権限が必要なので、sudoのパスワードを求められます。

```sh
waired update --check --force
```

macOSとWindowsはリリース元に直接問い合わせるので、結果は常に最新です。そこでの`--force`は、キャッシュした結果を使わないだけです。

## <a id="what-an-update-keeps"></a>アップデートで保持されるもの

サインインは保持され、このパソコンの識別情報とネットワーク上の位置、設定もそのままです。セットアップをやり直す必要はありません。

ダウンロード済みのモデルには触れません。推論エンジンは対象です。このパソコンに推論エンジンがあれば、アップデートはそれを、このビルドのWairedが使うバージョンにそろえます。Wairedが使うのはそのバージョンだけだからです。推論エンジンのないパソコンに、アップデートが推論エンジンを入れることはありません。ローカル推論をオンにしたときにインストールされます。

ログイン時にWairedアプリを起動するかどうかは変わりません。ログインしている人に対してアプリが起動する設定になっていないと、アップデートはそのことを表示して、そのままにします。戻したい場合は、Wairedを一度開いて［Start Waired on login］を有効にします。

Wairedアプリが開いていた場合は、アップデートの一環として閉じて開き直されるので、そのあとに見えるのは新しいバージョンです。開いていなかった場合は閉じたままです。

## <a id="if-an-update-does-not-finish"></a>アップデートが最後まで進まなかったとき

失敗したアップデートは、それまでのバージョンを動いたまま残します。Wairedは、すべてのファイルをダウンロードして検証したあとで初めて新しいファイルを置くので、途中の失敗は「アップデートが行われなかった」状態であり、中途半端にインストールされた状態にはなりません。もう一度実行してください。

何も変わらなかったアップデートは、そのことを表示します。最後の行には、実行が終わった時点でインストールされているバージョンが、パソコンから読み戻して表示されます。`updated 0.0.3 -> 0.0.4`は移行できたことを示します。移行できなかったアップデートは、代わりにそのことを報告します。

Windowsでは、アップデートが止まる理由がもう1つあり、何かに触れる前に止まります。Wairedのプログラムは、Windowsが認識する証明書でまだ署名されていません。そのため、Smart App Controlなどのアプリケーション制御ポリシーが実行を拒否することがあります。アップデートは、何かを停止または置換する前に新しいプログラムを先に実行します。Windowsがそのどれかを拒否すると、アップデートはそこで終わります。それまでのバージョンはインストールされたままで、バックグラウンドサービスは一度も止まりません。

```
[waired] Checking the new programs run on this computer before replacing anything
[waired] Windows will not run the new waired.exe on this computer:
[waired]   An Application Control policy has blocked this file
```

拒否はファイルごとに判定され、時間がたつと変わります。朝に拒否されたファイルが、パソコンに何も変更を加えていなくても午後には実行できることがあるため、あとでもう一度試す価値があります。いまのビルドを使い続けることもできます。ファイルの置換後に失敗した場合は、以前のプログラムを戻してサービスを再起動します。Wairedアプリだけが拒否された場合は、警告を表示してアップデートを続けます。詳しくは[Windowsがプログラムの実行を拒否したとき](/ja/getting-started/install/windows/#if-windows-refuses-to-run-a-program)を参照してください。

<Aside type="note" title="Windowsに残るファイル">
	Windowsは実行中のプログラムの置換を許可しないため、アップデートは古いコピーの名前を変えて残します。`C:\Program Files\Waired`に`waired.exe.displaced-3eb6caa1`のようなファイルが見えることがあります。これは以前のバージョンです。次のアップデートが削除しますし、自分で削除しても構いません。
</Aside>

## <a id="release-channels"></a>リリースチャンネル

| チャンネル | 対象 |
|---|---|
| **stable**（既定） | 全員。番号付きのリリースを順に追います。Wairedがプレリリースの間は、リリース候補版がこれにあたります。 |
| **edge** | 未リリースの変更を試す人向け。マージのたびにビルドされます。日常の利用には向きません。 |

`waired update`は、このパソコンをいまのチャンネルにとどめます。stableのインストールがアップデートでedgeに移ることはなく、その逆もありません。

切り替えるには次のように実行します。

```sh
waired update --edge     # edgeに移る、またはedgeにとどまる
waired update --stable   # stableに戻す
```

切り替えると、Linuxではaptのソースが、macOSとWindowsではアップデートが取得するダウンロード先が入れ替わります。どちらの向きにも切り替えられます。

<details>
<summary>最初からedgeでインストールする</summary>

<Tabs syncKey="os">
	<TabItem label="Windows">
		```powershell
		$env:WAIRED_VERSION = 'edge'
		iwr -useb https://github.com/waired-ai/waired-agent/releases/latest/download/install.ps1 | iex
		```
	</TabItem>
	<TabItem label="macOS">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | WAIRED_VERSION=edge sh
		```
	</TabItem>
	<TabItem label="Linux">
		```sh
		curl -fsSL https://github.com/waired-ai/waired-agent/releases/latest/download/install.sh \
		  | WAIRED_VERSION=edge sh
		```
	</TabItem>
</Tabs>

edgeにした後は、`waired update`もedgeのままです。

</details>

<Aside type="note" title="更新のお知らせ">
	バックグラウンドサービスは数時間ごとに確認し、更新があるとWairedアプリにお知らせを表示します。お知らせを止めるには、アプリの［Settings］サブメニューで［Notify me about updates］のチェックを外すか、`waired update --notify off`を実行します。
</Aside>
