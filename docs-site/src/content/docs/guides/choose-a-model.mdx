Waired picks a model for this computer during setup: the best one it can
serve a full coding session on. Other models still fit and stay selectable.
This page explains how to see what is running and how to switch.

## Whether to change it

| If you want | Do this |
|---|---|
| Better answers, and you have memory to spare | Switch up to a larger model |
| Faster answers, or the computer feels slow | Switch down to a smaller model |
| To know what is running right now | See [Which model is running](#which-model-is-running) |
| To run models here at all, when this computer does not | See [If no model was picked](#if-no-model-was-picked) |
| Nothing in particular | Leave it. The automatic pick is a good default |

<Aside type="caution" title="Larger is not always better">
	A model that does not fit in memory does not run slower. It fails to load,
	and this computer stops answering. Check the memory column for the model in
	the [model catalog](/reference/model-catalog/) before switching up.
</Aside>

Some models come in more than one size. **Qwen3.8 27B** and **Qwen3.6 35B-A3B**
each ship a smaller [variant](/reference/glossary/#quantization), the same
model with its weights stored more compactly at some cost in precision. A
computer with a 16 GB GPU, or a Mac with 24 GB of memory, now runs Qwen3.6
35B-A3B where it used to be offered Qwen3.5 9B, and a 12 GB GPU runs Qwen3.8
27B. You do not choose between the variants. Waired prefers the fuller one
wherever it fits and takes the smaller one only when the fuller one would not
stay in memory. Nothing changes on a computer that could already hold the
full-size one.

## If no model was picked

On some computers Waired picks no model and starts with local inference off.
The reason is speed: before downloading a full-size model, Waired times a
realistic request on a small one. If one answer would take longer than 45
seconds, it stops there rather than downloading a model you would wait minutes
on. See [How Waired chooses a model](/guides/how-a-model-is-chosen/).

The computer still joins your network and can use the models on your other
computers. To turn local inference on anyway, run `waired inference on`, or
select **Run models on this computer** in the Waired app. Waired keeps that
choice once you have made it.

```sh
waired inference status   # on or off, and why if Waired decided it
```

## Which model is running

Select the **Waired icon**, then **Inference**. The active model is listed
there. From a terminal:

```sh
waired models ls              # what is downloaded, and what is active
waired models ls --detail     # every model, what it needs, and what fits this computer
```

## Reading the list

Every model in the list shows the memory it needs and its size, `small`,
`medium`, or `large`, which is the class of GPU that runs it. Larger models
generally give better answers and need more computer.

- **The memory figure** is what the model takes to serve a full coding
  session: its weights, the engine's own overhead, and the KV cache. System
  RAM and VRAM count together.
- **VRAM counts as what is free, not what the GPU has.** A GPU that is also
  driving your display, or that another program is using, has less to lend.
  On a busy GPU, Waired recommends a smaller model than the GPU's headline
  size suggests. Closing whatever else is using the GPU and restarting Waired
  lets it see the memory again.
- The model Waired would choose is marked **recommended**. A model that runs
  here but is not that one is marked with the reason, and stays selectable.
- A model that has been timed as too slow on this computer stops being the
  recommended one. The rows say what they measured.
- On an NVIDIA computer running vLLM, a model whose weights fit can still
  leave too little room for a long conversation. Those rows say so.
- A model this computer cannot run is shown with what it would need. Picking
  it asks first, with the shortfall, and **Cancel** is the default answer.

## Switch models

<Tabs syncKey="mode">
	<TabItem label="In the Waired app">
		<Steps>

		1. Select the **Waired icon**.
		2. Open **Models**.
		3. Select a model from the list.

		</Steps>

		The change applies live. The engine reloads in a few seconds and keeps
		serving. If the model has not been downloaded yet, the download starts,
		the icon shows the progress, and the old model keeps answering until the
		new one is ready.
	</TabItem>
	<TabItem label="In the terminal">
		```sh
		waired models use <model-id>
		```

		Model IDs are the values in the ID column of the
		[model catalog](/reference/model-catalog/), for example `qwen3.8-27b`.
		The download, if one is needed, runs in the background. `waired status`
		shows its progress.

		To let Waired measure this computer and suggest a switch instead:

		```sh
		waired runtimes benchmark
		```

		The benchmark measures how fast this computer is with its current model.
		If a different model would suit it better, Waired names both models and
		offers the swap. Accept, and the download runs with a progress bar.
		Press Enter at any time to let it finish in the background. Once the new
		model is serving, Waired measures again and reports that figure.

		If you are already on the smallest model Waired offers and it is still
		too slow, Waired says so and asks whether to keep local inference on at
		all. Answering `n` turns it off, and the computer keeps working as a
		gateway to your other computers.

		Waired then offers to remove the model you moved off, since its files
		are several gigabytes. Keeping them is a fine answer if you expect to
		move back up later.
	</TabItem>
	<TabItem label="On a server with no desktop">
		`waired models use <model-id>` works over SSH like anywhere else. You can
		also set the model in the config file and restart the background
		service:

		<Tabs syncKey="os">
			<TabItem label="Linux">
				Edit `/etc/waired/agent.json`, set `inference.bundled_model_id` to
				the model ID, then run:

				```sh
				sudo systemctl restart waired-agent
				```
			</TabItem>
			<TabItem label="Windows">
				Edit `%PROGRAMDATA%\waired\agent.json` the same way, then run:

				```powershell
				Restart-Service waired-agent
				```
			</TabItem>
		</Tabs>

		The environment variable `WAIRED_INFERENCE_BUNDLED_MODEL_ID` and the
		`--inference-bundled-model-id` flag set the same thing and override the
		config file, in that order. See
		[Advanced install options](/reference/install-options/).
	</TabItem>
</Tabs>

## Confirm the switch

```sh
waired status --observability
```

The **Engine** line names the model that is loaded now:

```
Engine:   ready (model=qwen3.8-27b, 0/4 slots used, inflight=0)
```

If it says `not ready`, the model is probably still downloading, and
`waired models ls` shows how far along it is. If it stays `not ready` after
the download finishes, the model does not fit this computer. Switch back down.

<Aside type="note" title="A model that is not recommended can still be chosen">
	A model that runs here but is not the recommended one takes a warning and a
	confirmation, not a refusal. Even a model this computer does not have the
	memory for stays a choice. Waired shows the shortfall, for example
	`needs 32 GB RAM (have 31 GB)`, says that loading it is expected to fail,
	and asks again before downloading. When the inference engine has no
	variant of the model, the warning reads `has no Ollama variant` and gives
	no memory figure, because more memory would not help. When the engine is
	too old for the model, the warning says so and points at `waired update`.
</Aside>

## Free up disk space

Models are several gigabytes each. To delete one you are not using:

```sh
waired models rm <model-id>
```

You are asked to confirm first, or pass `--yes`. The model's files are
deleted, so the space comes back. If another model on this computer shares
the same files, they are kept and only the entry is removed. If the deletion
fails, Waired says so and keeps the model listed rather than reporting space
it did not free.
