Waired picks a model for you when you sign in — the best one this computer can
serve a full coding session on. Other models still fit and stay selectable, so
the automatic pick can be smaller than your total memory suggests
([why](/reference/model-catalog/#picked-can-it-hold-a-whole-coding-session-here)).
You only need this page if you want to change it.

## Should you change it?

| If you want… | Do this |
|---|---|
| Better answers, and you have memory to spare | Switch **up** a model |
| Faster answers, or your computer feels slow | Switch **down** a model |
| To know what you're running right now | See [Which model am I running?](#which-model-am-i-running) below |
| To run models here at all, when this computer is not | See [What if no model was picked?](#what-if-no-model-was-picked) below |
| Nothing in particular | Leave it — the automatic pick is a good default |

<Aside type="note" title="Bigger is not always better">
	A model that does not fit in memory does not run *slower* — it fails to
	load, and your AI stops answering. Check the memory column for your model in
	the [model catalog](/reference/model-catalog/) before switching up.
</Aside>

## What if no model was picked?

On some computers Waired picks none, and starts with **local AI off**. One
thing puts a computer in that group:

- **Speed.** Before downloading a full-size model, Waired downloads a small one
  and times a realistic coding question on it. If one answer would take longer
  than 45 seconds, it stops there rather than downloading tens of gigabytes you
  would wait minutes at a time on. See [Local AI started off and I did not
  choose that](/troubleshooting/#local-ai-started-off-and-i-did-not-choose-that).

Either way the computer still joins your network and can use the AI running on
your other computers, and you can turn local AI on whenever you want —
`waired inference on`, or **Run AI models on this computer** in the Waired app.
Waired keeps that choice once you have made it.

```sh
waired inference status   # on or off, and why if Waired decided it
```

## Which model am I running?

Click the **Waired icon** — in the menu bar on macOS, next to the clock on
Windows and Linux → **Inference**. The active model is listed there.

<details>
<summary>From a terminal</summary>

```sh
waired models ls              # what is downloaded, and what is active
waired models ls --detail     # every model, what it needs, and what fits this computer
```

</details>

## What the list tells you

Every model in the list shows the memory it needs and its size — `small`,
`medium` or `large`, meaning the class of graphics card that runs it at all.
Bigger models generally give better answers and need more machine.

- **The memory figure** is what the model takes to serve a full coding
  session: its weights, the AI engine's working memory, and the context
  cache. Your system RAM and graphics memory count together toward it.
- **Graphics memory is counted as what is free, not what the card has.** A
  card that is also driving your display, or that another program is already
  using, has less to lend than its specification says. Waired reads the free
  figure when your driver reports one, so on a busy card it recommends a
  smaller model than the card's headline size suggests — and the model it
  recommends is one that will actually fit, instead of one that starts and
  then runs partly on the processor. Closing whatever else is using the card
  and restarting Waired lets it see the memory again.
- The model Waired would choose for this computer is marked **recommended** —
  the best one this computer can hold a whole coding session on.
- A model that runs here but is not that one is marked too, with the reason.
  It stays selectable: it is a real choice with a real cost, not a mistake.
- A model this computer cannot run is shown greyed out with what it would
  need, rather than left out of the list. Nothing is hidden from you.

## Switch models

<Tabs syncKey="method">
	<TabItem label="From the Waired icon">
		<Steps>

		1. Click the **Waired icon** (menu bar on macOS, next to the clock on Windows
and Linux).
		2. Open **Models**.
		3. Pick a model from the list.

		</Steps>

		The change applies **live** — the AI reloads in a few seconds and keeps
		serving. If the model has not been downloaded yet, the download starts
		and the icon shows progress; the old model keeps answering until the new
		one is ready.
	</TabItem>
	<TabItem label="After a speed test">
		```sh
		waired runtimes benchmark
		```

		This measures how fast this computer actually is. If a different model
		would suit it better, Waired offers the swap, names both models and says
		which direction it is offering. Accept and
		the download runs in the foreground with a progress bar — press
		**Enter** at any time to let it finish in the background instead.

		Once the new model is serving, Waired measures again and reports that
		figure. The first number described the model you moved away from, so it
		is not carried over; if the second measurement cannot be taken, no rate
		is reported rather than the old one.

		Waired then offers to remove the model you moved off, since its files
		are several gigabytes and nothing is going to load them again on this
		computer. Keeping them is a fine answer — say **n** if you expect to
		move back up later, and `waired models rm <model-id>` removes them
		whenever you want. An unattended run always keeps them.
	</TabItem>
	<TabItem label="On a server with no desktop">
		A headless machine has no Waired icon, so set the model in the config
		file and restart the background service.

		<Tabs syncKey="os">
			<TabItem label="Linux">
				Edit `/etc/waired/agent.json` and set `inference.bundled_model_id`
				to the model ID you want, then:

				```sh
				sudo systemctl restart waired-agent
				```
			</TabItem>
			<TabItem label="Windows">
				Edit `%PROGRAMDATA%\waired\agent.json` the same way, then:

				```powershell
				Restart-Service waired-agent
				```
			</TabItem>
		</Tabs>

		Model IDs are the values in the ID column of the
		[model catalog](/reference/model-catalog/), e.g.
		`qwen3.8-27b`.

		<Aside type="note" title="Other ways to set the same thing">
			The environment variable `WAIRED_INFERENCE_BUNDLED_MODEL_ID` and the
			`--inference-bundled-model-id` flag also work, and override the config
			file in that order. See
			[Advanced install options](/reference/install-options/).
		</Aside>
	</TabItem>
</Tabs>

## Confirm the switch

```sh
waired status --observability
```

The **Engine** line names the model that is loaded now:

```
Engine:   ready (model=qwen3.8-27b, 0/4 slots used, inflight=0)
```

If it says `not ready`, the model is probably still downloading —
`waired models ls` shows how far along it is. If it stays `not ready` after the
download finishes, the model does not fit this computer: switch back down.

<Aside type="tip" title="Waired will let you pick a model that is not recommended">
	A model that runs here but is not the recommended one takes a warning and a
	confirmation, not a refusal — it is a real choice with a real cost. Even a
	model your computer does not have the memory for stays a choice: Waired
	shows the shortfall (for example `needs 32 GB RAM (have 31 GB)`), says that
	loading it is expected to fail, and asks again before downloading. Nothing
	is blocked outright.
</Aside>

## Free up disk space

Models are several gigabytes each. To delete one you are not using:

```sh
waired models rm <model-id>
```

You will be asked to confirm first. The model's files are deleted, so the space
comes back. If another model on this computer uses the same files, they are kept
and only the entry goes — deleting one model never takes another one's files with
it. Should the deletion fail, Waired says so and keeps the model listed rather
than reporting space it did not free.
