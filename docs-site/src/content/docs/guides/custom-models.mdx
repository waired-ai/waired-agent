Waired's own list covers the models it recommends. You can also import a model
from Hugging Face into your account. Waired calls these **custom models**.
They run only on your own computers. Your team can send requests to a computer
that runs one, and people outside your account never can.

<Aside type="caution" title="Waired has not reviewed a custom model">
	A custom model comes from Hugging Face, not from Waired. What it outputs,
	whether its files are safe to run, and whether its license allows your use
	are for you to judge. The console asks you to confirm this before your first
	import.
</Aside>

## Import a model

<Steps>

1. In the web console, open the **Custom models** tab, beside **Devices** and
   **Logs**, and select **Import a model**.
2. Paste the model's name (`org/model`) or its `huggingface.co` link, choose
   **Ollama** or **vLLM**, and select **Check this model**. A link to one GGUF
   file (`…/blob/main/<file>.gguf`) picks that variant.
3. For Ollama, a repository usually offers several variants. Choose one.
4. The console shows what it found: the size, the context window, the license,
   the commit it will pin, and whether it fits each of your computers. Give it a
   name, set the two switches (see [Requests that don't name a
   computer](#requests-that-dont-name-a-computer)), and select **Import**.

</Steps>

An account can hold 10 custom models. Importing pins the exact files, at the
repository's current commit: when a repository later replaces a file under the
same name, that is a different model, and importing it again adds a second
entry.

### What can't be imported

The check refuses a model when:

- it is private, or asks people to accept terms before downloading it;
- the link points at a branch or commit other than the repository's current
  one;
- it is not a text-generation model;
- it needs to run its own code to load, or its weights exist only in a format
  that can run code when loaded;
- for Ollama, the variant is published in parts, or the engine Waired installs
  does not support the model's architecture;
- for vLLM, the repository has no safetensors weights, or no chat template;
- Waired's own list already has it. Choose it from the list instead.

When it refuses one, the console says why and what to do.

## Run it on a computer

Open the computer's page in the console, open **Model list**, and choose the
**Custom models** tab. The setup wizard shows the same tab. A model imported for
the other engine is greyed there: a custom model runs only on the engine you
imported it for.

The computer downloads the model and switches to it, the same way as for a
model from Waired's list. On the computer, `waired models ls --detail` and the
Waired app's **Models** menu list custom models last, under **Custom models**.

While a computer runs a custom model, it takes no Public Share guests, even with
Public Share on. Its page says so, and guests are sent there again once it runs
a model from Waired's list.

## Requests that don't name a computer

The **Waired** and **Waired peer** rows in Claude Code and the other coding
agents let Waired choose the computer. Two switches decide whether it may choose
one that runs this custom model:

- **From your computers**: requests from your own computers.
- **From your team**: requests from your teammates' computers. The **Custom
  models** tab also lists the team's models, and there the team's owner or an
  admin can stop one for the whole team.

Both start on for a model whose context window is at least 200,704 tokens, and
off below that. A row that names a computer (**Waired peer: *name***) always
reaches it.

## Small context windows

A coding agent's session is sized for 200,704 tokens. A model with a smaller
context window still runs, and the console says so wherever you choose one.
Waired holds each turn to the model's own window: a larger turn is answered
`prompt is too long`. What the coding agent does then differs (measured with
Claude Code 2.1.278 and OpenCode 1.18.30):

- **Claude Code** summarizes the conversation by itself (it calls this
  compacting) and sends the turn again. When even the summary request is too
  long, it drops the oldest part of the conversation and tries again. When the
  turn still doesn't fit after that, it stops with `Prompt is too long`. Claude
  Code's own instructions and tool list take about 15,000 tokens of every
  request, so a model with a much smaller window can't take even a first turn.
- **OpenCode and OpenClaw** are told a window per entry. The entries that name
  that computer (`waired/local`, `waired/peer-<name>`) carry the model's own
  window, so they summarize before reaching it. The entries that name no
  computer (`waired/default`, `waired/peer`) keep 200,704, because which
  computer answers them is decided per turn. On the entries that name the
  computer, OpenCode is also given a smaller output limit: at most 8,192
  tokens, or a quarter of the window when that is less. Without it, OpenCode
  keeps 32,000 tokens of the window for the model's output, and on a small
  window it would summarize without end.

Keep sessions short with such a model, and start a new one when the agent
summarizes often. In OpenCode and OpenClaw, use the entry that names the
computer: it is the one that knows the window. When a request that names no
computer could go to one that holds 200,704 tokens, Waired sends it there
instead.

## When a custom model doesn't run

Each of these messages says why, and what to do.

| Message | Why | What to do |
|---|---|---|
| **… was imported for vllm, but this computer runs ollama — …** | A custom model runs only on the engine it was imported for. `waired models use`, the Waired app and a download all refuse it, and nothing on the computer changes. | Choose a model for this computer's engine, or import the model again for that engine. |
| **the file behind … on Hugging Face was replaced after this model was imported** | The file was replaced on Hugging Face after you imported it. The new file is a different model, so the computer doesn't download it. | Import the model again. The new import pins the new file. |
| **the repository's top level has no safetensors weights at the imported commit** | vLLM loads the safetensors weights at the top of the repository, and there are none. | Choose another model, or import one whose safetensors weights are at the repository's top level. |
| **insufficient disk space for this model: it needs … and only … is free** | Before a vLLM download starts, Waired compares its size with the free disk space. | Free up space, or choose a smaller model. |
| **This computer has no custom model …** | `waired models use` named a custom model this computer doesn't have. It was imported moments ago and hasn't reached the computer yet, or it was deleted. | Wait a minute and try again, or import it again. |
| **custom model … is no longer in this account's list** | Setup shows it for a model that was deleted in the console. | Choose another model, or import it again. |
| **custom model … is in this account's list, but this version of Waired can't read it** | Setup shows it when the Waired on that computer is too old to read the model. | Update Waired on that computer, then choose the model again. |

A model that fails to start for a reason another try can't fix is not started
again. Waired stops the engine and shows the notice **⚠ … did not
start on this computer**, and `waired status` says **Waired stopped the engine
because it cannot start the chosen model on this computer.** The notice names
the reason:

- **the vLLM version Waired installs does not support this model's
  architecture …**: choose another model.
- **this model needs to run its own code to load, which Waired does not
  allow**: choose another model.
- **this GPU is too old for the model's … quantization**: choose a build with
  another quantization, or another model.
- **vLLM found no safetensors weights in the downloaded files**: remove the
  model with `waired models rm` and choose it again to download a fresh copy.
- **the Ollama version on this computer does not support this model's
  architecture …**: update Waired, or choose another model.

Choosing a model starts the engine again. On vLLM, two more reasons show on the
engine's line in `waired status` and in the console:

- **on this computer the KV cache holds at most … tokens for this model, less
  than the context window it was started with**: choose a smaller model, or
  raise `inference.vllm_gpu_memory_utilization`. This is also the notice **⚠ …
  did not load on this computer**.
- **another program is using this GPU's memory**: close that program, or lower
  `inference.vllm_gpu_memory_utilization`, then choose the model again.

## Delete a model

Delete it from the **Custom models** tab. A model that a computer runs,
or has been told to run, can't be deleted: the console names those computers,
and you choose another model on each of them first. Computers that downloaded
it keep its files. To free that space, run `waired models rm <model id>` on
each of them before you delete the model.

If a model is deleted while a computer is still using it, that computer keeps
running it and shows the notice **… was deleted from your account** until you
choose another model. See [Notices](/guides/notices/).
