Waired connects OpenCode to the model on your own computer through a small
plugin in your home folder. Setup installs it if you said yes to the
coding-tool question. This page covers installing it yourself, what it
changes, and how to remove it.

## Connect OpenCode

```sh
waired link opencode
```

That is the whole setup. Start OpenCode as usual afterwards and pick the
Waired model.

<Expected>
	```
	opencode:    configured

	OpenCode integration:
	  - Plugin written to ~/.config/opencode/plugin/waired.js
	    (registers the 'waired' provider). Restart opencode to pick it up.
	```
	OpenCode's model picker gains a **Waired** provider:

	| Model | Where the turn runs |
	|---|---|
	| `waired/default` (shown as **Waired**) | Any of your computers — Waired picks one with a 200k context window |
	| `waired/local` (**Waired local**) | This computer, if it has a 200k context window |
	| `waired/peer` (**Waired peer**) | Another of your computers, never this one, with a 200k context window |
	| `waired/peer-<name>` (**Waired peer: &lt;name&gt;**) | The computer you name, if it has a 200k context window |
	| `waired/public` (**Waired public share**) | Someone else's computer, with a 200k context window |
	| `waired/default[1m]` and the other `[1m]` entries (**… (1M context)**) | The same, on a computer with a 1M context window. Listed while a computer that could answer the entry declares one |
</Expected>

No API key and no environment variable are involved. Waired connects OpenCode
to the model on your own computer directly.

The entries name a **computer**, not a model: whichever computer answers runs
the model it has. `waired/local` is offered only where this computer has an
engine and local inference is on, and `waired/public` only where you have
turned Public Share on. There is one `waired/peer-<name>` entry per computer
of yours that is serving right now with a context window of at least 200,704
tokens.

If the computer an entry names cannot answer, the turn fails and says so
rather than quietly running somewhere else.

The list is the one Claude Code shows in `/model`, `(1M context)` twins
included. See
[How a Claude Code turn is routed](/guides/claude-code/how-turns-are-routed/)
for what each row means.

## Subagents

A subagent uses the same entry as the conversation that starts it, unless
you give it one of its own. To send OpenCode's built-in `general` subagent
somewhere else, set its model in `opencode.json`:

```json
{
  "agent": {
    "general": { "model": "waired/peer" }
  }
}
```

Waired tells a subagent's requests from the conversation's, so the
**Serve main conversation** and **Serve subagents** switches on each
computer's page in the [web console](/guides/web-console/) apply to OpenCode
as they do to Claude Code.

When every computer an entry can use is busy, Waired holds the request until
one is free: up to a minute for the conversation, and up to 20 seconds for a
subagent. After that it answers with an error, and OpenCode retries the
request itself.

<Aside type="note" title="The list is read each time OpenCode starts">
	OpenCode asks Waired which computers are available when it starts, so an
	entry for a computer you have just switched on appears the next time you
	start OpenCode. If Waired is not running, the list falls back to
	`waired/default` alone.
</Aside>

<Aside type="note" title="Your own default model is not touched">
	Linking adds the Waired model to the list you can choose from. Which model
	OpenCode starts with stays as you had set it. Switch to the Waired model
	when you want it, with `/models` or the picker.
</Aside>

<Aside type="tip" title="Several coding tools installed">
	`waired link` with no name sets up every tool it finds: Claude Code,
	OpenCode, and OpenClaw.
</Aside>

## Context windows

Every entry uses only a computer whose context window holds 200,704 tokens,
and every `[1m]` entry only one that holds 1,048,576. That includes
`waired/local` and `waired/peer-<name>`. A computer serving less, such as one
where vLLM sized the window down to fit the GPU's VRAM, answers none of the
entries, not even `waired/local` on itself.

The plugin gives each entry its window as `limit.context`, taken from the
entry's name alone: 1048576 on every `[1m]` entry and 200704 on every other
one, including the `waired/default` entry the list falls back to when Waired
is not running. OpenCode compacts the conversation before that window. The
window does not depend on which computer answers. A turn on an entry without
`[1m]` that grows past 200,704 tokens is answered `prompt is too long` even on
a computer that holds 1M. The list at
`http://127.0.0.1:9473/v1/models` states the same numbers as
`max_input_tokens`.

The plugin shows the any-computer entry as `waired/default`, so a config
written against it keeps working, and sends it as `waired`, the id Claude
Code sends; `waired/default[1m]` goes as `waired[1m]`. Those ids carry the
200k and 1M windows above. A chat app that sends `waired/default` itself gets
no such window; see
[Use Waired from a chat app](/guides/chat-clients/#what-to-put-in-the-settings).

When no computer meets the entry's window, the turn fails and OpenCode shows
the error. It does not compact or retry, because the conversation's length is
not the problem:

```
None of your computers that could take this turn has a context window of 200704 tokens, which the model you picked needs.
```

## What it changed

Three files, all inside your own home folder:

| Path | What it is |
|---|---|
| `~/.config/opencode/plugin/waired.js` | A small plugin that registers the `waired` provider |
| `~/.config/opencode/commands/waired-status.md` | The `/waired-status` command inside OpenCode |
| `~/.config/opencode/commands/waired-doctor.md` | The `/waired-doctor` command inside OpenCode |

Your `opencode.json` is not written, and nothing outside your home folder is
touched.

## Check it or remove it

[`waired doctor`](/getting-started/doctor/) verifies the whole path: the
connection, whether routing is paused, and whether a model is loaded. It
repairs what it can when you press `f`. Inside OpenCode, `/waired-status` and
`/waired-doctor` run the same checks and summarize them.

To remove the integration:

```sh
waired unlink opencode
```

It undoes what `waired link` added and nothing else. Files you put in
`~/.config/opencode/commands/` yourself, and anything OpenCode wrote there,
stay.

You can also see and reapply the integration from the Waired app. Select the
**Waired icon**, then **Settings**, then the **OpenCode** entry.
