Waired connects OpenCode to the model on your own computer through a small
plugin in your home folder. Setup installs it if you said yes to the
coding-tool question. This page covers installing it yourself, what it
changes, and how to remove it.

## Connect OpenCode

```sh
waired link opencode
```

That is the whole setup. Start OpenCode as usual afterwards and pick the
Waired model.

<Expected>
	```
	opencode:    configured

	OpenCode integration:
	  - Plugin written to ~/.config/opencode/plugin/waired.js
	    (registers the 'waired' provider). Restart opencode to pick it up.
	```
	OpenCode's model picker gains a **Waired** provider:

	| Model | Where the turn runs |
	|---|---|
	| `waired/default` (shown as **Waired**) | Any of your computers — Waired picks |
	| `waired/local` (**Waired local**) | This computer |
	| `waired/peer` (**Waired peer**) | Another of your computers, never this one |
	| `waired/peer-<name>` (**Waired peer: &lt;name&gt;**) | The computer you name |
	| `waired/public` (**Waired public share**) | Someone else's computer |
</Expected>

No API key and no environment variable are involved. Waired connects OpenCode
to the model on your own computer directly.

The entries name a **computer**, not a model: whichever computer answers runs
the model it has. `waired/local` is offered only where this computer has an
engine and local inference is on, and `waired/public` only where you have
turned Public Share on. There is one `waired/peer-<name>` entry per computer
of yours that is serving right now.

If the computer an entry names cannot answer, the turn fails and says so
rather than quietly running somewhere else.

<Aside type="note" title="The list is read each time OpenCode starts">
	OpenCode asks Waired which computers are available when it starts, so an
	entry for a computer you have just switched on appears the next time you
	start OpenCode. If Waired is not running, the list falls back to
	`waired/default` alone.
</Aside>

<Aside type="note" title="Your own default model is not touched">
	Linking adds the Waired model to the list you can choose from. Which model
	OpenCode starts with stays as you had set it. Switch to the Waired model
	when you want it, with `/models` or the picker.
</Aside>

<Aside type="tip" title="Several coding tools installed">
	`waired link` with no name sets up every tool it finds: Claude Code,
	OpenCode, and OpenClaw.
</Aside>

## What it changed

Three files, all inside your own home folder:

| Path | What it is |
|---|---|
| `~/.config/opencode/plugin/waired.js` | A small plugin that registers the `waired` provider |
| `~/.config/opencode/commands/waired-status.md` | The `/waired-status` command inside OpenCode |
| `~/.config/opencode/commands/waired-doctor.md` | The `/waired-doctor` command inside OpenCode |

Your `opencode.json` is not written, and nothing outside your home folder is
touched.

## Check it or remove it

[`waired doctor`](/getting-started/doctor/) verifies the whole path: the
connection, whether routing is paused, and whether a model is loaded. It
repairs what it can when you press `f`. Inside OpenCode, `/waired-status` and
`/waired-doctor` run the same checks and summarize them.

To remove the integration:

```sh
waired unlink opencode
```

It undoes what `waired link` added and nothing else. Files you put in
`~/.config/opencode/commands/` yourself, and anything OpenCode wrote there,
stay.

You can also see and reapply the integration from the Waired app. Select the
**Waired icon**, then **Settings**, then the **OpenCode** entry.
