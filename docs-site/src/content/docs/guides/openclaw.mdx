Waired connects OpenClaw to the model on your own computer through a small
plugin in your home folder. Setup installs it if you said yes to the
coding-tool question. This page covers installing it yourself, what it
changes, and how to remove it.

## Connect OpenClaw

```sh
waired link openclaw
```

That is the whole setup. Start OpenClaw as usual afterwards and pick the
Waired model.

<Expected>
	OpenClaw's model picker lists the Waired entries:

	| Model | Where the turn runs |
	|---|---|
	| `waired/default` | Any of your computers — Waired picks one with a 200k context window |
	| `waired/local` | This computer |
	| `waired/peer` | Another of your computers, never this one, with a 200k context window |
	| `waired/peer-<name>` | The computer you name |
	| `waired/public` | Someone else's computer, with a 200k context window |
	| `waired/default[1m]` and the other `[1m]` entries | The same, on a computer with a 1M context window. Written while a computer that could answer the entry declares one |
</Expected>

No API key and no environment variable are involved. Waired connects OpenClaw
to the model on your own computer directly.

The entries name a **computer**, not a model: whichever computer answers runs
the model it has. `waired/local` is offered only where this computer has an
engine and local inference is on, and `waired/public` only where you have
turned Public Share on. There is one `waired/peer-<name>` entry per computer
of yours that was serving when you linked.

If the computer an entry names cannot answer, the turn fails and says so
rather than quietly running somewhere else. The entries where Waired picks
the computer, `waired/default`, `waired/peer` and `waired/public`, use only a
computer whose context window holds 200,704 tokens, and every `[1m]` entry
only one that holds 1,048,576; when none does, the turn fails and says which
window it needed. The list is the one Claude Code shows in `/model`; see
[How a Claude Code turn is routed](/guides/claude-code/how-turns-are-routed/)
for what each row means.

The plugin shows the any-computer entry as `waired/default`, so a config
written against it keeps working, and sends it as `waired`, the id Claude
Code sends; `waired/default[1m]` goes as `waired[1m]`. Those ids carry the
200k and 1M windows above.

<Aside type="note" title="Run `waired link openclaw` again after your computers change">
	OpenClaw reads its model list from `openclaw.json`, which Waired writes
	when you link. Switch another computer on and the entry for it appears
	once you run `waired link openclaw` again — or press `f` in
	[`waired doctor`](/getting-started/doctor/), or use **Reconfigure** in the
	Waired app.
</Aside>

<Aside type="note" title="Your own default model is not touched">
	Linking adds the Waired model to the list you can choose from. Which model
	OpenClaw starts with stays as you had set it. Switch to the Waired model
	when you want it.
</Aside>

<Aside type="tip" title="Several coding tools installed">
	`waired link` with no name sets up every tool it finds: Claude Code,
	OpenCode, and OpenClaw.
</Aside>

## What it changed

Two things, both inside your own home folder:

| Path | What it is |
|---|---|
| `~/.openclaw/plugins/waired/` | A small plugin that knows how to reach your model |
| `~/.openclaw/openclaw.json` | Two settings that switch that plugin on, and the model above added to the list |

Nothing else in that file is modified, and nothing outside your home folder
is touched.

If you already had an `openclaw.json`, Waired copies it before the first
change it makes, to `~/.openclaw/openclaw.json.waired-bak-<timestamp>`.
Writing the file back drops your key order and formatting, so that copy is
the only record of the file as you wrote it. Running `waired link openclaw`
again when nothing needs changing leaves the file, its timestamp, and that
copy as they are.

## How much context OpenClaw is told about

The plugin records a context window for each Waired entry, so OpenClaw
compacts your conversation before the window the entry states and not
earlier. `waired/default`, `waired/peer` and `waired/public` state 200704
tokens, the window Waired holds them to. Every `[1m]` entry states 1048576.
`waired/local` states this computer's own window and `waired/peer-<name>` the
named computer's own; a computer that states none gets no number, and
OpenClaw uses its own default for that entry.

The entries are written when you link. During first-time setup this computer
is usually not serving yet, so the plugin starts with `waired/default` alone.
`waired init`, `waired link all` and `waired doctor --fix` bring the plugin up
to date when any entry changed, by name or by window, or when the plugin was
written by an older version of Waired, and say so:

```
Updated OpenClaw's list of Waired models and their context windows.
```

`waired doctor` warns when the plugin is out of date, with one of these
lines:

```
! openclaw context window   the plugin was written by an older version of Waired
! openclaw context window   the plugin's list of Waired models is out of date
! openclaw context window   the plugin declares no window for waired/default; Waired now gives it 200704 tokens
```

Press `f` to bring it up to date.

## Check it or remove it

[`waired doctor`](/getting-started/doctor/) verifies the whole path: the
connection, whether routing is paused, and whether a model is loaded. It
repairs what it can when you press `f`.

To remove the integration:

```sh
waired unlink openclaw
```

It undoes what `waired link` added and nothing else. The copy of your original
`openclaw.json` stays where it is, and `waired unlink` prints the path.

You can also see and reapply the integration from the Waired app. Select the
**Waired icon**, then **Settings**, then the **OpenClaw** entry.
