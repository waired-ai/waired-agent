A notice is how Waired tells you something about this computer that you
should know. The background service decides what to say, and the same set of
notices appears on every surface: as rows near the top of the Waired app's
menu, under **Notices:** in `waired status`, and as ⚠ rows in `waired doctor`.
A computer with no screen is told through the last two.

## How notices behave

- There are usually none. Then there are no rows.
- A warning (⚠) means something is working, but not the way it should. A
  note (⬆) is worth reading and is not a problem. Warnings come first.
- A notice stays as long as it is true. Nothing dismisses it. When the thing
  it reports stops being the case, the row goes on its own within a minute.
- In the Waired app, a notice that has an action does it when you select
  the row. The row's text names the action.

## Every notice

| Notice | Meaning | What to do |
|---|---|---|
| **⚠ Faster model recommended — switch to …** | With the model it runs, one request the size of a coding agent's takes this computer longer than the target. The text gives the figures: *This computer takes 228 s per request with qwen3.8-27b (target: 190 s or less).* | Select the row to switch. Answering **No** stops it asking again for that pair of models. |
| **⬆ Update available — install …** | A newer version of Waired than the one this computer runs. The text names the version it runs. | Select the row. It asks for administrator rights and updates in place. See [Update Waired](/getting-started/update/). |
| **⚠ Ollama is not running the version Waired pins** | The engine answering requests here is not the version this build of Waired expects. Usually one you installed yourself, or one left over from an older Waired. | The text names the command that puts it back. |
| **⬆ Ollama sized this model for this computer** | Not a problem. The engine made a trade on purpose, such as keeping a long context window at the cost of some speed. | Nothing. The row exists so the trade is visible. |
| **⚠ Ollama is serving a configuration this computer could not hold** | The engine was sized for this computer and could not keep to it. The model spilled into system RAM, the GPU ran out of room, or the engine did not use the GPU at all. Answers are slower, or a request can fail. | The text says which. A smaller model is the usual answer. See [Change the model](/guides/choose-a-model/). |
| **⬆ Context window: 1M, extended past the model's trained length** | Not a problem. This computer is serving the 1M context window, which runs the model past the length it was trained for. That applies to every request, so short prompts may be affected. | Nothing. The row exists so the trade is visible. To go back, pick the 200K context window where you chose the model. |
| **⬆ Context window: … tokens, under a coding agent's 200,704** | Not a problem. This computer is serving a custom model whose own context window is smaller than the 200,704 tokens a coding agent's session is sized for. A coding agent's session overflows it on every turn. | Keep sessions short, or choose a model with a larger context window. See [Small context windows](/guides/custom-models/#small-context-windows). |
| **⚠ … was deleted from your account** | A custom model this computer runs, or was told to run, was deleted from your account in the Waired console. This computer keeps running it. Your other computers and your team can no longer use it, and nothing will download it again. | Choose another model. The row goes away once this computer stops using the deleted one. |
| **⚠ … did not start on this computer** | vLLM could not start the chosen model on this computer, for a reason another try can't fix: an architecture the installed vLLM doesn't support, a model that needs to run its own code, a GPU too old for the model's quantization, or weights missing from the download. Waired stopped the engine and won't start that model again by itself. The text gives the reason. | Choose another model, which starts the engine again. See [When a custom model doesn't run](/guides/custom-models/#when-a-custom-model-doesnt-run). |
| **⚠ Ollama is running but not answering** | The engine process is up but not replying to its own health checks. Your other computers have noticed and stopped sending work here. | Restart the engine: `waired inference engine stop`, then `start`. |

The engine's name in the rows above is the one this computer runs, so on a
Linux computer with vLLM the rows say **vLLM** instead.

## Where else to look

The notices cover the computer they appear on. For the state of everything
Waired knows right now, including your other computers, open **Status…** in
the Waired app. See [The Status… report](/guides/status-report/).
