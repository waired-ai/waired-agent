Setup normally connects Claude Code for you. This page explains what that
connection is, how to choose where a session runs, and how to check or remove
it. You do not set an environment variable, edit a config file, or use an
alias. Waired writes Claude Code's machine-wide managed settings, the same way
on Windows, macOS, and Linux.

<Aside type="note" title="What reaches Anthropic">
	Waired writes one setting, `ANTHROPIC_BASE_URL`, and no credential. Your
	claude.ai sign-in and its subscription keep working as before. Only a turn
	whose model is an Anthropic model reaches Anthropic, and Waired does not
	store or use your claude.ai credentials. Waired has no affiliation with or
	endorsement from Anthropic, and Anthropic does not support routing Claude
	Code to non-Claude models through any gateway (see
	[Other LLM gateways](https://code.claude.com/docs/en/llm-gateway)). What
	Waired adds is the choice, in `/model`, to run a session on your own
	computers instead.
</Aside>

## Before you start

- Claude Code installed on this computer.
- Waired installed and signed in.
- Administrator rights, for the machine-wide setting.

## Connect Claude Code

<Steps>

1. **Install the Waired skills for Claude Code.** Setup already did this if
   you said yes to the coding-tool question.

   ```sh
   waired link claude-code
   ```

2. **Turn on routing.** Setup already did this unless you declined the
   routing question, cleared the Claude Code switch in the browser, or
   installed with `--skip-claude-proxy`.

   <Tabs syncKey="shell">
   	<TabItem label="macOS / Linux">
   		```sh
   		sudo waired claude enable
   		```
   	</TabItem>
   	<TabItem label="Windows">
   		From an administrator terminal:

   		```powershell
   		waired claude enable
   		```
   	</TabItem>
   </Tabs>

   The command writes the managed settings file and tells you to restart any
   running `claude` session. On a computer where an organization manages
   Claude Code, `enable` writes nothing and explains why. See
   [Claude Code problems](/troubleshooting/claude-code/#waired-says-claude-code-is-managed-by-your-organization).

3. **Start Claude Code** as you normally would.

   ```sh
   claude
   ```

4. **Pick a Waired row in `/model`.** Type `/model` and select **Waired**, the
   row described as *Any of your computers*. The choice applies from your next
   message.

</Steps>

## Which model answered

The footer says so on every turn.

<Screenshot
	src="claude-code-statusline.png"
	alt="The Claude Code footer showing the Waired status line: where this session's turns run, and the local model that answered the last request."
/>

| Footer | Meaning |
|---|---|
| `⚡ waired: on Waired (qwen3.5-9b)` | Your own computer answered, with that model. |
| `⚡ waired: on Waired (peer sv-mag: qwen3.5-9b)` | Another of your computers answered, with that model. |
| `→ waired: Anthropic` | This session is on an Anthropic model, so the Anthropic API answers. |
| `⚠ waired: Waired cannot answer (local disabled, no peer)` | Nothing of yours can take the next turn. The brackets say why. |

The footer describes the session it sits under, not the computer. Two
sessions open side by side can show different things, and each is right about
itself. For every form the footer takes and what to do when it is missing,
see [The Waired status line](/guides/claude-code/status-line/).

## Switch where a session runs

Type `/model` inside the session. No restart is needed. The Waired rows sit
below the Anthropic models, each with a second line saying which computer it
means:

```
Waired               Any of your computers
Waired local         This computer
Waired peer          Another of your computers
Waired public share  Someone else's computer
```

Pick a Waired row and the session runs on your own computers. Pick an
Anthropic model and it runs on the Anthropic API, on your Claude
subscription. The change applies from your next message.

That choice is the whole mechanism. A turn runs where the model you picked
says, and Waired never moves it to the other side on its own. A Waired turn
that none of your computers can answer fails and tells you why. For the rows
that name your computers, the `(1M context)` twins, and what each failure
message means, see
[How a Claude Code turn is routed](/guides/claude-code/how-turns-are-routed/).

<Aside type="note" title="A new session starts on Anthropic">
	Waired does not write a default model into your Claude Code settings. A
	session you have not touched starts on Claude Code's own default, which
	is an Anthropic model, and the footer says `→ waired: Anthropic`. Pick a
	Waired row once and `/model` remembers it, the same way it does for any
	other model.
</Aside>

## Subagents

Subagents follow the main conversation unless you say otherwise. To run every
subagent on your own computers whatever the main conversation is on, run
`waired claude subagents waired`. For details, see
[Choose where subagents run](/guides/claude-code/subagents/).

## Check the connection

```sh
waired claude status
```

The output says whether the managed settings file is present and what it
points at, whether the gateway is listening, whether the status line is
installed, which model new sessions start on, and where the last turn went.

| | Managed settings file |
|---|---|
| Linux | `/etc/claude-code/managed-settings.json` |
| macOS | `/Library/Application Support/ClaudeCode/managed-settings.json` |
| Windows | `C:\Program Files\ClaudeCode\managed-settings.json` |

If the output says `installed, but not in the form this computer runs`, run
`waired claude enable` again from an administrator terminal. It rewrites the
status line and the `/model` refresh hook in the form the shell on this
computer can run.

## Turn it off

To stop routing Claude Code through Waired and restore Claude Code's normal
behavior:

<Tabs syncKey="shell">
	<TabItem label="macOS / Linux">
		```sh
		sudo waired claude disable
		```
	</TabItem>
	<TabItem label="Windows">
		From an administrator terminal:

		```powershell
		waired claude disable
		```
	</TabItem>
</Tabs>

To remove the skills as well:

```sh
waired unlink claude-code
```
