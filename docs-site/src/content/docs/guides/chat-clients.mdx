Waired answers on your own computer at an address that speaks the OpenAI and
Anthropic APIs. Anything that can talk to those, such as a browser chat UI, an
editor extension, or a script, can use your model instead of a cloud service.

[Claude Code](/guides/claude-code/), [OpenCode](/guides/opencode/), and
[OpenClaw](/guides/openclaw/) are set up for you and need none of this page.

## What to put in the settings

<Steps>

1. **Base URL.** Which one depends on the API your tool speaks.

   | Your tool speaks | Base URL |
   |---|---|
   | OpenAI | `http://127.0.0.1:9473/v1` |
   | Anthropic | `http://127.0.0.1:9473/anthropic` |

2. **Model.** Use `waired/default`, and your settings keep working when you
   switch models. To pin one model instead, use its name from
   `waired models ls`.

</Steps>

No API key. Waired does not check one. If your tool requires an API key, any
value works.

## Check the address first

```sh
curl http://127.0.0.1:9473/v1/models
```

<Expected>
	A JSON list that includes `waired/default`. Those are the names your chat
	app can use.
</Expected>

<Expected tone="bad">
```
curl: (7) Failed to connect to 127.0.0.1 port 9473
```
	Waired is not running, or routing is paused. Run
	[`waired doctor`](/getting-started/doctor/).
</Expected>

A full request looks like this:

```sh
curl http://127.0.0.1:9473/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "waired/default",
    "messages": [{"role": "user", "content": "Say hi"}]
  }'
```

## Run the app on the same computer

The address `127.0.0.1` means this computer only. It is not reachable from
the network on purpose. That is what keeps your model from being exposed by
accident.

A chat app in a browser must therefore run on the same computer as Waired. To
use your model from a different computer, install Waired there too and
[sign in with the same account](/getting-started/add-a-device/). The two
computers connect privately, and the chat app then talks to `127.0.0.1` on
that computer.

A chat UI served from another computer does not work, even in a browser on
this computer. Waired turns away requests that a web page made, because a page
you merely visit could otherwise reach your model.

## Which of your computers answered

Every answer Waired serves says so in its response headers, on the OpenAI and
Anthropic endpoints alike.

- `X-Waired-Local-Model` is the model that answered, by its name from
  `waired models ls`.
- `X-Waired-Inference-Peer` is present when another of your computers
  answered. Its value is that computer's identifier, the one in the
  `DEVICE-ID` column of `waired peers list`. No peer header means this
  computer answered.

The `model` field inside the JSON body is the inference engine's own tag for
the weights, such as `openai/gpt-oss-20b`. It names neither Waired nor a
computer, so the headers are the place to look.

To see the headers from a shell, add `-D-` to the `curl` request above. A
reply that another of your computers answered looks like this:

```
HTTP/1.1 200 OK
Content-Type: application/json
X-Waired-Local-Model: qwen3.5-9b
X-Waired-Inference-Peer: dev_a1b2c3…
```

## A conversation too long for the model

Every model holds only so much of a conversation at once. When a request is
larger than the model running here can hold, Waired replies with an error
instead of passing it on. Left to itself, the inference engine would drop the
oldest part of the conversation and answer from what was left, which reads as
the model forgetting your instructions.

The reply is the standard error for this case, so a client that knows how to
shorten a conversation does so and retries by itself:

```json
{"error":{"message":"prompt is too long: 214000 tokens > 200704 maximum","type":"invalid_request_error","code":"context_length_exceeded"}}
```

Tool descriptions and tool output count toward that limit alongside the
messages. In a coding session they are usually most of it.

## The full endpoint list

| API | Endpoint |
|---|---|
| OpenAI chat | `POST /v1/chat/completions` |
| OpenAI models | `GET /v1/models` |
| OpenAI responses | `POST /v1/responses` |
| Anthropic messages | `POST /anthropic/v1/messages` |

The model each Waired name resolves to is in the
[model catalog](/reference/model-catalog/).
