# 最初の1語までの時間は「出す」が「判定しない」 (20260821 11:30)

## Status

Accepted。オーナー裁定（2026-08-21、waired-agent#912）。提示した3案
（数字だけ / 数字＋同一ホストの最速値 / 語で言い切る）のうち2案目が選ばれた。
根拠の実測は #912 と #838 / #866 / #883 に既に載っている。

## Context

waired-agent#879 で `model loaded:` を出したが、それは**重みが (V)RAM に在るか**という
1ビットでしかない。#879 自身の文（「1時間前に降ろしたホストと、いま生成中のホストが
同じ状態に見える」）は、1段下でもそのまま成り立つ。

実測（#912、同一モデル・同一ホスト・既定設定）:

| 分岐点 | 最初の1語 |
|---|---|
| 末尾から 10 トークン | **2.57 s** |
| 末尾から 2,926 トークン | **35.4 s** |

どちらも `model loaded: yes`。何も降ろされておらず、何も退去しておらず、設定は同一。
これが埋めるべき穴で、特別な構成なしに再現する。

**語（cold / warm）は擁護できない。** 3台の cold / warm 実測:

| ホスト | cold | warm | 比 |
|---|---|---|---|
| 離散GPU 24GB / 35b-a3b | 16,493 ms | 259 ms | 64x |
| 統合メモリ / 35b-a3b | 51,798 ms | 799 ms | 65x |
| 離散GPU 8GB / 4b | 44,649 ms | 1,960 ms | 23x |

**4b の *warm*（1,960 ms）は 35b-a3b の *warm*（259 ms）の 7.5 倍**で、両方とも正しい。
1,960 ms を cold と呼ぶ定数は Windows で誤り、warm と呼ぶ定数は Linux で誤りになる。
一方**比は 23〜65倍で残る**ので、**同一ホスト内の比較なら成立する**。

さらに、TTFT は症状であって機構ではない。同じ数字は分岐距離でも出る（#866 / #883）ので、
「キャッシュが冷えていた」は測っていないことについての主張になる。

なお #912 本文の「履歴を持ち回るのは1語のためには大きすぎる」という見積もりは**誤り**
だった。`observability.Ring` は既に 16,384 件の `RequestEvent` を保持し、各件が
`TTFTMs` / `InputTokens` / `Model` を持っている。`LatestRequest()` が既に同じ
後ろ向き走査をしている。

## Decision

1. **`waired status` の `model loaded:` の直下に、直前の回答が始まるまでの実測値を出す。**
   同一ホスト・同一モデルで観測した最短値を並べる。
2. **判定の語を出さない。** `cold` / `warm` / `slow` / 「キャッシュ」を、この行にも
   その ja 訳にも使わない。数字だけを出し、判断は読み手がする。
3. **時刻を必ず併記する。** `model loaded:` は「いま」についての文なので、1時間前の
   数字がその下に出ると次のリクエストへの約束に読める。読めない時刻は句ごと落とす。
4. **母集団を3つで絞る**（どれも「役に立たない」ではなく「偽になる」ため）:
   観測済み（`TTFTMs > 0`。0 は「観測できなかった」であって「速かった」ではない、#874）/
   **このホストが答えたもの**（ピアが答えた要求はピアの prefill を測っている）/
   **いまのモデル**（モデル切り替え前の値は上の行が名指すモデルについて何も言わない）。
   加えて最短値の母集団は**直前の応答の入力トークン数の半分以上**のものに限る。
   一言の質問は同じホストの同じ重みでも桁違いに速く答えるので、入れると
   **どの実応答も遅く見える床**ができる。これは「何が速いか」ではなく
   「どの標本が似ているか」の線引きで、判定の閾値ではない。
5. **tray は対象外**、`waired status --observability` の `Last:` 行は据え置き。
   tray の推論サブメニューは操作の面であって読み取り値の面であり、`--observability` は
   既に `ttft=Nms` を出している。**この2点は #912 の未決の問いに対する記録者の判断**で、
   オーナー裁定として提示したのは 1〜4 のみ。

## Consequences

- 数字が出るのは **Anthropic ストリーミング脚**の traffic だけ（#874）。OpenAI 脚と
  非ストリームは `TTFTMs` を 0 のままにするので、その面しか使わないホストでは
  行が出ない。**出ないことは「速い」ではない。**
- ring はインメモリなので、「このホストで観測した最短値」は**エージェント再起動で消える**。
  再起動直後は比較対象が無く、数字だけが出る。
- 最短値は**厳密に速いときだけ**出す。直前の値そのものが最短なら比較にならないので出さない。
- 新しい行は既定の `waired status` に出るので、`docs-site` の
  `reference/cli.md`（と ja ミラー）に **`Inference:` ブロックの出力例が初めて載る**。
  それまで docs には `--observability` の例しか無かった。
- 語を出さないという判断は**取り消せる**。取り消すには、ホストごとの warm の床を
  持ち回るか（ring はそれを持っている）、モデルごとに弁護できる定数を出す必要がある。
  どちらも今は無い。
