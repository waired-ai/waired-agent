# 空きメモリは毎起動で測り直し、最も高い読みを残す (20260819 18:30)

## Status
Accepted

## Context

20260809/0016 §2 は「計測はインストール毎に一回」と裁定し、`AgentVersion` を
キーに `runtime/host-memory.json` を凍結した。理由は 2 つ書かれている
——(a) 常駐モデルを自ホストに課さない、(b) live 値を配信すると
「5 分毎 resample の map churn」が出る。同 decision の Context §(c) は
「`total − available` の主成分は常駐アプリで、Windows では短時間に GiB 単位で
揺れる」を測定事実として記録し、20260808/1907 は「スナップショットの揺れを
許容するかの判断が要る」を明示的に未決として残している。

rc10 のオーナーレビュー (waired#1223 / waired-agent#835) で、その未決部分が
実害として出た。macOS の M5 Pro / 48 GiB (`pc-mbp14-m5`) の実測 (2026-08-19):

| 出所 | 値 |
|---|---|
| 記録されていた値 (2026-08-18 のインストール時計測) | **23 GB of 48** |
| 同じホストの live probe | **33 GB** |

10 GB の差はインストールの瞬間に常駐していたものであって、このマシンの性質では
ない。そして凍結の設計上、agent を更新するまで**永久に**その 1 分間の
スナップショットで fit 判定が行われる。`waired inference memory remeasure`
(#589) は存在するが、ユーザーがこの数字の存在を知っていることが前提になる。

つまり 0016 §2 が固定したのは「OS の取り分」ではなく「インストール時に
たまたま開いていたウィンドウの取り分」だった。

## Decision

1. **計測は毎デーモン起動で行う**。場所は変えない —— engine bootstrap の前、
   エンジンポートに応答がある場合は延期して前回レコードを保持
   (0016 §2 の常駐モデル条項はそのまま有効)。`AgentVersion` は
   再計測のキーではなくなり、記録の出自として残るだけになる。
2. **記録するのは最も高い読み**。新しい読みが記録以下なら
   レコードは 1 バイトも書き換えない —— 値も `MeasuredAt` も。
   現に効いている数字は前回の計測が出したものなので、今日の日付を
   付け直すのは、その数字を出していない計測に帰属させることになる
   (env seam が日付を返さない理由と同じ)。
3. **下げる手段は `waired inference memory remeasure` だけ**。これは今までどおり
   レコードを上書きする（上にも下にも）。自動で動くものはすべて単調に上向き。

### なぜ churn の懸念が消えるか

0016 §3 が恐れたのは「resample で判定が翻る」ことだった。最大値保持なら
`OSMemoryDeductionGB = max(2, total − available)` は**単調に小さくなる**ので、
fit 判定は「入らない → 入る」の一方向にしか動かない。**サービス中のホストから
モデルが取り上げられることは構造的に起きない**。更新の頻度も 5 分毎の resample
ではなく再起動回数で、しかも「これまでの最高値を超えたとき」だけなので、
実際の書き込みは数回で収束する。

### 何を測っていることになるか（意味の変更）

0016 は「OS **と、インストール時に常駐していたすべて**が system RAM から
取る分」と定義していた。本決定はこれを「**ユーザーが作業をしまったとき**に
このマシンが差し出せる分」に変える。モデルを動かすときユーザーはブラウザを
閉じる、というのが製品の前提なので、後者のほうが判定の目的に合っている。
定数 floor `OSMemoryAllowanceGB = 2` はそのまま残り、「OS は最低 2 GB は取る」
という下限を守る。

### 含まれないもの

- 判定の分母を `UsableVRAMMB` で下支えする案 (#835 の修正案 2) は採らない。
  proto に触れるうえ、16 GiB Mac では 12 GB 床が緩すぎ、waired#1056 決定 1
  「Mac のみ合成 VRAM を加算せずプールサイズ」の趣旨からも離れる。
- darwin の probe が active な file cache を数え落としていた件は独立の欠陥で、
  既存の不変条件への適合として別に修正した (waired-agent#835、PR #840)。

## Consequences

- `signer.HardwareSummary.RAMAvailableGB` は「インストール時に一度」ではなく
  「これまでに観測された最高の空き」になる。wire の形・capability
  (`ram-available-v1` / `-v2`) は不変で、0 の意味も変わらない。
  古い agent が送る値は今までどおり解釈できる。
- CLI の文言と `docs-site` のリファレンスから「インストール時に測り、次の
  インストールまで固定」という記述が消える。
- 既存ホストは agent 更新後の最初のクリーンな起動で自動的に追いつく。
  `pc-mbp14-m5` は 23 → 33 GB に上がる見込み。
