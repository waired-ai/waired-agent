# エンジンが取りこぼしたツール呼び出しを gateway で復元する (20260802 09:05)

## Status
Accepted

## Context

エンジン側のツール呼び出しパーサが失敗し、モデルが正しく選んだ呼び出しが
アシスタントテキストとして素通りする事象が、実測でツール呼び出し失敗の
大半を占めていた（#409, 計測は #322 の agentgrade）。ollama 0.31.1 に
27 ツールのコーディングエージェント要求を投げた結果:

- qwen2.5-coder 0.5b/3b/7b/14b — 24/24 試行で ```` ```json
  {"name":…,"arguments":{…}} ```` がテキストに残る。7b は現行の
  `BundledModelID` そのもの。
- qwen3-coder:30b-a3b — 8/24 で Qwen3-Coder の XML 方言
  (`<function=…><parameter=…>`) が漏れる。
- granite4:350m — 5/12 で `[TOOL_CALLS]Read{…}{}` が漏れる。

いずれもモデルは **正しいツールを正しい引数で選んでいる**。壊れているのは
シリアライズだけで、エージェント側はそれを散文として受け取り停止する。

エンジンを乗り換えても解決しない。vLLM は正しいパーサを持つが Windows 非対応・
macOS Metal も実質未対応で、この問題に当たっているユーザ層を覆えない
(#410 は vLLM 側の別の欠陥)。waired は Anthropic↔OpenAI 変換を自前で
持っているので、そこで直せば全エンジン・全 OS に一度に効く。

## Decision

gateway が、**エンジンが構造化 `tool_calls` を返さなかった場合に限り**、
アシスタントテキストから呼び出しを復元して通常の `tool_use` ブロックとして
返す。

対象の方言は実測された 3 つ（Qwen3-Coder XML / 素の JSON オブジェクト /
テンプレート区切り子）。引数はツールの `input_schema` に宣言された型にのみ
強制変換する — 文字列しか運べない方言で `limit` が `"5"` のまま届くと
クライアント側のスキーマ検証で落ち、復元した意味がなくなるため。

安全側の条件は 3 つ。いずれも「復元が呼び出しを捏造しない」ための条件で、
これが崩れるくらいなら復元しないほうがよい:

1. 要求がツールを提示していること。
2. エンジンの `tool_calls` が空であること。エンジンのパーサが動いた turn は
   一切詮索しない。
3. 解析した名前が **実際に提示されたツール** であること。提示外の名前は
   #322 の rc7 ハルシネーションであり、シリアライズの不具合ではない。
   パーサで直せる類のものではないし、変換すれば「見える失敗」が
   「見えない失敗」に化ける。

ストリーミングも対象とする。Claude Code は常にストリーミングなので、
非ストリーミングだけ直しても agentgrade の数値が動くだけで実ユーザの症状は
残る。ただし Anthropic の SSE には送出済みイベントの撤回手段がないため、
turn 全体をバッファするのではなく `toolTextSieve` が「呼び出しの開始に
なりうる箇所」からだけテキストを保留する。素の散文は従来どおり即時に流れ、
TTFB (#757) と逐次表示は保たれる。素のコードフェンス ``` は保留対象に
しない — コーディングエージェントは常時フェンスを出すので、稀な漏れを
拾うために全フェンスを止めるのは割に合わない。

復元が発火したことは `RequestEvent.ToolRecovery`（方言名、additive +
omitempty）と `slog.Warn` に記録する。gateway がテキストを修復するように
なった以上、エンジンやモデルのシリアライズ劣化は他に観測手段がなくなるため。
**断片も本文もログには出さない** — メッセージ本文であり、spec §8.5 / §15-10
がこれを禁じている。ツール名と方言名のみ。

## Consequences

- qwen2.5-coder 系（現行 `BundledModelID` を含む）が実用になる。#322 の
  引退候補リストは復元後の再計測で取り直す必要がある — 「正しく選べるが
  正しく書けない」モデルを、パーサ修正前の数値で捨てることになるため。
- agentgrade の既存判定は復元前に測ったもので、`internal/catalog/agentgrade.json`
  は陳腐化する。再計測は別 PR（GPU 実測は CI で再現できず、
  agentgrade.json は計測記録であってコードの正しさの証明ではない）。
- gateway がエンジンの出力を書き換える最初の箇所になる。誤検出時の代償を
  テキストの遅延のみに留めるため、保留したテキストは呼び出しとして解釈
  できなければそのまま逐語で流す。
- エンジンが HTTP 500 を返す系統（qwen3.5 が自身の XML でパーサを落とす）は
  復元できるテキストが存在しないので対象外。エンジン側のツール解析を
  バイパスするか ollama/ollama#16383 を待つかの判断は別途。
