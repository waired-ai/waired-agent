# 新しいモデルは、実クライアントの送る形をエンジン上で受け付けることを示してから出荷する (20260828 04:00)

## Status
Accepted

## Context

qwen3.8-27b は `internal/catalog/agentgrade.json` に**合格 verdict を持ったまま出荷され**、
24GB のホストで Claude Code の全ターンが 500 になった (agent#1035)。必須ゲートは緑だった。

見逃した理由は構造的なもので、運用の失敗ではない。

- 採点フィクスチャは `[user, assistant, user]` を固定で組み立て、`Case` に
  非先頭の指示ターンを表現するフィールドが無い。
- `computeRevision` はツール・system・コンテキスト・(ケース名, ツール要否, プロンプト)
  をハッシュする。**ロール列は入力に入っていない。**
- したがって「クライアントが送る形」は一度も宣言された対象ではなかった。

引き金は実在する。Claude Code は `mid-conversation-system-2026-04-07` の下で、
トップレベル `system` を 3 ブロック配列で送り、**さらに** `messages[]` の末尾に
`role:"system"` を置く。ollama 0.32.13 の qwen3.8 レンダラはこの形を拒否するが、
同じエンジン・同じ日に qwen3.6-35b-a3b と qwen3.5-9b は全形状に 200 を返した
(`docs/knowledges/20260827/1330-qwen38-on-a-24gb-card.md` §1)。
**受け入れ可否はモデルごとに違う。**

## Decision

1. **形状マトリクスを実測し、記録する。** 対象は「エンジンのチャットテンプレートが
   その形をレンダリングするか」だけで、応答の質は見ない。判定は HTTP ステータス。
2. **エンジン直に撃つ。** ゲートウェイの両面が指示ターンを畳むようになった今
   (#1035 / #1055)、ゲートウェイ経由の行は自分の正規化を測ることになり、
   全モデルで同じ答えになる。エンジン直なら (重み, テンプレート, エンジン版) の事実になる。
3. **エンジン版は所見の一部として必ず記録する。** 0.32.13 は拒否し、0.32.14 は許容し、
   0.32.15 は先頭へマージする (ollama#17754 / #17757 / #17855)。版の無い記録は何も言っていない。
   値はアダプタから読み、オペレータのフラグにしない。
4. **実測は新規モデル追加時のみ。** 既存カタログは再測定しない。エンジン pin の移動でも
   再測定を強制せず、ずれた件数を表示するだけにする。pin 移動が既存モデルの形状を
   壊した記録は無く、L4 に載らないモデルが 5 件ある以上「全カタログを回す」は元から成立しない。
5. **マージを止めるのは在庫ゲート**（必須の `unit tests` の中の Go テスト）であって、
   実測ジョブではない。パスゲートのジョブは必須チェックにできない。
6. **免除は宣言する。** 測れないモデルは既存の `unmeasurable` を再利用し、
   この検査より前から在る変種は `baseline` に置く。`baseline` は変種単位・`VariantSHA` 値で、
   増やす操作はテストのリテラル編集として diff に出る。
7. **相乗りする。** マトリクスは既存の採点 run と同じレポートに入れる。新しい GPU レーンも
   新しい成果物ファイルも作らない。

## Consequences

- **新規モデルの PR は、実測を先に回さないとマージできない。** 手順は既存の採点と同じで、
  追加の GPU 起動は無い（新規モデルはどのみち採点 verdict が要る）。
- **証明できるのは「記録が在ること」であって「GPU が作ったこと」ではない。** 公開リポで
  後者は証明できない。代わりに、捏造した記録が必ず間違える点をすべて import で拒否する
  — 対照が立たない run、測れなかった行、部分的な走行、未 stamp / `-dirty` のハーネス、
  エンジン版の欠落、出荷中の表が問うていないダイジェスト。
- **陰性対照はエンジン非依存にした。** 大半のモデルは全形状を受け付けるので、
  「全部 accepted」は正常な結果であり、検証していないハーネスと区別が付かなくなる。
  レンダラの挙動に依存した対照は pin が動くと対照自体が壊れる（0.32.13 → 0.32.15 で実際に
  そうなる）ので、存在しないモデル名を撃って拒否が立つことを見る。
- 形状表のダイジェストは**行ごと**。表全体で 1 つにすると、1 行足すたびに全記録が無効になり、
  4 の「既存は再測定しない」と正面から矛盾する。
- 記録にエンジンの生のエラー文は保存しない。上流の不安定な文言であり、リクエスト内容を
  含み得る。分類は製品側のマッチャ (`IsEngineRequestShapeRejection` /
  `IsEngineParseFailure`) を共有する。
