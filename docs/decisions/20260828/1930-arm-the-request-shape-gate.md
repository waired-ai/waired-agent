# 形状ゲートは判定まで読む。証拠が在ることは、そのモデルが使えることではない (20260828 19:30)

## Status
Accepted

## Context

20260828/0400 で形状マトリクスの機構を決め、agent#1099 で実装した。ゲートは
**未武装**のまま残した — baseline が空で、CI からも呼んでいなかった。

武装の準備で読み直したところ、**そのまま武装しても目的を達成しない**ことが分かった。

`RequestShapeGaps` は「記録が在るか」しか見ていない。`stale` は `VariantSHA`・
`EngineVersion`・各行の digest 一致を検査するが、**`ShapeOutcome.Outcome` を
一度も読まない**。`agentgrade --require-pass` に相当する腕が無かった。

したがって `qwen3.8-27b/mtp-q4-gguf`（**現在も offered**）の ollama 0.32.13
マトリクス——6 行中 3 行が `rejected`——を import すると、`shapes --check` は
**gap ゼロ = 緑**を返す。この表が存在する理由そのもの（#1035: 合格 verdict を
持ったまま出荷され、24GB ホストで Claude Code の全ターンが 500 になった）が、
JSON に清書されたうえで通過する。

同時に、記録機構そのものにも穴が 4 つあった。いずれも**記録がゼロの今なら
無効化コストがゼロ**で直せる。

## Decision

1. **ゲートは判定を読む。** `shapes --check --require-accepted` を必須の `lint`
   ジョブに置く。offered 変種の記録に `rejected` の行が 1 つでもあれば落ちる。
   拒否行はフラグの有無に関わらず**常に印字**する — 拒否を見た run が、
   見なかった run と同じ見た目になってはいけない。

2. **免除マップは作らない。** コーディングエージェントが送る形をレンダリング
   できないモデルは、このプロジェクトが offer できないモデルである。逃げ道は
   既存の語彙で足りる — エンジン pin を動かすか、その変種を offer しない。
   実例が出る前に third answer を発明しない。

3. **行の digest は、その行が実際に送るボディに対して取る。** name と roles
   だけでは、`OpenAIBody` が決めている `tools` 配列や schema を変えても 1 bit も
   動かない。`OpenAIBody` 自身のコメントが「ツール定義が無いと厳格なエンジンは
   ロール列でなくツール呼び出しを理由に拒否し、その行は**間違った所見**を
   記録する」と書いている当のものが、staleness の鍵から漏れていた。
   `agentgrade.FixtureRevision` は同じ理由で描画済みツール一式を hash している。

4. **`--import` は完全カタログで解決し、gap 判定は offered のまま。**
   これは agentgrade が既に出荷済みバグとして `internal_resolve_test.go` に
   記録している型。withheld なモデルの測定を offered 集合で解決すると、
   **withhold を正当化したその測定自体が拒否される**。`granite4:350m` は
   `make e2e-agentgrade` の既定・routing sentinel が pin するタグ・GPU レーンの
   コピペ行が名指すタグでありながら、記録を持てなかった。

5. **既存カタログは宣言による免除**（20260828/0400 項目 6 のとおり）。
   `--seed-baseline` は `unmeasurable` を尊重する — 既に「どのランナーでも
   ホストできない」と宣言されたモデルに二重の恒久免除を与えない。seed は
   一回限りなので、汚れた baseline の後始末は手編集になる。
   ratchet は baseline と**双方向**で一致させ、測定済みの死んだ免除が
   リテラルに溜まらないようにする。

6. **モデルの source は実在を問い合わせる**（#824）。文字列検査だけでは
   `Qwen/Qwen3.6-27B-AWQ` が数か月出荷された。HF は不在/非公開に **401** を
   返す（404 ではない）ので、既存の `get()` の 404 マッピングでは
   「存在しない」が「一般のステータスエラー」になる。ネットワークが要るため
   必須チェックにはせず、`proto/catalog/bundled/**` の paths ゲートで回す。
   **答えられなかったこと（429/5xx）を「不在」と報告しない** — それは
   通信不調の午後に生きているモデルをカタログから消す。

## Consequences

- **新規モデルの PR は、実測を先に回さないとマージできない**（従来どおり）。
  加えて、**拒否行を含む実測はマージできない**。これが今回の変更点。
- **現在のエンジン pin 0.32.15 ではこの腕は空振りする** — エンジン自身が
  指示ターンをマージするため、offered なモデルは全行を受け付ける。
  したがって落ちる腕は**合成データでテストする**。絞り込んだガードは
  全緑でも「空」でありうる。
- **実測はマージ済みコミットである必要は無い。** import が拒否するのは
  未 stamp と `-dirty` であって、マージ済みかどうかは見ていない。
  コミットして push したブランチ上で測れば、同じ PR の中で取り込める。
  0400 の決定が「PR を 2 本に割る」と述べた前提はこの点で誤っていた。
- **公開リポに追跡バイナリを置かせない**ガードを併せて入れた。agent#1099 が
  15MB の ELF をルートにコミットしており、21 のチェックすべてが緑だった。
  `.gitignore` の手書き列挙が `cmd/` 4 つのうち 3 つしか挙げていなかったのが
  原因なので、ガードは期待値を `cmd/*/` から**導出**する。
