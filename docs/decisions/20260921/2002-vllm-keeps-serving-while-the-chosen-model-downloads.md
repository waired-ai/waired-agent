# vLLM でも、選んだモデルのダウンロード中は前のモデルで応答し続ける (20260921 20:02)

## Status

Accepted。オーナー決定(2026-09-21、#1361-L107 のセッションで直接)。waired-agent#1515。

## Context

vLLM ホストでは、選んだモデルの重みが手元に無いと、`bootstrapVLLM` がエンジンを起動する前に、その起動処理の中でダウンロードしていた。

- ダウンロードの間は何も応答しない。前に動いていたモデルも起動されない。
- このダウンロードは進行中の一覧に載らないので、取り消せない。状態は `starting` のまま、理由も出ない。
- 応答中の vLLM ホストでモデルを切り替えると、サービス全体を再起動していた(`errSwapNeedsRestart`)。選んだ瞬間から何も応答しなくなる。

ollama ホストはそうなっていない。`ollama serve` はモデルに依存せず起動するので、前のモデルが応答している間に次のモデルを落とし、終わってから切り替える。

実例: Linux の 24 GB カードのホストで、NAVI から qwen3.6-35b-a3b(vLLM build は 23.42 GB)が選ばれた。前のモデル gpt-oss-20b は退役済みだった。

## Decision

1. **選んだモデルの重みが無いときは、ダウンロードを通常の pull の経路で始める**(取り消せ、`models ls` に出る)。その間は次の順で応答を続ける。
   - エンジンが動いていれば、そのまま応答を続ける。
   - 止まっていて、前に動いていたモデルが条件を満たせば、それで起動する。
   - どちらでもなければ待つ。状態は `loading` になる。
2. **前のモデルの条件**(`vllmPreviousCandidate`)。state.json の Active で、vLLM で動いていたこと。この版のカタログに同じ id で載っていて、このエンジンの版で読めること。重みが Ready で手元にあること。
   - **退役済みのモデルは起動しない**(オーナー決定)。マニフェストが消えているので起動に要る情報が無く、どの Waired のリクエストも届かない。GPU を握るだけになる。
3. **重みが届いたら切り替える。**
   - 進行中のターンを捌いてから(drain)エンジンを止め、選んだモデルで起動し直す。数分の間ここでは何も応答しない。その間のターンはメッシュが受ける。
   - 切り替えの引き金は「選んだモデルの重みが着いたこと」とする。前の選択のダウンロードが遅れて着いても、切り替えない。
4. **Active はエンジンが Ready になってから書く。** エンジンが動いている間は、pull の完了で書き換えない。エンジンが動いていない新規ホストは今までどおり。
5. **vLLM 同士の切り替えではサービス全体を再起動しない。** tray、CLI、管理 API、NAVI(desired)のどこから来ても、上の流れに乗る。再起動が残るのはエンジンの種類が変わるときだけ。
6. **取り消されたダウンロードは、次の引き金で勝手に再開しない。** 同じ build は 1 プロセスで 1 回だけ始める。新しい選択、明示的な pull、デーモンの再起動があれば、もう一度始める。
7. **起動の要求が重なったら 1 回やり直す。** 前のモデルの起動中に重みが着いたときの切り替えを取りこぼさないため。
8. **大きすぎるモデルでも断らない**(`docs/decisions/20260920/2345-an-explicit-choice-below-the-coding-window-is-warned-not-refused.md` のとおり)。
9. **起動に失敗したら止めて理由を出す**(オーナー決定)。
   - 選んだモデルの起動がメモリ不足で失敗したら、その build とそのときの形(窓、KV の型、同時数)を、ollama と同じ `FailedLoads` に記録する。失敗の判定は、エンジンのログの CUDA OOM・KV プールの不足、または計算上「重みだけで予算を超える」こと。
   - 記録したらエンジンを止める(`parkCauseOutOfMemory`)。`waired status` には承認済みの一文(#1464)が出る。同じ機械・同じ形では、再起動しても起動を試みない。
   - 解除は、モデルを選び直すこと(そのモデルの全 build の記録を消す)と、コンピュータが変わること(記録の条件が合わなくなる)。タイマーでの再試行はしない。前のモデルに自動で戻すこともしない。
   - 重みが予算を超えるときの起動失敗の案内を、「KV の設定を下げよ」から「重みが vLLM に使える GPU メモリより大きい。小さいモデルを選ぶ」に改めた。

## Consequences

- 前のモデルが退役済みのホスト(Context の実例)は、ダウンロード中に応答しないのは変わらない。変わるのは、状態が `loading` になること、ダウンロードを取り消せること、開始要求が捨てられないこと。
- 切り替えの間(新しいモデルの起動、数分)は、このコンピュータでは応答しない。
- `waired models use` と tray の文言(「The current model keeps answering until then.」)は、何も応答していない場合と vLLM の再起動を言い分けていない。文言はオーナー承認のうえ別の PR で直す。
