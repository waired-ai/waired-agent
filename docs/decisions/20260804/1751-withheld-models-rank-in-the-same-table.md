# 保留中のモデルも同じ順位表に並べる (20260804 17:51)

## Status
Accepted

## Context

`catalog-tool agentgrade` のレポートには、あるバリアントの失敗率が現れうる場所が
2 つあった。

* **料率表**は `BundledManifests()`（提供カタログ）を回すので、`internal_only`
  のエントリは構造上そこに存在しない。
* **`WITHHELD, PENDING RETIREMENT` 節**（#475）は、保留中のうち
  `RetireFailureRate`（50%）を**超えたものだけ**を挙げる。

したがって**線より下の保留中エントリは、どこにも印字されない**。

これが実害になった。granite4-350m ——ルーティング・センチネルのフィクスチャで、
3 OS 分すべての PR で実際に pull されるモデル——は、#483 が引数不正クラスを失敗に
昇格させたときに 17% から **38%** に上がった。これはストア内のどのエントリよりも
退役ラインに近づいた値で、しかも**不可視**だった。提供されていないので料率表に無く、
50% 未満なので保留節にも無い。

さらに悪いことに、印字される値の代わりに置かれていた散文が逆向きに間違っていた。
granite4-350m の `internal_only` は「greeting と search は 3 試行でクリーン」と
書いており、これは書かれた時点の 3 draw については真だったが、24 試行では
search-then-edit が 13/24 で落ちる。この文は飾りではなく**論拠**だった——
「実際にツール呼び出しを駆動する将来の CI レグはこのモデルで組める」の根拠が
これだった。

## Decision

**1. 料率表を、測定済みの全バリアント（提供・保留の別なく）1 本の順位表にする。**

#484 が併記していた 2 案のうち、「保留節のフィルタを『線より上』から『記録のある
保留全件』へ広げる」ではなく、こちらを採る。**穴が構造的だった**からである。
メンバシップ規則の異なる 2 本のリストは、今日一致させられても、どちらかの次の変更で
また離れる。測定済み全件を回す 1 本のリストは、同じ穴を開け直せない。

`withheld` は**列であって除外ではない**。38% を見た読み手は、それが誰にも提供されて
いないことを同じ一瞥で知る必要がある。

**2. 保留節は、線より上か下かに関わらず全件を挙げる。**

線は「削除すべきか」に答える。保留節は「これを止めていることに、まだ誰か責任を
持っているか」に答える。この 2 つはメンバシップが違う。granite4-350m は 38% で
**設計上恒久的**、qwen2.5-coder-0.5b は 90% で**暫定的**。後者だけを印字することは、
読み手に「保留かつ掲載 = 削除待ち」と教えることになるが、`internal_only`
フィールドはそんな主張をしていない。

**検証を持たない保留エントリも挙げる。** 料率表には構造上行が無いので、ここが唯一
現れる場所になる。「止めているものを誰も測っていない」は、同じ欠陥の一段手前である。

**3. ゲートは広げない。** `--require-pass` は offered-only のまま。保留エントリを
ゲートすれば、どの PR にも消せない赤になる（削除は #200 のマシナリ待ち）。恒久的な
赤は無視されるようになり、それはこの節が防ごうとしている結末そのものである。

**4. `internal_only` の理由文を 2 つの性質で pin する。**

* 現在の worst-case 下限を**引用していること**。スイープが率を動かしたとき、散文を
  置き去りにできない。
* **どちらの種類の保留か**を述べていること（"permanent" か "pending retirement"）。
  レポートが両者を並べて印字する以上、それを区別するのは理由文だけである。

## Consequences

* granite4-350m の理由文を実測に合わせて書き直した。撤回した主張は
  「ツール呼び出しを駆動する将来の CI レグをこれで組める」——2 段要求の半分以上を
  落とすので、組めない。センチネルがルーティングだけを主張し続ける理由が明文化
  された。フィクスチャに選ばれた根拠（708 MB、1 語のプロンプトに 2 トークンで
  停止）は元から grade と無関係なので、そのまま残る。
* `Failures` の doc が granite4-350m を「次点 17%」と呼び続けていた。
  `TestRatesCitedByRetireFailureRate` はストアと**テスト表**を突き合わせるので、
  同じ数値の 2 度目の引用は射程外だった。pin のコメントにその限界を書いた。
* 保留は 2 件とも料率表に載る。0.5b は 90% で先頭、granite は 38% で 2 番目——
  提供カタログの最悪値（qwen2.5-coder-3b の 23%）より上に、初めて可視の形で並ぶ。
